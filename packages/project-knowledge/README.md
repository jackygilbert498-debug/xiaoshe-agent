# 小蛇项目知识

一个可关闭的源码知识插件。学习的是“按项目建索引、按需取知识、随源码变化失效”的机制，代码独立实现；没有复制 AOCI 的实现、模板或数据格式，也不依赖 AOCI 服务。

## 它做什么

- 模型先读取真实源码，再整理职责、接口、关系、约束；保存主文件及显式依赖的 SHA-256、当前工作目录、Git 分支/提交、条目版本和核对时间。
- 下次在同一项目工作时，只把相关且来源仍一致的少量知识加入上下文。可以据此定位代码，仍应核对实际源码。
- 源码、列明的依赖、分支或提交变化后，旧摘要不再注入；查询只返回过期项的位置与版本，供重新读取和更新。
- 本轮新建或更新的知识，到下一条用户消息才进入自动上下文；同轮可以主动查询最新版。每次仍重新核对源码，不缓存过期正文，长任务也不会因为工具记录增多而重置这一边界。
- 用户偏好仍是 memory；会话事实仍是 Session Log；工具成功经验仍是 agent-experience。本插件不替代它们。

## 使用和关闭

Product Bundle 默认挂载。已有项目不会被后台全盘扫描。可向小蛇说：“阅读这个项目的核心代码，把稳定的结构和依赖整理成项目知识，方便下次接手。”普通任务中模型也可按需要记录，不强制每个任务写索引。

设置中的插件配置命名空间为 `xiaoshe-project-knowledge`，`enabled` 开关即时生效。关闭后不提供知识上下文，知识工具会说明已关闭；普通读文件、搜索、执行工具不受影响。也可直接卸载此插件行。

数据由 DSH 的 Settings 服务存放在当前用户 Profile 的 `xiaoshe-project-knowledge` 命名空间，不写入项目源码目录。不要把个人 Settings 随开源代码发布。条目不会凭同名项目自动跨目录继承。

## 工具契约

1. `xiaoshe_knowledge_inspect({paths})`：第一个路径是主文件，其余是明确依赖；返回正文、来源哈希、15 分钟有效的本会话读取凭证、已有版本及 `saveArgs`。`changes` 明确比较更新前的持久版本，避免把刚更新的知识误当成原本就没变。
2. `xiaoshe_knowledge_save({...saveArgs, document})`：模型根据正文填写 `title/purpose/interfaces/relations/constraints/overview`。不用填写条目 ID。保存前再次核对来源；版本冲突时重读，不能覆盖新版本。成功返回的 `provenance` 记录实际更新前后版本和来源变化，避免混淆新旧；这些回执元数据不存进知识正文。
3. `xiaoshe_knowledge_query({query})`：主题/相对文件路径检索，返回有效条目与过期定位信息。检索是确定性词项匹配（含中文），不是向量检索或完整调用图。
4. `xiaoshe_knowledge_forget({id, expectedVersion})`：仅删除当前项目的一条知识投影，不删除源码、用户记忆或会话。

## 容量与真实边界

- 每次 inspect 最多 8 个普通 UTF-8 文件，合计 256 KiB；不跟随文件/目录链接，不读取常见密钥、认证配置、二进制或超大文件。
- 每个 Profile 最多 500 条；每次查询最多核对 12 个候选、返回/注入最多 8 条完整知识。上下文不超过 8,000 个 UTF-16 字符（不是精确 token 数），有遗漏/过期计数。
- 自动上下文准备有 1.5 秒时间预算。关闭、损坏、取消或超时时退回普通源码工作，不关闭其他工具，不假报成功。
- 哈希一致只说明列出的源码未变，不证明模型摘要正确、所有依赖已列全、任务已经验收；未声明的外部依赖仍需人工/模型按任务核实。它不提高基础模型本身的推理上限。
- 工作目录和 Git 身份采用保守绑定；换目录不自动迁移，换分支/提交要重新核对和更新。Git 不可用时不冒充健康的代码索引。
- 路径检查属于索引的数据边界，不代替 OS 沙箱。防止同用户恶意进程竞态仍依赖宿主安全边界。

## 验证

`npm test --prefix packages/project-knowledge` 运行服务、真实文件/分支、Cordis Prompt 与 FileSettings 集成测试。

`node packages/project-knowledge/scripts/live-acceptance.mjs --live` 为明确付费的隔离真实模型检查：使用现有 DeepSeek 凭据、合成文件及临时 Settings，最多 32 个请求，不访问生产会话。检查建立知识、重启接手、依赖失效、更新和关闭后恢复普通读取；报告明确区别于完整桌面/Harness 的端到端验收，包含建立知识的成本，不把单次 A/B 当统计性能结论。
