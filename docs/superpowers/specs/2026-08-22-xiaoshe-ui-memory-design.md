# 小蛇新版界面与原生记忆设计

日期：2026-08-22

## 1. 目标

在不改变 DSH 唯一 Agent Runtime 地位的前提下，完成新版小蛇界面的品牌、字体、首页和右侧工作栏重构，并为新版补齐可真实使用、可追溯的原生记忆编辑能力。

本轮不是把 `127.0.0.1:7788` 的旧界面移植到 `127.0.0.1:3080`。旧版只提供两个参考维度：一是信息是否足够细，二是操作是否有明确反馈。新版的布局、信息层级和交互必须服从 DSH 当前真实数据与产品结构。

## 2. 不可变约束

1. 唯一合法图形 Logo 是 `runtime/xiaoshe-legacy/ui/assets/snake.svg`。
2. 浏览器、侧栏和首页只能通过 `/xiaoshe/brand/favicon.svg` 读取该母本；不得复制 SVG、描摹路径、生成替代图形或用 CSS/SVG 滤镜制造第二种轮廓 Logo。
3. 允许对“小蛇”两个文字场景做排版设计；文字不是第二个图形 Logo。
4. DSH 继续拥有模型、会话、工具、审批、任务流和持久设置；旧 Python 运行时只保留受限桌面 Provider 职责。
5. 右侧信息必须来自 DSH 页面状态或 XS 正式接口。缺失数据要显示为未知、未配置或空状态，不伪造精确数字。
6. 现有三个 Git 工作树中的用户改动全部保留，不 reset、不 clean、不覆盖。

## 3. 视觉方向

采用“当代工作室”方向：纸面般的明亮底色、墨色正文、低饱和玉色状态、少量香槟金提示和细线结构。视觉重点来自字体角色、留白、秩序和信息密度，不依赖大面积渐变、玻璃卡片或装饰性光效。

### 3.1 字体角色

- 界面正文：`Inter`、`Noto Sans SC`、`PingFang SC`、`Microsoft YaHei` 与系统无衬线回退，保证阅读与跨平台稳定。
- 数据与状态：`IBM Plex Mono`、`SFMono-Regular`、`Consolas`、`Menlo` 与系统等宽回退，用于版本、计数、时间和状态值。
- 侧栏“小蛇”：采用紧凑、直立的现代无衬线品牌字，与小号等宽英文 `HARNESS · ATELIER` 组成可靠的产品签名。
- 首页“小蛇”：采用系统可用的文楷／楷体优先栈，分别渲染两个字并进行光学字距、基线和尺度校正。使用实体墨色和一处克制的玉色标记，不再使用文字渐变剪裁。

侧栏与首页故意使用不同字体角色：前者承担识别与导航，后者承担主视觉和性格。两者不再只是同一套宋体的大小变化。

### 3.2 Logo 使用

侧栏保留原始 Logo，与文字品牌并列。首页可直接显示同一母本的正常图片实例，但不得使用形态学膨胀、腐蚀、路径描边或轮廓滤镜。尺寸和布局可以响应式变化，图形内容保持原样。

### 3.3 首页

首页保留 DSH 原生工作区、模式选择与输入器，不替换其行为。品牌区调整为：

1. 小号工作状态行；
2. 具有字形节奏的“小蛇”主标题；
3. 一句短产品说明；
4. 三个静态能力说明；
5. 原生工作区与输入器。

顶部“新会话”信息区与主视觉使用同一套字体层级，降低当前渐变、阴影和漂浮元素造成的模板感。

## 4. 右侧工作栏

右侧工作栏采用“上下文仪表台”，而不是旧版面板复刻，也不是通用后台卡片堆叠。

### 4.1 信息结构

- `状态`：当前阶段、任务计划计数、工具执行状态、审批/排队/上下文活动、当前工作区与模型。
- `记忆`：长期与项目记忆的真实列表、创建、修改、遗忘、恢复及版本状态；同时保留会话记录说明，明确它与长期记忆的区别。
- `系统`：Bridge、平台、协议、版本、ModLens、桌面动作、屏幕权限和安全边界。

### 4.2 呈现原则

- 第一屏先回答“现在在做什么”和“哪里需要注意”，再展示细节。
- 使用细分隔线、紧凑键值行、状态刻度和少量分组底色；避免每一组都做成独立大圆角卡片。
- 运行中、失败、等待审批等需要视觉优先级；零值和空状态降低对比度。
- 宽屏保持固定右栏，可折叠为窄状态脊；中窄屏转为可关闭抽屉。
- 键盘焦点、ARIA 标签、减少动画偏好和明暗主题保持可用。

## 5. 原生记忆架构

### 5.1 所有权

记忆状态存放在 DSH 的独立设置命名空间 `xiaoshe-memory` 中，由当前 Profile 的设置持久层管理。XS Bundle 提供受限的记忆服务、HTTP 接口、模型工具和 UI；不调用旧版 `/api/memory/*`，也不引入第二套 Agent 或会话运行时。

### 5.2 数据模型

每条记忆包含：

- 稳定 ID；
- `global` 或 `project` 作用域；
- 项目作用域键（仅项目记忆）；
- 正文；
- `active`、`forgotten` 或 `superseded` 状态；
- 创建、更新时间；
- 修订号；
- 被替代条目的 ID（编辑时）；
- 最近一次状态变更的审计信息。

修改采用“新版本替代旧版本”语义：旧文本保留为 `superseded`，新条目成为活动版本。遗忘是可恢复状态，不执行不可逆删除。

### 5.3 并发与限制

- 每次写入携带期望修订号；陈旧页面收到冲突并刷新，不静默覆盖。
- 单条正文、项目键、总条数和审计条数均有明确上限。
- 写入串行化，设置更新失败时不发布内存中的新状态。
- HTTP 仅接受同源回环请求，使用严格 JSON 结构、大小限制与 `no-store`。

### 5.4 模型工具

提供三个正式工具：

- 列出／检索记忆；
- 新增或以新版本修改记忆；
- 遗忘或恢复记忆。

写入工具描述明确要求只有用户显式要求记住、修改、忘记或恢复时才能调用，不把模型推断自动写成长久事实。工具输出与右侧工作栏读取同一服务。

## 6. 交互细节

- 记忆页默认显示与当前工作区有关的项目记忆，并可切换长期记忆与已遗忘内容。
- 新增和编辑使用内联表单；保存期间禁用重复提交；错误紧邻操作显示。
- 编辑成功后旧版本不再出现在活动列表，但历史计数和修订号更新。
- 遗忘与恢复按钮使用明确文字，不使用含义不清的图标。
- 当没有记忆时显示真实空状态和新增入口，不显示模拟数据。
- 右栏刷新时保留当前标签和折叠偏好。
