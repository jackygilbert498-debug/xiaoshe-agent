# 小蛇版 DSH 实施方案

## 目标状态

对用户只有一个“小蛇”：统一入口、统一会话、统一模型配置、统一审批和统一任务轨迹。内部由 DSH 提供 Harness 内核，ModLens 提供图像语义理解，小蛇桌面插件提供本机 GUI 观察与操作。旧 Python 小蛇在迁移期只是隐藏的能力进程，不形成第二套用户会话。

## 架构决定

1. 不修改 DSH 主仓库；以外部 Bundle 安装到 Profile，固定并验证 DSH 版本。
2. 不整仓搬运旧小蛇；先通过窄 JSON-RPC stdio 协议复用已验证的桌面模块。
3. 观察与动作分权：观察和唯一窗口枚举直接执行，点击、输入、按键和窗口聚焦进入 DSH 一次性审批。
4. 所有坐标动作绑定视口版本。执行前重新截屏，哈希不一致即拒绝旧坐标并返回新视口。
5. 每次动作完成后自动重新截屏和读取元素表，以截图哈希和 AX/UIA 增删提供真实变化证据。
6. 图片理解只调用既有 ModLens 工具；本 Bundle 返回受控本地图片路径和结构化观察结果。

## 分阶段交付

### G0 基线与可回退安装

冻结 DSH、ModLens、旧小蛇版本和工作树状态；建立独立仓库、Bundle manifest、Profile patch、安装与卸载步骤。

### G1 观察闭环

实现桥接生命周期、严格 JSON-RPC、私有临时目录、环境变量清洗、请求超时和中止；交付 `screen_observe`、`screen_zoom`、`screen_verify`，并验证返回图片可被 ModLens 读取。

### G2 安全动作闭环

交付 `screen_click`、`screen_type`、`screen_press`；审批策略必须先执行下游策略，再把允许升级为询问；执行层再次检查视口版本；动作后自动返回新视口和变化证据。

### G3 统一产品体验

增加“小蛇”品牌 Profile、中文设置卡、桌面能力开关、权限状态、截图预览和动作前后证据卡；启动器只启动该 Profile，不暴露 Python 桥进程。

### G4 去桥接与跨平台收口

按实测稳定度逐项把 Python Provider 替换为原生实现，保持 JSON-RPC 能力接口不变；补齐多显示器、OCR 标记和 DSH 附件持久化。Windows UIA 当前 Provider 真机证据已完成，但仍需迁移到原生实现；只有替代实现通过同一验收集后才移除旧模块依赖。

## 主要风险与控制

- DSH 处于开发者预览：Bundle 固定兼容版本，升级前运行真实组合测试。
- 坐标陈旧：任何动作前执行屏幕哈希复核；不提供绕过参数。
- 权限绕过：动作工具在执行体内仍检查 `actionsEnabled`，不能仅靠 schema 隐藏。
- 子进程泄密：桥接环境采用允许列表，不传递名称含 KEY、TOKEN、SECRET、PASSWORD 的变量。
- 截图隐私：目录 0700、文件 0600，进程退出清理；不默认持久化。
- 子进程悬挂：超时或中止时终止整棵桥接进程，并等待退出后才返回。

## 完成定义

工程完成不是“代码已写”。每一阶段必须同时具备实现、单元测试、真实组合启动证据、失败路径证据、文档和可执行回退。Windows 真机、系统授权和真实 UI 交互如果当前设备无法覆盖，必须明确列为外部验收，不得写成已通过。
