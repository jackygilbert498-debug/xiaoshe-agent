# 小蛇稳定化与可交付内测版

本阶段在现有产品上修复可靠性与交付短板，不扩展通用能力范围，也不以新增测试数量替代真实任务结果。

后续实产品验收入口与边界见 [真实启动与重启恢复](real-product-lifecycle.md)。该入口只有实际成功报告才计为完整任务通过。

## 本阶段工作

1. 受控写入：账本写盘失败不发布虚假内存状态；文件修改与完成回执之间的中断可对账，确认、撤销和重试不得覆盖用户的新内容。
2. 版本一致性：区分当前源码／构建、后台已加载身份和前端产物；旧实例、未知身份和暂时不可用不得展示为“已是最新版”。
3. 固定任务集：30 项任务使用可检查的结果条件，分别登记未执行、组件夹具验证和真实模型验证，保留失败及历史证据。
4. 高频场景：先稳定“本地审核资料整理 → 用户确认 → 网页提交 → 保存与回读核验”。夹具只能证明组件串联，不证明模型会可靠地自主执行。
5. 候选验收：依赖顺序构建、类型检查、单元／集成／Electron 旅程、源码身份绑定；真实模型、真实账号、签名和跨平台实机另列边界。
6. 工具可发现性：当前展示面不等于会话全部工具。能力规划器可以找回仅被任务精简隐藏的工具；保留其他作用域限制、任务硬约束和已注销状态。运行信息区分展示数与可发现注册数，不把工具隐藏解释为必须换会话。

## 安全边界

- 保留现有源码改动、会话、草稿、Profile 和登录状态；测试创建自己的临时目录与数据。
- 不提交、不推送、不正式发布；不因验收而重启或替换使用者的日常服务。
- 无模型测试不调用模型。真实模型批测须先批准任务范围和用量预算；现有脚本的超时不等于硬金额封顶。
- 真实网站登录由使用者完成；测试文档／页面及读写权限需明确，不能复制日常浏览器凭据。
- 本机开发验收不替代干净设备安装、Windows 实机、签名或公证。

## 通过标准

每个报告说明源码身份、环境、执行方式、检查结果、时间和剩余边界。源码变化后的旧报告只能作为历史参考。未执行不记成功；组件测试不记真实模型成功；没有准确用量时不填估算成本。全套确定性检查成功仍是内部候选状态，不自动批准发行或给产品提升到固定分数。

完成后按相同产品评分口径重新评估，主要观察异常恢复、版本一致性、可重复任务证据和交付可复现性，不按开发投入或测试数量加分。

## 可重跑入口

使用项目 engines 要求的 Node 版本。本机已验证的解释器为 `/opt/homebrew/opt/node@24/bin/node`，以下命令在项目根目录运行：

```sh
npm run verify:internal
npm run test:workflow
npm run test:browser:native
```

第一项按依赖顺序构建，并运行固定的确定性检查；不加 `--live` 就不调用模型。第二项先编译受控写入包，再执行合成本地资料到隔离网页的组件流程。第三项可单独复跑原生浏览器操作与退出后的存储恢复，它在完整门禁中排在其他 Electron 旅程之后，避免测试间抢焦点。希望保留证据时，设置 `XIAOSHE_MATERIAL_WORKFLOW_EVIDENCE_DIR` 或 `XIAOSHE_NATIVE_BROWSER_EVIDENCE_DIR` 为明确的绝对输出目录。报告只有在测试自己的浏览器与临时数据清理后才完整。

`npm run verify:tasks -- --source-sha <当前源码摘要> --since <本次开始ISO时间> --report <明确报告路径> --output output/stabilization/task-evidence.json --summary output/stabilization/task-evidence.md` 可生成固定任务索引；详见 [任务契约](task-catalog.md)。不提供真实模型报告，就不能将组件成功计作模型任务通过。

日常实例诊断（只读，不自动更新）：

```sh
node scripts/runtime-version-status.mjs \
  --root /Users/zfy/Desktop/XS \
  --dsh-root /Users/zfy/Desktop/XS/runtime/DSH \
  --profile-root /Users/zfy/.dsh/profiles/web \
  --base-url http://127.0.0.1:3080
```

未提供窗口真实加载的前端摘要时，整体不会显示 `current`；后台摘要不一致则显示 `stale`。新界面在“设置 → 高级与关于”查询自身前端摘要与后台版本。此功能不会保存草稿或重启；切换日常实例前，使用者须先保存未发送内容并明确确认。

## 恢复与限制

受控写入的 `applying/reverting` 是已确认但尚未完成对账的意图。重启不会自动改文件；在工作台点击“恢复对账”，检查工作区仍相同、文件摘要符合预期后才继续。外部编辑或工作区变化会阻止恢复，不强制覆盖。原文件与账本不是跨文件原子事务；本阶段只支持单服务实例，不承诺多进程互斥、断电持久性或对任意外部编辑器的完全隔离。

本轮实施前已保存包含现有未提交与未跟踪源码的基线归档，位置见 `output/stabilization/baseline-*/baseline.json`。它不含会话和凭据，也不是覆盖当前工作区的授权；恢复时先对比，再逐文件取回。
