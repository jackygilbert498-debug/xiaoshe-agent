# 同会话文件任务：真实模型验收

目标是验证“首轮观察会话能力后，同一个会话接着处理文件，文件工具始终可见可用”的使用路径。不创建替代会话，不向模型提示源数据的答案，不把模型的完成声明当作结果。2026-09-09 起采用 continuous-availability 校验；历史隐藏后恢复的证据仍按 legacy-rediscovery 校验，不作为新策略通过的证明。

## 执行边界

需先取得付费 API 使用授权，再运行：

```sh
node scripts/acceptance/same-session-files-live.mjs --live-authorized
```

仅访问已配置的 DeepSeek 官方凭据引用 `DEEPSEEK_API_KEY`；本机凭据文件由父进程内存读取，传给自己的子进程环境。不会通过命令参数、launchctl、配置或报告落盘密钥。隔离 Profile 只链接公开产品包，不复制日常 Profile、会话、模型配置或资料；不使用日常 3080 端口，不安装依赖，不启动 ModLens。

每次尝试都是独立的标准预设会话，原生工具呈现。保留完整注册目录与产品权限过滤，能力推荐不再隐藏工具；另在工具执行层仅允许运行时观察、能力规划、会话内任务清单及指定合成文件的读写，禁止 shell、网络、插件重配和子代理。任务清单不能充当文件读取或回读证据。该执行护栏不是对恶意宿主插件或同用户外部进程的操作系统沙箱。

官方适配器和请求护栏按确定顺序装配，禁止自动重试和额外模型调用。一次尝试最多 16 次请求、每次最多 2048 输出 token，关闭思考用于这个小型结构化任务。16 次为两轮观察、能力规划、任务清单、读写和回读预留空间，避免旧 8 次边界截断正常规划流程。这是诊断的单次执行边界，不是金额上限；失败也消耗已预留请求，不清零重用。需要再次尝试时保留旧账本，用新 run ID 创建新证据。

## 独立验收

1. 首轮真实 `xiaoshe_runtime_info` 与 `request/header` 都证明：`read`、`write` 已注册且在当前 native 展示面可见。
2. 两轮每次请求均保留文件工具；第二轮在同一会话真实读取随机生成的 JSONL，不要求能力规划作为解锁步骤。
3. 从源数据提取四字段，缺少 `owner` 时使用 `null`，保持顺序和值。模型写入指定结果后必须用读取工具回读。
4. 独立进程核对完整事件配对、读到的实际内容、写入与回读的时序、最终 JSON、原文件哈希及没有额外文件。
5. 源码和运行时指纹前后一致，真实模型账本完整；自有进程组退出并清理隔离 Profile 后才发布成功任务证据。

结果写入每次独立的 `output/stabilization/same-session-files-<uuid>/`。包含两轮历史、原始合成输入与输出、请求/usage 账本、执行护栏挂载记录和汇总；失败证据也保留。缺失 usage 是未知值，不记作零费用。两个固定任务合同共享同一端到端过程，耗时与 token 只在 `sharedJourneyMetrics` 记录一次，不伪造分任务成本。

这覆盖两个固定任务 `files-extract-structured`、`files-structured-write-readback` 和一个独立工具可用性回归。它不等于 30 项任务全通过，不证明日常 `ss` 启动、原生窗口交互、ModLens 视觉或 Windows 已通过。实际计费以服务商账单为准；不同隔离 Profile 的运行时指纹不可拼接成同一个运行实例的成绩。

离线测试已纳入 `npm run verify:internal`；该默认命令不会发送付费模型请求。
