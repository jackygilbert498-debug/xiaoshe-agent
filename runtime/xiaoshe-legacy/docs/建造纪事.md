## 序：核心心智模型

- **你 = 甲方 + 监工**。戴三顶帽子：🏛 架构师（定方向、做取舍）、📋 产品经理（用大白话提需求）、🔍 质检（验收对不对）。**你从不搬砖——不写一行代码。**
- **AI = 施工队**。负责写代码、写测试、读参照资料、找 bug、维护文档。
- **一句总纲**：循环属于模型（AI 负责"想怎么干"），机制属于你（你负责"定规矩、验收、不让它塌房"）。
- **成品**：一个属于你、你完全理解的生产级 agent（那个"壳"）——GitHub 私有仓库 `jackygilbert498-debug/ke`（本地叫 `Harness`），能在终端里真替你干活。

一个贯穿始终的验收仪表盘是**测试条数**：每加一块功能，配一批**中文名的测试**，只增不减、全绿才算数。它从 v1 的 82 条一路涨到现在的 188 条。你不用读测试代码，看名字（比如"写文件_用户答y_才真的落盘"）+ 绿/红 就能验收。

# 第一部分：做了什么（详细流水账）

## 阶段 0 · 摸底（起点）

**甲方说的第一句话**：「先细细了解一下项目」。

**AI 干了什么**：派多个"读者"分头通读整个交接包（10 个代码模块、契约文档、82 条测试、方法论手册），产出一张结构化的项目地图；然后本机实跑测试。

**踩的坑 & 发现**：本机跑测试 **82 条里红了 7 条**。诊断结果：不是功能坏了，是**测试代码的跨平台毛病**——Mac 的临时目录本质是个"快捷方式"（`/var` 指向 `/private/var`），权限闸门核对路径时把快捷方式展开了、测试给的地址没展开，两边对不上，被误判成"越出工作区"。另外单独跑了"实链测试"确认**真连 Kimi 是通的**（本机代理在跑、密钥有效）。

**学到的**：换机后"跑通 82 条全绿"这个验收契约暂时破了，得先修——**红着的测试上不能盖楼**。

## 阶段 1 · v2 规划（定方向）

**甲方说**：「先做详细的规划，包括架构什么的」。

**AI 干了什么**：进入"先想清楚再动手"模式，**一次只问一个问题**，逐个把方向敲定。关键的几个岔路口和甲方的选择：

| 岔路 | 甲方选的 |
|---|---|
| 规划对象 | 整体路线图（v1 → 生产级 v2） |
| 目标终态 | **先通用后接管**——先做成日常真用的通用 agent，"是否接管星见"留到路线尾部的决策关卡 |
| 环境 | **双机并用**（Mac + Windows）——这一条把"跨平台"从"差距"升级成**硬需求** |
| 双机同步 | 私有 git 仓库（代码 + 记忆进 git，密钥永不进） |
| 推进节奏 | 逐功能验收（每块做完停下来给甲方过目） |
| 路线方案 | **方案二"换底盘"**（先服务化重构再装能力） |

**一个关键的架构复议**：AI 一开始按甲方选的"换底盘"提了个**常驻服务（daemon）**方案。甲方说「对比顶尖」，于是 AI 去对照真实的顶级 CLI，发现**它们都没有常驻服务**，daemon 的双平台运维成本对单人不划算——于是改成**"顶尖 CLI 同构"**：不搞常驻服务、状态全落盘、借系统调度器、多开进程即并行。**这次复议是甲方一句"对比顶尖"逼出来的，避免了走一条更重更险的路。**

**产出**：一份九里程碑的路线图 + 目标架构设计文档（写进仓库、提交 git）。九个里程碑：M0 换机闭环 → M1 引擎整备 → M2 无头模式 → M3 定时调度 → M4 后台跨重启 → M5 Web 工具 → M6 安全夯实 → M7 可观测性 → M8 真实使用毕业考 → 关卡 G（是否接管星见，甲方拍板）。

## 阶段 2 · M0 换机闭环（拆成 5 个任务）

目标：让"换机后 82 条全绿"这个基线重新可信，并建立双机同步。逐个任务：

- **T1 修 7 条红**：让权限闸门核对路径前先把工作区地址"展开"（对 Mac 的快捷方式免疫）。7 条红转绿本身就是回归证明。→ 84 条。
- **T2 去 Windows 残留**：报错提示不再写死 `D:\Harness`，改成指向本机真实的 `.env`；文档双平台化。
- **T3 记忆合并命令**：加 `python -m harness.memory merge`，两台机器的记忆文件 git 冲突时一条命令修好；记忆文件纳入 git。**这里对抗审查揪出一个 Critical**：某种 git 冲突样式（diff3）下会**静默丢掉一侧记忆还报成功**——正好踩"不许静默丢记忆"的高压线，当场修掉。
- **T4 接私有远程**：推送前做安全自检（翻遍 git 全历史确认密钥从没进过任何提交）；README 写下双机同步纪律。
- **T5 契约收尾**：CONTRACT.md 增 M0 段。

**建 GitHub 仓库这一步的真实经过（教程里很值得讲的一段）**：甲方发来一个私有空仓库地址。AI 要装 GitHub 命令行工具（`gh`）时，`brew install gh` **静默空转了 17 分钟**——原因是本机访问 GitHub 必须挂本地代理，不挂就不报错、干等。挂上代理（`export https_proxy=...`）后几秒装完。然后走**设备码登录**：AI 生成一个一次性代码，甲方在浏览器 `github.com/login/device` 输码授权。**中间有个教训被记进长期记忆**：AI 一度把一次性代码写在"工具调用之间"，甲方界面看不到、以为卡死了——所以关键信息（代码、步骤、问题）必须作为"回合最后一条消息"发出。授权成功后推送、并在 API 层面核实仓库确实是 Private、远端没有 `.env`。

**M0 交付**：90 条全绿 + 私有仓库双机同步跑通。

## 阶段 3 · M1 引擎整备（5 个任务）

目标：让多个 harness 进程能同时开工互不打架。

- **文件锁**：跨平台的进程互斥锁原语。
- **记忆上锁**：两个窗口同时"记住…"不互相覆盖。**对抗审查揪出 Important**：抢不到锁时记忆函数返回"失败"，却被上层渲染成"（早就记着了）"——**对模型假报成功**。改成抢不到锁就明确报错。
- **多会话档案**：一会话一个文件 + 启动时列出最近会话让你挑。**对抗审查揪出 Critical**：两个进程**同一秒启动**会拿到同一个会话编号、**互相覆盖存档**——用真双进程实验复现的，靠"编号里掺进程号"修掉。**还有一个**：并发清理旧档案时会崩进程（4 进程压测崩 3 个），补容错修掉。
- **repl 集成**：把"会话列表恢复"接进对话界面。**对抗审查揪出 Important**：会话列表里输入"②"（中文输入法打 2 的常见候选）会**崩掉启动**——一个词修掉。
- **收尾**：gitignore/契约/README。

**M1 交付**：110 条全绿。开两个终端同时用互不干扰、重开能挑会话接着聊。

## 阶段 4 · M2 无头模式（3 个任务）

目标：给 harness 加"免值守"入口。

- **核心 `headless.py`**：`run.py -p "任务"` 一句命令进、结果出、中途没人值守。
- **入口分流 `run.py`**：无参数=交互对话（一切如旧），`-p`=无头。**对抗审查揪出 Important**：`-p ""`（自动化里变量为空的经典事故）会**静默掉进交互模式、退出码还是 0**——一次"假成功"；改成报错退出码 2。
- **收尾**：契约/README。

**关键安全语义（教程里能讲清"创建时刻=审批时刻"）**：无头模式没人守着，危险操作默认全拒；`--allow write_file` 是你**敲命令那一刻**完成的授权；`.env`/私钥这些硬护栏给了白名单也照拒；**退出码 0 = 跑完了，不等于干成了**（真相看输出）。

**M2 交付**：123 条全绿。

## 阶段 5 · M3 定时调度（另一台机器做的 + 我修跨平台）

**M3 不是这台机器做的**——是在**另一台机器**上推进完并推送到 GitHub，这台机器 `git pull` 拉下来。内容：`schedule` 一套定时任务命令、双平台安装器（Mac launchd / Windows 任务计划）、六道无人值守安全闸、外加一轮基线夯实。**这本身就是 M1"多机不打架"设计的第一次实战验证——双机通过 git 协作真的成立。**

**但双机纪律也当场立功**：拉下来在 Mac 上跑，**171 条里红了 3 条**——全是 M3 的安装器测试在 Windows 那边写的时候**没把系统平台钉死**（跟着本机系统走，Windows 绿、Mac 红），其中一条还会把测试文件**误写进真实的系统目录**。已修复（平台显式钉死、落盘路径进沙盒），并把这条跨平台纪律写进测试文件头。

**教训**：一块功能在一台机器上"全绿"，换台机器可能就露馅——**这正是路线图把"双平台测试都要绿"列为硬需求的原因**。

**M3 交付**：171 条全绿，两机同步。

## 阶段 5 补记 · M3 定时调度（这台 Windows 机的第一手）

> 上面阶段 5 是从"没做 M3 的那台机器"视角记的；这里补上**做 M3 的这台设备**（本机 Windows）亲历的细节与一条硬教训。两节互补：那边是 Mac 上跑出 3 条红并修跨平台，这边是 Windows 上踩编码坑并落地验收。

### M3 · 定时调度（这台设备做的）

- **想干嘛**：让 agent 能定时、无人值守地自己跑（比如每小时干件事），电脑重启也照跑。
- **做了啥**：借系统调度器（Windows 任务计划 / Mac launchd）+ 一个"薄监工"复用无头模式干活；配了六道安全闸（墙钟超时两阶段杀、防重入、能急停、总开关 `HARNESS_DISABLE_SCHEDULE`、`.state/schedule` 目录设防、默认不连 MCP）；双平台安装器（schtasks / launchd）；`schedule` 八条中文子命令。
- **踩的坑**：真机跑发现子进程在 Windows 按 GBK 输出、被监工按 UTF-8 读成乱码。
- **怎么解决**：监工给子进程强制 `PYTHONUTF8=1`，两端编码对齐。
- **验收**：真机端到端验过——任务计划触发 → 监工 → 真连 Kimi → done、越权计数准确、pause / remove 全过。

### M3 前 · 基线夯实（坏文件免疫）

- **想干嘛**：定时任务无人值守，任何"一启动就崩"的缝隙都会被放大成"每次定时都失败还没人发现"。
- **做了啥**：修了 5 处——`memory.json` / `.env` / 会话档案编码坏不再崩、无头 Ctrl+C 温和退出（码 130）。
- **验收**：全量测试全绿。

### ⚠ 一个惨痛的坑：这台机器终端输出污染

- **遇到啥**：这台 Windows 机的终端输出经常被污染 / 我产生幻觉，把"以为成功"当"真成功"上报，一度连 git 版本号都看错、反复误导甲方。
- **教训**：凡关键结论必须**写文件再 Read**、或**跑测试看真实输出**、或**多 agent 交叉验证**，绝不信命令自己喊的"成功"。

## 阶段 6 · 对比顶尖壳（回答"它到底算不算真壳"）

**起因**：甲方觉得练手做的 `myagent` "太简陋，顶级的不这样"，想拿几个顶尖项目对比。

**方法（值得记）**：先让 AI 把三个目标认清、确认能下载（甲方点头再下），然后**开一个多 agent 工作流**——每个顶尖壳派一个 agent 专门实地拆架构（读真代码，不靠名气脑补），另派一个 agent 摸清自己的 Harness，最后一个 agent 汇总成差距报告。三个对比对象：**Kimi 官方 CLI（主参照）、CodeWhale（Rust）、cc-haha（泄露版 Claude Code 修复版）**。

**结论（教程里能当"什么是完整壳"的定义）**：一个"完整壳"由**六大件**构成——① 主循环 ② 工具 ③ 安全护栏 ④ 记忆/上下文 ⑤ 配置/多模型 ⑥ 打包分发。**你的 Harness 六件全有、都跨过成型线，已经是一辆能上路的车**；最弱的一维是"只会开一个模型（Kimi）"。顺手对比的 `myagent` 只是个打印一句话的空壳（≈5%），缺的正是最难的 95%。

## 阶段 7 · 流式输出（已完成，治"按了没反应"）

**起因**：甲方在终端里让 harness 查了 64 个视频的帧率，成功了，但过程中"按了 a 半天没反应"——其实是生效了、只是它闷头干活没有动静。这暴露了一个真实短板：**不流式**（回复要等一整轮跑完才显示，黑箱感强）。

**先实测再建（纪律）**：动传输层这块"最娇贵的代码"前，AI 先探一枪——确认 Kimi 线路**支持流式**（回复能一小块一小块吐出来），再写计划。

**执行（4 个任务全部完成，共 3 轮对抗审查揪出真问题）**：

- **T1 SSE 拼装内核**：把流式分片拼回完整回复的纯函数。**对抗审查揪出**：打印回调一旦出错会击穿拼装、丢光已收内容、崩掉交互循环（Windows 打 emoji 就会触发）——改成回调坏了就继续拼、绝不丢内容。
- **T2 流式传输层**：真正连 curl 流式收发。**对抗审查揪出一个 Critical**：流式路径会**"静默吞掉 API 错误"**——密钥失效/限流时不报错、直接返回空回复。审查员**拿作废密钥打真实 Kimi 端点**才逼出来的：老路响亮报错、流式却静默返回空。已修复并实链验证根治。**还揪出 Important**：90 秒总超时会把合法的长回复"安静截断"，改成"空闲失速检测"。
- **T3 接进对话界面**：让终端里真能逐字冒字、有"（思考中…）"占位、Ctrl+C 能干净打断。**对抗审查用真机实验又揪出一个 Critical**：Ctrl+C 打断工具执行会让会话"砖死"——悬空 tool_calls 导致之后每句话 API 400 死循环（根因：回滚用 `except Exception`，而 Ctrl+C 是 `BaseException` 子类会绕过它）。改一行 `except BaseException` 修掉，配回归测试。还修了占位残留垃圾、压缩摘要上屏两个 Important。
- **T4 收尾**：契约/README/推送。

**终审真机三验通过**：① 回复逐字冒出；② Ctrl+C 打断工具后再问一句不砖死（存档未毒化）；③ API 错误响亮报错不静默、密钥不泄漏。

**顺带产出**：一份 HTML 的"两轮质量审计报告"（把 T1/T2 审计发现的问题和处置可视化）。

**流式交付**：**188 条全绿**，交互模式现在真能看到逐字冒字了。

# 第二部分：怎么做的（方法论 · 教程的核心）

没有一次是"随便让 AI 写写"。每一块功能都走**同一条纪律流水线**。下面每一步都给"甲方该说什么"的话术 + 本项目的真实例子。

```
① 头脑风暴（先想清楚）
  → ② 写契约/规格（大白话说清该做/不该做）
    → ③ 写详细计划（拆成一次能验收一块的小步）
      → ④ 施工队按计划做（测试先行）
        → ⑤ 规格审查（照计划了吗？多做少做了吗？）
          → ⑥ 对抗式质量审查（换个 AI 动手做实验找真 bug）★
            → ⑦ 修真问题 → 复审确认
              → ⑧ 里程碑终审 → 提交 + 推送
```

### ① 头脑风暴——先想清楚再动手

- **在干嘛**：别一上来就让 AI 写代码。先把"要做什么、给谁用、怎么算成功、有哪些取舍"聊透。
- **甲方该说**：「先别写代码，我们先头脑风暴 / 先做详细规划」。然后 AI 会**一次只问你一个问题**，你逐个拍板。
- **真实例子**：v2 规划就是这么定下来的——环境是不是双机？目标是先通用还是先接管？这些都是一问一答敲定的。
- **坑**：如果跳过这步直接让它写，做出来的东西大概率不是你要的，返工代价大。

### ② 写契约/规格——让它先写"说明书"，你再点头

- **在干嘛**：让 AI 用**大白话**写下"这东西该做什么、不该做什么、怎么算对"，你看得懂、能对照验收。
- **甲方该说**：「把我们刚定的写成一份规格/契约，大白话，我要能看懂」。
- **产出长什么样**：一份 `CONTRACT.md`，逐条列"你做什么 → 它应该怎样"的表格，加"已知取舍"。本项目每个阶段都有一段契约。
- **价值**：跨会话不失忆（AI 换个会话读契约就接上）、验收有白纸黑字依据。

### ③ 写详细计划——拆成能一块块验收的小步

- **在干嘛**：把功能拆成小任务，每个任务能**单独验收、单独回退**。
- **甲方该说**：「把这个拆成详细的实施计划，每步能单独验收」。
- **产出长什么样**：一份计划文档，每个任务写清"改哪个文件、先写什么测试、期望什么结果、怎么提交"。
- **价值**：永远有"能跑的版本"垫底，不存在做到一半烂尾。

### ④ 施工队按计划做——测试先行

- **在干嘛**：AI 按计划一个任务一个任务地实现，**先写测试（会红）再写代码（转绿）**。
- **甲方基本不用管**，等它报告。
- **关键**：每块都配**中文名的测试**——你看测试名 + 绿/红 就能验收，不用读代码。

### ⑤ 规格审查——照计划了吗？

- **在干嘛**：派另一个 AI 去核对"实现是不是照计划来的、有没有偷偷多做或少做"。
- **本项目每次都做**，大多是干净通过。

### ⑥ 对抗式质量审查——★ 最独特、最管用的一招

- **在干嘛**：**不让写代码的 AI 自己夸自己**，而是派另一个 AI 专门去**挑刺、做实验找真 bug**——注入假数据、模拟坏返回、跑各种失败路径、亲手压测。
- **甲方该说**：「派一个审查员去对抗式地审这段代码，动手做实验，别只读代码」。
- **为什么它值钱**：**单元测试照不到的深水雷，全靠这步捞出来。** 本项目真捞出来的例子：
  - 流式传输层"静默吞掉 API 错误"——审查员**拿作废密钥打真实端点**逼出来的。
  - 两进程同一秒启动互相覆盖会话档案——审查员**用真双进程实验**复现的。
  - 并发清理档案崩进程——审查员**4 进程压测**压出来的（崩 3 个）。
  - 记忆合并遇到某种 git 冲突样式静默丢记忆——审查员**构造真实 git 冲突**发现的。
  - 打印回调出错会崩掉交互循环——审查员想到"Windows 打 emoji 会编码错"这个真实场景。
- **一句话**：这一步是"能放心用"和"看着能用一用就崩"的分水岭。

### ⑦ 修真问题 → 复审

- 审查员报的每个问题，让原施工队修，然后**让审查员再验一遍**（不是修完就算）。本项目严格执行"修完必复审"。

### ⑧ 里程碑终审 → 提交推送

- 一个里程碑所有任务做完，派一个 AI 从整体视角再审一遍（四方一致性、有没有漏、回归安全、推送就绪），然后 `git commit` + `git push`（记得先挂代理）。

## 配套的六条老规矩（每条配真实例子）

1. **中文名的测试**——测试名说清行为（"写文件_用户答y_才真的落盘"），甲方看名字+绿/红验收，不读代码。
2. **大白话契约**——每块功能配 `CONTRACT.md` 段落，跨会话不失忆。
3. **增量里程碑**——每步留可回退的 git 基线；本项目 40 多个提交，任何一个点都能回退到"能跑的车"。
4. **参照驱动**——拿不准就读顶级实现（对比顶尖壳那次就是把 Kimi 官方 CLI、CodeWhale 的真代码拆开看）。
5. **真机验收**——除了离线测试，关键能力必须用真 Kimi + 真人式自然对话跑一遍（甲方在终端里亲手查 64 个视频帧率就是一次真机验收）。
6. **双机 git 同步**——动手前 `git pull`，收工 `git push`；记忆进 git，密钥走 U 盘。

## 几条一开始就拍死、不许改回去的硬决定

- 安全默认从严：没人值守时危险操作默认拒绝；`.env`/私钥连读都拒。
- 模型锁 Kimi、传输走系统 curl（当初实测 Python 自带的加密握手连不上 api.kimi.com，curl 稳）。
- 纯 Python 标准库、零第三方依赖——换机/部署摩擦最小。

## 用到的工具与环境（教程要交代的）

- **指挥台**：Claude Code（就是甲方打字下指令、AI 干活的地方）。
- **几个"模式"**：头脑风暴模式、写计划模式、"派施工队+两道监理"模式、多 agent 并行拆解、出可视化报告——甲方一句话就能触发。
- **git + GitHub 私有仓库**：双机同步的载体。

## 红旗预警（AI 在忽悠你 / 项目要塌房的信号）——教程里很实用的一节

- AI 说"已完成、都测过了"但**没给你看具体输出/绿红** → 让它把证据摆出来。
- AI **自己夸自己代码没问题** → 一定要派对抗审查，别信自夸。
- 一个功能"在我这全绿"但**没在另一台机器/另一种情况验过** → 大概率有跨平台/边角漏网（M3 那 3 条红就是活例子）。
- 关键信息（代码、步骤）AI 写在"中间"你看不到 → 让它作为"最后一条消息"重发。
- AI 跳过头脑风暴/契约直接写代码 → 拉回来，先想清楚。
