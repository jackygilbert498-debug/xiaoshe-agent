# Harness 共建手册 · 写给 Vibe Coder 的你

> 这不是一门教你写代码的课。这是一门教你 **「看懂 → 指挥 → 验收」** 的课——
> 让你在不手写一行代码的前提下,能和我(Claude)一起,把一个**生产级 agent harness** 一块块造出来。
> 你负责理解和判断,我负责写代码和测试。这本手册,是教你怎么当好这个「判断的人」。

---

## 我们要造什么(已定方向)

**一个独立的、属于你自己的 agent harness**(方案 B),Python 起步,增量推进。

- 星见(你的视频 agent)**暂时继续骑 Kimi**,不受影响、不停摆;
- 我们另开一条线,从零造你自己的 harness——**没有产品压力,造扎实、真搞懂**;
- 它若长成了、扛得住,**将来再考虑接管星见**(那时是水到渠成的升级,不是现在的豪赌)。

为什么不是 A(直接取代 Kimi)或纯 C(先干再说):见和我的对话,一句话——**A 是同时赌产品和学习,太险;B 天然留着变成 A 的后路。**

## 你的定位:你不是码农,你是「三顶帽子」

| 帽子 | 你干什么 |
|---|---|
| 🏛 **架构师** | 定方向、做取舍(用什么、不用什么、先做哪个) |
| 📋 **产品经理** | 提需求、描述"我要它能做到什么" |
| 🔍 **质检(QA)** | 验收——**靠跑行为 + 读中文测试名**,不靠读代码 |

我的活:写代码、写测试、读 Kimi/CodeWhale 源码当参照、debug、维护架构文档。
**你看不见的 bug 由我负责;你看得见的"对不对"由你拍板。**

---

## 这本手册怎么用

1. **不急着搭建。** 先把这几章读一遍,建立"我在干什么、我该懂什么"的全局感。
2. **不需要读懂任何代码。** 全程大白话 + 生活类比。看不懂的技术细节,跳过没关系——那是我的活。
3. **每个阶段动手前,回看对应那一章**——它会告诉你这一步:你要懂什么、你要拍什么板、你怎么验收、你会对我说什么。
4. **把它当"我们俩的共同语言"。** 你我对齐了词汇和纪律,配合才顺。

## 一条核心心法

> **循环属于模型(它本来就聪明),机制属于我们(harness 是我们造的)。**
> 你每学一步,只要问自己一句:**"这个机制是为了解决什么痛点?没有它会怎么翻车?"**
> 想清楚这个,你就能指挥我把它造对、也能验收它造好了没。代码长什么样,不重要。
