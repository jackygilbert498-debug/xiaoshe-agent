# 04 · 六阶段路线图:从空壳到你自己的 v1 agent

> 这是我们的施工总图。每个阶段都有**一个能跑起来的里程碑**。
> 每节按同一个结构写,你只看你那几栏就行:
> **🎯 你要拍的板 · 👤 你要懂什么 · ✅ 你怎么验收 · 🪄 你会对我说什么 · 🏭 我参照哪里**
> 至于代码——我写,你验。

整条路的节奏:**一次只造一小块 → 配上中文测试 → 你跑过了 → 进下一块。** 永远有个能跑的版本垫底。

---

## 阶段 0 · 脚手架 🌱

**里程碑:一个"空壳"agent,你说一句话,它回你一句话,还留下日志。**

- **一句话**:先把"你↔模型"这条最短的线接通,确认管子是通的。
- **没有它会怎样**:地基没夯,后面什么都搭不稳。

| | |
|---|---|
| 🎯 **你要拍的板** | 用哪个模型 API(你已有 Kimi/Claude,先用着);学习仓库建在哪 |
| 👤 **你要懂什么** | 就 [01 章](01-心智模型.md)那个"问→答"的最小闭环。不用懂别的 |
| ✅ **你怎么验收** | 你打一句"你好",它回一句话;去看日志文件,里面记着这次往返 |
| 🪄 **你会对我说** | "帮我起一个最小 agent,接上模型,我发话它能回,带日志和一个冒烟测试" |
| 🏭 **我参照** | 课程 s01;无需 Kimi |

---

## 阶段 1 · 核心循环 + 工具 + 权限 🔧

**里程碑:agent 能在你授权下,真的读写你本地的文件、跑命令。**

- **一句话**:给它装上"手"(工具)和"刹车"(权限)——它从"只会说话"变成"会动手"。
- **没有它会怎样**:它只是个聊天机器人,干不了实事;或者反过来,没刹车地乱删你文件。

| | |
|---|---|
| 🎯 **你要拍的板** | 先给哪几个工具(建议:读文件、写文件、跑命令);哪些操作必须先问你(危险边界) |
| 👤 **你要懂什么** | 工具 = 它的一项技能([词汇表](03-词汇表.md));权限闸门 = 危险动作先拦一下。**你在星见上已经实操过权限了** |
| ✅ **你怎么验收** | 让它读一个文件→看到内容;让它做个危险操作→它**先问你**而不是闷头干;测试里有"危险操作被拦住"这类绿条 |
| 🪄 **你会对我说** | "加读/写/跑命令三个工具;删文件、跑危险命令这类必须先问我;每个都配测试,坏输入不许崩" |
| 🏭 **我参照** | 课程 s02/s03;Kimi 的 `tool/` 和 `permission/policies/`(13+ 策略) |

> 🚩 **这一阶段过了,你就有一个"能听话干活、且守规矩"的真 agent 了**——已经比很多人做出来的东西扎实。

---

## 阶段 2 · 记忆 + 压缩 + 任务清单 🧠

**里程碑:长对话不"爆桌面",agent 能自己记待办、撑住多步任务。**

- **一句话**:给它"行车记录仪 + 会整理桌面的能力",让它扛得住长活。
- **没有它会怎样**:聊几轮就忘事、或上下文塞满崩掉;干多步任务走哪算哪、丢三落四。

| | |
|---|---|
| 🎯 **你要拍的板** | 多长算"该压缩了";哪些东西必须记牢不能被压掉(比如你的硬性要求) |
| 👤 **你要懂什么** | 上下文窗口 = 桌面大小;压缩 = 把旧资料缩成摘要;任务清单 = 干大事前先列计划([词汇表](03-词汇表.md)) |
| ✅ **你怎么验收** | 故意跟它聊很久/给个多步任务→它不崩、还记得早先你的要求;它会列出待办并一条条勾掉 |
| 🪄 **你会对我说** | "加上下文压缩,桌面快满时自动腾地方,但别忘了我开头定的规矩;再加个任务清单,干多步活先列计划" |
| 🏭 **我参照** | 课程 s05/s08/s09;Kimi 的 `compaction/` 和 `context/projector.ts`(怎么压才不出错) |

---

## 阶段 3 · 子智能体 + 错误恢复 + 后台任务 🧩

**里程碑:能把活拆给"分身"并发干,挂了能从存档恢复,慢活丢后台。**

- **一句话**:从"单兵"升级到"会调度的小队长",而且打不死。
- **没有它会怎样**:大任务把主线淹没;一出错全盘崩、白干;慢活把整个流程卡死。

| | |
|---|---|
| 🎯 **你要拍的板** | 什么样的活值得拆给分身;出错时是重试、换路子、还是停下问你 |
| 👤 **你要懂什么** | 子 agent = 派实习生干脏活带结论回来;错误恢复 = 游戏存档读档;后台任务 = 洗衣机开着你干别的([词汇表](03-词汇表.md)) |
| ✅ **你怎么验收** | 给个大任务→它拆成几块并发干完;中途故意制造一个错→它能恢复接着干,不是从头崩 |
| 🪄 **你会对我说** | "加子 agent 能拆活并发;加错误恢复,崩了能读档继续;慢操作丢后台别卡主线。每块都要有测试覆盖出错的情况" |
| 🏭 **我参照** | 课程 s06/s11/s12/s13;Kimi 的 `subagent-host.ts`、`replay/`、`background/` |

> ⚠️ **从这阶段起进入"重状态/异步"区**,bug 更隐蔽。这正是"有我这个会读代码的搭档"最值钱的地方——我会重点写测试、对照 Kimi/CodeWhale 来保证正确。**你单独 vibe 容易撞墙的部分,交给我。**

---

## 阶段 4 · MCP 对接 + 综合整合 🔌

**里程碑:agent 能加载外部 MCP 插件,前面所有零件收口成一个统一系统——你的 v1。**

- **一句话**:开一个"USB 插座",让它能即插即用外部工具(将来包括你的星见桥);再把全部机制理顺成一个整体。
- **没有它会怎样**:能力被锁死在内置工具;零件多了各自为政、变成乱麻。

| | |
|---|---|
| 🎯 **你要拍的板** | 第一个接什么 MCP 工具来验证(可以拿你熟的星见桥练手);要不要把它做成能给别人用 |
| 👤 **你要懂什么** | MCP = 工具的 USB 标准([词汇表](03-词汇表.md));"综合整合" = 把零件理成有条理的系统 |
| ✅ **你怎么验收** | 接上一个真实 MCP 工具→agent 能调它干活;全套老测试重跑还是绿(没把老功能搞坏) |
| 🪄 **你会对我说** | "加 MCP 客户端,先支持一种连接方式;拿星见桥当第一个插件验证;把前面所有机制收口成一个干净系统,补一份总契约文档" |
| 🏭 **我参照** | 课程 s19/s20;Kimi 的 `mcp/connection-manager.ts`、`di/`;MCP 官方规范核对协议 |

> 🎉 **走到这,你就有了一个"你自己的、你完全理解的、能接生态"的 v1 agent harness。** 这已经是真东西。

## 阶段 5 ·(可选)团队 / 调度 / 自治 🚀

**里程碑:浅尝多 agent 协作、定时触发、目标自治;产出一份"离生产级还差什么"的清单。**

- **一句话**:摸一摸最难的那批生产难点,知道边界在哪。
- **定位**:这些 Kimi/CodeWhale 也只是部分覆盖,**目标是"读懂难在哪",不强求全造完**。

| | |
|---|---|
| 🎯 **你要拍的板** | 你的真实需求里,到底用不用得上这些(很多个人项目用不上) |
| 👤 **你要懂什么** | 知道这些机制存在、解决什么场景即可 |
| ✅ **你怎么验收** | 我给你一份"生产级还差哪些硬骨头"的清单 + 每条的难点说明——**这份清单本身就是你能力到位的证明** |
| 🪄 **你会对我说** | "带我浅尝下 cron、多 agent、自治目标,重点告诉我每个难在哪、Kimi 怎么处理的" |
| 🏭 **我参照** | 课程 s14–s18;Kimi 对应模块;CodeWhale 的 `whaleflow`、`execpolicy` |

## 走完全程,你会得到什么

1. **一个 v1 agent harness**——你自己的、能跑、有测试兜底、你完全理解(理解的是"机制和数据流",不是每行代码)。
2. **一身永久能力**——以后看 Kimi、Claude Code、任何 agent 框架都是降维;选型、调试、定制全部变快。
3. **一个想清楚的决定**——它到底要不要接管星见(那时你有资格判断了)。
