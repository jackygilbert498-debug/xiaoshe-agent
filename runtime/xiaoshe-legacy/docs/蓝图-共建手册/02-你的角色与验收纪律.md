# 02 · 你的角色与验收纪律

> 这是整本手册**最实用**的一章。读完你会知道:每一步你具体做什么、怎么在**不读代码**的情况下判断"成了没"、怎么给我下指令才让我造得准。

---

## 一、你的三顶帽子(轮流戴)

### 🏛 架构师 —— 定方向
你决定:用什么语言、先造哪个零件、要不要这个功能、出现两条路时走哪条。
**你不需要知道"怎么实现",只需要知道"我要往哪走"。** 拿不准时,你问我利弊,我给你摆清楚,你拍板。

### 📋 产品经理 —— 提需求
你用大白话描述"**我要它能做到什么**"。例如:
> "我要这个 agent 能听我说'读一下这个文件夹里的视频文件名',然后它真的去读、把名字列给我。"

你不用说"怎么写",你只说"要什么 + 不要什么"。**剩下翻译成代码是我的活。**

### 🔍 质检(QA)—— 验收
这是你**最核心的技能**,下面整章重点讲。一句话:**你靠"看行为"和"读中文测试名"来确认对不对,不靠读代码。**

---

## 二、为什么我们必须有纪律(否则 vibe = 一锅意大利面)

很多人 vibe coding 到后面变成"跑不动、改不动的乱麻",**不是因为 AI 不会写代码,是因为没纪律**。我会一直替你守这四条——你只要理解它们为什么重要,配合我别嫌烦:

| 纪律 | 大白话 | 为什么救命 |
|---|---|---|
| ✅ **测试先行** | 每造一个功能,我先写一个"自动检查它对不对"的小程序 | 这是你这个不读代码的人**唯一可靠的"对错眼睛"** |
| 📜 **契约文档** | 每个模块我写一份说明书(像星见的 `CONTRACT.md`) | 让我下次开新会话时**不失忆**,系统不会越改越乱 |
| 🧱 **增量里程碑** | 一次只造一小块,每块都能单独跑起来 | 永远有个"能跑的版本"垫底,出问题好回退 |
| 🏭 **参照驱动** | 拿不准就去读 Kimi/CodeWhale 怎么做的,照搬思路 | 不闭门造车,站在两套生产级实现的肩膀上 |

> 你刚在星见上**亲眼见过这套**:我先冻结基线 → 写契约 → 配置外置 → 安全闸门 → **32 个测试全绿** → 实链冒烟。整个 harness 就是把这套放大。

## 三、🔍 不读代码,你怎么验收?(重点中的重点)

你看不懂代码,但你**完全有能力判断"成了没"**。四个办法,从易到专业:

### 1️⃣ 跑行为 —— 最直接
我把功能造好,你**亲自跑一下、用一下**,看它做的事对不对。
> 例:让 agent"读这个文件夹的视频名",你看它列出来的名字和你眼睛看到的一不一样。对,就过。

### 2️⃣ 读中文测试名 —— 你的"对错清单"
我写的每个测试,**名字都用中文写、说清它在验证什么行为**。你不用看测试代码,只看名字 + 跑出来的"绿/红"。
> 例(星见真实测试,你回看就懂):
> - `8个付费API全部被拒` ✅ → 你一看就知道:危险的付费工具被拦住了
> - `源文件不应被移动删除` ✅ → 你一看就知道:只复制不动源,纪律守住了
>
> **一排绿色 = 你要的行为都被守住了。某条变红 = 那个行为坏了,我得修。** 这就是你的验收仪表盘。

### 3️⃣ 看契约文档 —— 确认"说好的"
每个模块的 `CONTRACT.md` 用大白话写明"它该做什么、不该做什么"。你对照它,确认我没造跑偏。

### 4️⃣ 用"避坑清单"当审查问句 —— 进阶
课程每节都有"复刻坑点"。你不用懂,但可以**拿来当问我的问题**。
> 例:"课程说'工具结果顺序错了会出错',你这块处理对了吗?写测试覆盖了吗?"
> 你这么一问,等于逼我把最容易错的地方说清楚、测到位。**你提对问题,比你读懂代码更有价值。**

> ⚠️ 一个诚实的提醒:有些 bug(比如并发时偶发的)行为上一时看不出来。这种**由我负责**——我会主动写针对性测试、用参照实现对照、把风险点告诉你。你的任务不是抓这种 bug,是**坚持"每个功能都要有测试、都要能跑给我看"这条底线**。

## 四、🪄 怎么给我下指令(高质量"咒语"模板)

你给我的需求越清楚,我造得越准。一个好指令包含四块(不用全有,但越全越好):

```
【目标】 我要它能做到什么(大白话)
【约束】 不能做什么 / 必须遵守什么(比如"绝不碰付费API""只复制不动源")
【验收】 我怎么算它成了(比如"我跑 X,应该看到 Y")
【参照】 照谁来(比如"参照 Kimi 的 turn 那块" / "按课程 s03 的思路")
```

**示例(你将来会这样跟我说):**
> 【目标】给 agent 加个"读文件"工具,我说读哪个文件它就读给我看。
> 【约束】不让它读项目文件夹以外的路径(安全)。
> 【验收】我让它读一个存在的文件→能看到内容;读一个不存在的→给我友好提示不报错崩。
> 【参照】按课程 s02 工具分发的思路,生产细节参照 Kimi 的 tool 那块。

你能写出这样一段,我就能给你造出对的东西、配上对的测试。**这,就是 vibe coding 一个 harness 的真正姿势。**

## 五、本章小结:每一步你的固定动作

1. **开工前**:回看 [六阶段路线图](04-六阶段路线图.md) 对应那节,搞懂"这块解决什么痛点"。
2. **下指令**:用上面的四块模板,把"要什么/不要什么/怎么算成"说清楚。
3. **我交付**:代码 + 中文测试 + 契约文档。
4. **你验收**:跑行为 ✅ + 看测试全绿 ✅ + 对照契约 ✅。
5. **过了就进下一块;没过我修。** 永远保持"有一个能跑的版本"。
