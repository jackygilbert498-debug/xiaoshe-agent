# 阶段5 · 离生产级还差什么（v1 完工后的诚实边界）

> 这份清单是阶段5 的交付物本身。走完阶段0-4，你有了一个**能跑、有 82 条测试兜底、经多轮对抗复盘 + 一次整体体检、你完全理解**的 v1 agent harness。
> 但"你自己理解的 v1"和"能扛真实生产负载的系统"之间，还隔着下面这些硬骨头。**知道它们在哪、难在哪，就是你架构师能力到位的证明。**
> 每条按同一结构：**我们现在在哪 · 生产级要什么 · 难在哪 · 想补的话往哪走**。

---

## 一、多 agent 团队 / 协议（手册 s15/s16）

- **我们现在**：`spawn_subagent` 能派一个分身、**同步阻塞**跑完、只带结论回，嵌套上限 2 层。
- **生产级要**：一队分身**并发**跑、彼此能发消息/共享中间产物、主控做结果聚合与冲突仲裁（Kimi 的 `subagent-host`、CodeWhale 的 `whaleflow`）。
- **难在**：并发状态一致性、死锁、部分失败的补偿、成本爆炸（N 个分身各烧 token）、"谁是权威"的仲裁。这正是分布式系统的老大难，搬到 agent 上更糊。
- **往哪走**：先把 `spawn_subagent` 改成非阻塞 + 一个 `join`/结果队列；参照 Kimi 的 subagent 调度器。

## 二、定时调度 / 持久后台任务（手册 s14 + s13 进阶）

- **我们现在**：`jobs.py` 后台任务**只活在本进程**（`_JOBS` 进程内字典），重启即失忆；没有定时触发、没有 wall-clock 硬超时。
- **生产级要**：任务落盘的持久队列、cron/定时触发、崩溃重启后重连或重跑、资源配额与超时强杀、失败重试策略。
- **难在**：exactly-once 语义（别重复执行副作用）、跨重启的进程重连、时钟/时区、僵尸清理。
- **往哪走**：给 `jobs` 加一个 `jobs.json` 持久化（pid + command + 状态）；加 wall-clock 看门狗线程；再谈 cron。

## 三、工作树隔离（手册 s18）

- **我们现在**：**无**。所有工具直接在 `ROOT` 里读写；多个分身若并行改文件会互相踩踏。
- **生产级要**：每个并行 agent 一个 git worktree 沙盒，各改各的，最后合并（这也是很多 agent 平台"隔离执行"的基础）。
- **难在**：worktree 生命周期管理、合并冲突、清理、磁盘开销。
- **往哪走**：这条和"多 agent 并发"绑定——先有并发写需求，再上 worktree。

## 四、目标自治（手册 s17）

- **我们现在**：一问一答（含多轮工具），一轮结束就停。没有"给个大目标、自己拆解、跑几小时、自我纠偏"。
- **生产级要**：目标分解 → 计划 → 执行 → 自评 → 纠偏的长循环，且知道**何时该停**（防跑偏烧钱）。
- **难在**：进度度量、"做完了没"的判定、防止无限自我循环、错误累积。我们的 `MAX_TOOL_ROUNDS=20` 只是最粗的刹车。
- **往哪走**：`update_todos` 已是雏形；把它 + 一个"自评是否达成目标"的收尾判定串起来。

## 五、上下文 / 成本工程（真实生产的日常）

- **我们现在**：`compaction` 按**字符数**（token 的粗略代理）压缩；`all_specs()` 每轮把全部工具声明重发。**prompt caching 与流式已实现**（`kimi_client` 传 `prompt_cache_key`=会话 id 命中稳定前缀、`usage_report` 统计 `cached_tokens` 命中率；流式输出 v2 基线已上）——原"无 caching/无流式"为 v1 快照，已过期。
- **生产级要（仍缺）**：精确 token 计量与预算（现按字符）；工具声明按需裁剪（但 A11 已论证：**23 工具仅 ~3.5k token，动态裁剪反打破前缀缓存净亏 → 反向纪律=工具声明字节级冻结**，除非工具涨到 50+ 或接大型 MCP server 才重估）。
- **难在**：token 计量要贴合具体模型分词。
- **往哪走**：把 compaction 的字符预算换成真 token 计数（caching 已落地）。A11 丙 compaction 三连（75% 触发点须同抬字符安全网否则 no-op / token 预算护尾 / 防抖动）是这条的具体化。

## 六、权限 / 沙箱深度（安全）

- **我们现在**：三态策略链 + 敏感文件硬护栏 + 命令**子串扫描**；但 `run_command` 是 `shell=True` **无沙箱**，MCP server 以**完整权限**跑。复盘已证实命令扫描可用 `chr()` 拼串规避。
- **生产级要**：真正的沙箱（容器/低权限用户/syscall 过滤）、能力式权限（capability-based）、对不可信 MCP server 的隔离。
- **难在**：跨平台沙箱（Windows/Mac/Linux 各一套）、既要隔离又要好用。
- **往哪走**：不可信内容别用 `run_command` 跑；要跑就上容器。子串黑名单只是"防手滑"，不是"防对手"。

## 七、可观测性 / 遥测

- **我们现在**：`logs/agent.jsonl` 逐条消息（含 depth/is_error/usage）。
- **生产级要**：结构化 trace、指标（延迟/成功率/成本）、可回放调试、成本核算与告警、看板（Kimi 有 `telemetry` 包）。
- **难在**：不是难，是"量"——要一整套采集/存储/查询/看板。我们的 JSONL 是它的种子。

## 八、多模型 / 路由 / 降级

- **我们现在**：写死 Kimi（`kimi-for-coding`）。换模型只改 `.env`，但没有多 provider、没有失败降级、没有按任务路由。
- **生产级要**：多 provider 抽象、失败自动换备用模型、按任务难度/成本路由（Kimi 的 `kosong` 就是 provider-agnostic 层）。
- **难在**：不同 provider 的工具协议/流式/错误码差异抹平。
- **往哪走**：把 `kimi_client` 抽象成 `LLMClient` 接口，Kimi 只是一个实现。

## 九、传输鲁棒性

- **我们现在**：模型传输走 **curl 子进程**（为绕本机 TLS/代理怪癖的务实妥协）；MCP 只支持 **stdio**。
- **生产级要**：原生 SDK/HTTP、流式、连接池；MCP 支持 HTTP/SSE 传输。
- **难在**：curl 方案换环境要改（没 curl 的机器就跪）；这是我们最"务实但不优雅"的一处。
- **往哪走**：`kimi_client._post` 一处封装了传输，将来换 httpx 只改这里。

## 十、测试 / 评估的层级

- **我们现在**：82 条单元/集成测试 + 多轮多 agent 对抗复盘 + 一次整体体检（挖出并修了 10+ 条高危 + 一堆中低危/去重优化，全是单测照不到的）。
- **生产级要**：真实任务的 eval 套件、性能基准、持续红队、property-based/fuzzing。
- **难在**：eval 的"对不对"本身难判定（agent 输出开放）。
- **往哪走**：我们的"对抗复盘"已是红队雏形；把它固化成常态流程。

## 十一、跨平台

- **我们现在**：只在 **Windows** 实测过。`.command`/`.bat`、`os.replace`、taskkill、GBK 终端都按 Windows 走。
- **生产级要**：Mac/Linux 同等验证（总台本身是关心苹果电脑的）。
- **难在**：进程组/信号、路径、编码在三个平台各有坑。
- **往哪走**：CI 三平台跑同一套测试。

## 十二、状态 / 并发正确性

- **我们现在**：两轮对抗复盘证明——**看得见的功能靠测试，看不见的深水雷靠对抗复盘**（压缩静默失效、resume 毒化会话、孤儿进程、MCP 冻死主线……都是这么挖出来的）。
- **生产级要**：形式化不变式、property-based 测试、并发 fuzzing。
- **难在**：并发/异步 bug 的可复现性。这正是手册说"阶段3 起进入重状态区、有我这个会读代码的搭档最值钱"的地方。

## 附 · 实用中新发现的待办（v2 使用期陆续记，非上面十二条）

### A1. 交互 REPL：多行粘贴被拆成 N 条消息 → 烧 token / 炸配额　【✅ 已完成 2026-07-11】

> **完成状态**：三个方案全落地。方案2（`:paste` 显式多行）+ 顺带的请求突发软护栏（`_BurstGuard`：忘打 :paste 直接粘也会被拦下问一句）在 **P0** 就做了；**方案1（bracketed paste 自动识别）2026-07-11 补上**——支持的终端（Windows Terminal/VSCode/现代 xterm）粘贴块被 `ESC[200~…ESC[201~` 包起，repl 自动合成一条（连 :paste 都不用打），不支持的终端落突发护栏兜底。`agent._read_bracketed`/`_bracketed_paste_seq` + 7 单测 + 真机 E2E（piped bracketed 序列→repl 合成 1 条 user 消息、只打一次 Kimi）。下方为原始记录，保留备查。


- **现象**：往 `你 ›` 里粘贴一大段**多行文本**（例：一整套"文章写作规范"几十行），每一行（每个换行）被 `input()` 当成一次独立提交 → 一次粘贴变成几十条消息，每条都发一次 Kimi、还各自被模型扩写成一大篇，几十次往返直接**烧穿账号本计费周期用量额度**（`Kimi 返回错误：access_terminated_error / usage limit`）。不是崩溃——护栏、流式、"出错了但没崩"都正常，是**交互 + 成本缺口**。
- **根因**：`agent.py` 的 `repl()` 用 `user_text = input("你 › ")` **一行一句**读；没有"整段粘贴 = 一条消息"的处理。
- **要什么**：粘贴进来的多行文本作为**一条** user 消息进入**一轮**对话。
- **往哪走（挑终端能用的）**：
  1. **bracketed paste 模式**：开 `ESC[?2004h`，把 `ESC[200~ … ESC[201~` 之间的整块当一条。Windows Terminal 支持；老 conhost / 经典 PowerShell 窗口不一定认——需探测 + 兜底。
  2. **显式多行模式**（推荐先做）：加 `:paste` 命令，进入多行输入直到 `:end` 或连续空行才提交。跨终端最稳、零依赖、可离线测；代价是用户多打一步。
  3. **快速到达检测**：短时间涌入多行判为粘贴、缓冲成一条。`input()` 阻塞式难做，要 `msvcrt` 非阻塞读，Windows 专属且较脆。
- **建议**：先上方案 2（稳、可 TDD、跨平台），方案 1 作为"支持的终端上自动生效"的增强。
- **顺带**：可加一道"单轮/单位时间请求数或 token **软上限**"护栏——粘贴风暴 / 跑飞时**先问一句再继续**，防再次烧穿配额（与《五、上下文 / 成本工程》挂钩）。

### A2. 自我扩展：agent 自己"装工具"/"造工具"　【规划中·先不做·待拍板 2026-07-11】

- **想法**：从"我们喂它固定一套工具" → "它能自己扩充能力"。两条路：**① 从 GitHub/生态下现成工具（= 装 MCP server）**、**② 自己造工具（写代码变成新工具）**。
- **现状**：路①的 MCP 机制已在（`mcp_client`+`mcp.json`），缺"自己发现+安装+信任闸"；路②弱版今天靠 `run_command` 已能"写脚本跑一下"，缺"固化成持久工具+沙箱+审核"。
- **⚠ 核心风险**：这是全项目**最大的安全升级**——现有护栏都假设"工具是策划过的已知集合"，自装/自造工具动摇这个前提（能力面失控 + 供应链 + 自我改造）。**必须人始终在环 + 分阶段 + 自造工具走沙箱**。
- **详见完整方案稿**：`docs/superpowers/specs/2026-07-11-自我扩展能力方案-装工具与造工具.md`（含现状盘点、风险、三阶段路线、动代码前要钉的 5 个决策）。
- **下一步**：甲方定方向后先 brainstorming 钉需求+安全边界再动代码。**先不着急做。**

### A3. 跨会话项目记忆结构：大项目跨多次对话如何保持连贯　【规划中·先不做·待拍板 2026-07-11】

- **想法**：大项目要多次对话才做完，应有"共享的项目总记忆（A）+ 每次对话各自的工作区（B/C…），都能读 A"。
- **现状**：**小蛇已有这套的一半骨架**——`memory.json`（全局记忆，每次开会话注入=你的"A"）+ `.state/sessions/<id>.json`（每会话档案=你的"B/C"）+ `episodic.jsonl`（跨会话教训，半个版本）。
- **真正短板（不是文件夹怎么分）**：① 总记忆是"平铺事实"不是"结构化项目大脑"（目标/决策/现状/待解/已完成）② 缺"会话末提炼回写 + 剪枝"（只堆不炼会变噪音）③ 不"提示"（默默读默默写）。这三点才决定跨对话连不连贯。
- **参照**：正是 Claude Code 的 `.claude/.../memory/` 做法（MEMORY.md 当索引 + 每条一文件 + 会话末提炼剪枝）——用户已跑通，搬给小蛇即可。
- **详见完整方案稿**：`docs/superpowers/specs/2026-07-11-跨会话项目记忆结构方案.md`（含现状、短板、目标结构草案、动代码前要钉的 6 个决策）。
- **下一步**：甲方定方向后先 brainstorming 钉"大脑分区/提炼粒度/文件还是文件夹/提示 UX/并发跨机"再动代码。**先不着急做。**（比再加工具更影响长期连贯性。）

> 附记（2026-07-11）：以下 A4–A7 是拿"Claude Code 有、小蛇还没有的"量出来的能力缺口，先记着、先不做；真做时各自先 brainstorm/spec 再 TDD。**性价比排序：A4 + A5 最高（核心手艺、日常立刻顺滑、低风险），其次 A6（把自动化交给用户），A7 锦上添花往后放。**

### A4. 手术刀式改文件 Edit（找一段 → 换一段，带唯一性校验）　【规划中·先不做 2026-07-11】

- **缺口**：小蛇现在改文件**只有 `write_file` = 整个文件覆盖重写**。改大文件要把整份重发（费 token），且易手滑覆盖掉不该动的内容（不安全）。
- **要什么**：一个 `edit(path, old, new)` 类工具——精确定位一段旧文本、校验其在文件中**唯一**、替换成新文本（改不到就报错、不猜）。对应 Claude Code 的 Edit。
- **价值/风险**：省 token + 安全（不整文件覆盖）+ 改动可读。低风险、好 TDD。**第一梯队**。
- **注意**：仍走现有路径硬护栏（越界/敏感拒）；唯一性校验防误替；可留 write_file 作新建/整体替换用。

### A5. 专用快速搜索：glob 找文件 + grep 搜内容　【规划中·先不做 2026-07-11】

- **缺口**：要搜代码现在只能 `run_command` 跑 shell 的 grep/find——糙、慢、还得过命令闸门。
- **要什么**：`glob(pattern)` 按名/路径找文件 + `grep(pattern, ...)` 结构化搜内容（底层可用 ripgrep，缺则退 Python 扫）。对应 Claude Code 的 Glob/Grep。
- **价值**：做"上规模项目"（跨几十文件定位）几乎必需；只读、安全、结构化输出。低风险。**第一梯队**。

### A6. Hooks（生命周期自动化）+ 自定义 /命令　【规划中·先不做 2026-07-11】

- **缺口**：没有"每当 X 发生就自动跑 Y"的机制（工具调用前后/会话结束/开场），也没有用户自定义可复用命令（现仅内置 `:paste`/`:exit`）。
- **要什么**：① **Hooks**——harness 在特定时机强制执行用户配置的动作（不靠模型自觉；甲方问过的"自动同步文档"正属此类）。② **自定义 `/命令`**——把常用指令/工作流存成可复用命令。
- **价值/风险**：把确定性自动化交到用户手里。⚠ Hooks 会执行用户配的命令，须清晰的配置来源+边界（别变注入面）。**第二梯队**。

### A7. 更聪明的分工与安全网（命名子 agent / Plan 模式 / 文件级 undo / 持久放行清单）　【规划中·先不做 2026-07-11】

- **命名的专用子 agent**：审查员/规划员/探路员各有各的提示+工具集，vs 现在通用分身（与 A2 沾边）。
- **Plan 模式**：只读研究 → 出方案 → 用户批准 → 才动手，比直接干更稳（现有 ADaPT 是"卡住才拆"，非"先规划后执行"）。
- **文件级 undo/检查点**：现只有 `.state` 整体备份，缺"这步改错了撤回上一步"的文件级回滚。
- **持久放行清单**：配置里"这类命令/工具永远放行"，少一遍遍复问（现有会话级 `_approved_tools`/`--allow`，缺跨会话持久白名单）。
- **价值**：锦上添花，安全/质量/体验各补一角。**第三梯队，往后放。**

### A8. 视觉能力升级（三层合流：外部 SOTA + 内部审计 + 探针档）　【规划中·先不做·待拍板 2026-07-11】
