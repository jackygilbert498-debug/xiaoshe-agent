> 日期：2026-08-02

> 方案来源：V2《小蛇体验优化专项报告——编码壳范式版》P0 15 项，以及 2026-08-02 本机交接核验。

## 1. 目标

本轮按四道验收门完成以下目标：

1. 把交接报告、源材料、工具链和缺失的体验优化基线纳入轻量主仓库，同时让三套对标壳可按固定提交复现，避免把约 560 MB 的本地镜像直接塞入主仓库。
2. 修复 UI 契约夹具被 `.gitignore` 意外排除的问题，并让 Windows 测试入口、平台专项测试和文档口径可复现。
3. 在不改变契约 v1、安全语义、品牌几何和 token 持久化承诺的前提下，完成 V2 P0 的 15 个实施单元。
4. 建立可重复执行的行为验收和截图走查入口，让后续 P1/P2 不再依赖人工记忆验收。

## 2. 非目标与红线

本轮不做以下事项：

- 不创建“小蛇壳化转型完整方案”；该方案仍是交接后的独立研究交付物。
- 不实施 P1 的壳式状态行、改动聚合卡和任务型最近会话空态，也不实施任何 P2 契约升级。
- 不修改 allow / ask / deny、污点、`force_ask`、审批指纹、网络白名单、沙箱降级、信任标签或审计语义。
- 不改变 `sessionStorage` 中配对 token 的“关页即清”行为。
- 不改蛇瞳 S 的路径、方瞳、镜桥缝或空态版面重心；水印只允许校准透明度。
- 不新增前端运行时依赖、不引入构建步骤、不添加外链或内联脚本。
- 不把本地三套对标壳的嵌套 `.git`、生成物、依赖缓存或平台二进制提交到主仓库。

## 3. 总体实施结构

采用一个专用分支、四道验收门、逐批提交的结构：

1. Gate A：交接完整性与轻量复现。
2. Gate B：契约夹具与 Windows 可复现性。
3. Gate C：P0 行为实现，按四个可独立验收的子批次推进。
4. Gate D：全量回归、视觉走查、文档对账和远端同步。

每道门必须先通过本门的定向验证，再进入下一道门。行为变更严格遵循测试驱动：先写能够复现缺口的失败测试，确认失败原因正确，再写最小实现使其通过。

## 4. Gate A：轻量交接与对标壳复现

### 4.1 纳入主仓库的内容

主仓库跟踪以下内容：

- `docs/handoff/换机手册-v15-壳化转型工作包.md`。
- 专项包中的 V2 Word、Markdown、参考文献、两张自绘图、报告源材料、报告工具链和校验 JSON。
- 从 `C:\Users\example\Desktop\体验优化\体验优化` 补入的七份背景文档、三张当前界面截图、两张已采用设计图和竞品截图索引。
- 对标壳固定版本清单、恢复脚本和恢复说明。

缺失的体验材料统一进入专项包下的 `体验优化基线/`，保留原文件名，并增加一个索引说明各材料用途、来源和校验日期。

### 4.2 不纳入主仓库的内容

`对标壳源码/` 下的本地完整镜像保持在当前机器，但通过专项路径级 `.gitignore` 规则排除。规则只覆盖本专项的本地镜像，不扩大为全仓库同名目录规则。

专项 README 必须把“本地工作包已带完整镜像”和“Git 同步版通过固定提交恢复”分开描述，不能继续声称普通 clone 会自动得到三套源码。

### 4.3 固定版本清单

新增 `对标壳清单.json`，每项至少包含：

- `name`：目录名。
- `repository`：HTTPS 上游地址。
- `commit`：40 位固定提交。
- `purpose`：该壳用于回答的问题。
- `excluded_paths`：本地镜像中不属于复现必需品的生成物或缓存说明。

固定提交为：

- Kimi Code：`93f16c32d71d974f30c3ea3b1134691936ac5f53`。
- cc-haha：`6e6c87aa169ad45f8a1a745ad8dcdf51b8559ee1`。
- CodeWhale：`542719b14a9ddf84fd3b0b0a362d67475292d7d4`。

### 4.4 恢复脚本

新增纯标准库 Python 脚本 `报告工具链/restore_benchmarks.py`。接口为：

```text
python restore_benchmarks.py [--target PATH] [--dry-run]
```

数据流：

1. 读取并校验 `对标壳清单.json`。
2. 对目标目录逐项检查：不存在则 `git clone --no-checkout`；存在且为匹配上游的 Git 仓库则复用；存在但身份不匹配则拒绝覆盖。
3. `git fetch origin <commit>` 后以 detached HEAD 检出固定提交。
4. 读取 `git rev-parse HEAD`，必须与清单完全一致才报告成功。
5. 任一仓库失败时返回非零退出码，列出已成功、失败和未执行项目；不删除已下载内容。

`--dry-run` 只输出计划，不联网、不建目录。脚本不读取 `.env`，不打印凭据，不自动安装依赖。

## 5. Gate B：契约与 Windows 可复现性

### 5.1 UI 契约夹具

根因是 `.gitignore` 的通用 `state.json` 规则吞掉了 `tests/ui_contract/fixtures/state.json`。修复采用精确反向例外，让运行态 `state.json` 继续忽略，而契约夹具进入 Git。

夹具必须覆盖校验器要求的非空 `model` 字符串和布尔 `autonomy`，并与真实 `/api/state` 形状一致。新增回归测试必须证明干净 Git 树能枚举到该 fixture，且契约校验为零错误。

### 5.2 Windows UTF-8 入口

新增 Windows 验证脚本，显式设置 `PYTHONUTF8=1`，依次运行契约、smoke、E2E 和全量单测。README、`docs/LOCAL_VERIFY.md` 与换机手册使用同一条入口，避免每份文档维护不同命令。

生产 CLI 若仍会因不可编码的装饰字符在 GBK 终端崩溃，则先以失败测试复现，再将输出收口到现有安全打印边界；不以删除测试或吞异常解决。

### 5.3 平台专项测试

平台测试遵循“测试环境可注入，生产检查不放松”：

- macOS seatbelt 测试在注入假 runner 时不依赖 Windows 上不存在的 `/usr/bin/sandbox-exec`；未注入时仍执行真实二进制存在性检查。
- macOS 路径攻击用例不在 Windows 文件系统上预先创建含非法字符的路径；攻击字符串在被测边界直接注入。
- Docker bind 断言统一核对 Docker 接收的 POSIX 路径，不用宿主 `Path` 字符串作为期望值。
- curl 丢弃输出使用 `os.devnull`，不写死 `/dev/null`。
- 真正只能在特定平台证明的行为必须显式 skip 并写明原因；能通过依赖注入证明的逻辑不得滥用 skip。

成功标准是：Windows 全量测试除明确的平台跳过和既有预期失败外零失败、零错误；文档记录实际运行数，不复制历史数字。

## 6. Gate C：体验 P0

### 6.1 子批 C1：统一模态与键盘闭环

覆盖 O2+O45、O1、O3-F8/F12。

新增 `ui/js/modal.js`，只负责模态生命周期：

- `openModal(options)`：挂载内容、记录触发元素、给应用背景加 `inert`、设置正确角色与标签、把焦点移入模态。
- `closeModal(reason)`：卸载当前层、恢复下层或页面背景、将焦点归还对应触发元素。
- 支持 Esc、Tab/Shift+Tab 循环和堆叠焦点链。
- alertdialog 默认聚焦安全主按钮；普通 dialog 聚焦显式指定元素或首个可交互元素。

命令面板、观测台、灯箱和自主确认框接入统一生命周期。五处 `window.prompt/confirm` 迁为统一中文模态。恢复存档改用 `/api/sessions`，选项 button 化并支持方向键、Enter 和 Esc。侧栏命令入口改为 button；移到项目菜单补 Esc 和焦点归还。

### 6.2 子批 C2：错误、连接与真实回执

覆盖 O6、O7-F2、O12、O16、O18、O21-P0。

- 记忆面板和会话列表采用“加载中 / 数据 / 空 / 错误+重试”四态；失败不得停在永久骨架。
- 断线时输入框 placeholder 明确显示“连接已断开，正在重连…”；恢复连接后恢复正常文案。
- 中栏大标题从当前会话预览或首条用户任务生成，空会话仍显示“新会话”，切换会话同步更新。
- recall 不再点击后立即显示成功提示；只有收到真实 command 回执才显示结果，失败则显示可重试错误。
- attach 在没有真实上传入口时保持可见但禁用，并说明当前发送图片应走已有待发图路径；不得伪装成已支持的文件选择器。

### 6.3 子批 C3：第一体验、视觉下限与一致性

覆盖 O10、O31、O34、O44、O35-P0。

- 空态 chips 改为 button，点击只把任务文案填入输入框并聚焦，不自动发送，用户仍可编辑。
- 水印不改 SVG 几何，仅在亮暗主题分别微调透明度；验收同时看空态截图和正文可读性。
- 窄窗必须保留右侧状态/记忆/系统入口，采用可打开的面板入口而非直接永久隐藏；修复布局幽灵列。
- 输入框最大高度只保留一个事实源。JS 从 CSS 计算值或共享 CSS 自定义属性读取，不再分别写 `110px` 与 `120px`。
- 修正 GUIDE、界面和相关说明中的旧名称、错误命令或过时数字；文案测试验证用户可观察的入口和输出，不用只 grep 一句源码代替行为测试。

### 6.4 子批 C4：验收基础设施

新增 P0 Gherkin 验收清单和 Playwright 真浏览器脚本。脚本复用 `serve_demo` 与系统 Chrome，不进入产品运行时依赖，至少覆盖：

- 记忆/会话失败注入后的错误态与重试。
- chips 填入但不自动发送。

- recall 成功与失败回执。
- 1600px 与窄窗布局。

截图输出到显式临时目录或用户指定目录，不进入 Git；只有经过人工确认的基线图才能提交。

## 7. 错误处理原则

- 所有恢复脚本和验证脚本以非零退出码表示失败，并列出下一步，不输出“部分成功”式绿灯。
- UI 错误态必须区分未连接、请求失败和空数据；空数据不能冒充错误，错误不能冒充加载中。
- 重试按钮重复点击应复用同一加载状态，避免并发重复请求。
- 模态关闭必须幂等；重复 Esc、遮罩点击和按钮关闭不得破坏焦点栈。
- 平台能力缺失以明确 skip 或灰态呈现，不通过捕获所有异常获得假通过。

## 8. 测试与验证

测试层次从小到大：

1. 恢复脚本单测：临时本地 Git 仓库作为上游，覆盖首次恢复、重复恢复、错误远端、错误 commit、`--dry-run` 和部分失败。
2. 契约定向测试：fixture 可追踪、校验器零错误、真实 `/api/state` 形状一致。
3. 平台定向测试：macOS runner 注入、Docker 路径、curl sink 和 UTF-8 输出。
4. UI Playwright 行为测试：先观察每个 P0 缺口失败，再实现最小修复。
5. 现有 `scripts/smoke_serve.py`。
6. 现有 `scripts/e2e/run_e2e.py`。
7. `PYTHONUTF8=1` 的全量 `unittest discover`。
8. 亮暗主题、宽窄窗口截图走查和页面异常收集。

每个子批必须保留红→绿证据。完成声明只依据本轮新鲜命令输出，不沿用交接文档中的历史测试数字。

## 10. 最终完成标准

以下条件必须同时成立：

- 普通 clone 能取得完整报告、源材料、工具链、体验优化基线、固定版本清单和恢复入口。
- 主仓库不包含三套对标壳本地镜像、嵌套 Git 元数据或超过 GitHub 普通 Git 限制的平台二进制。
- `tests/ui_contract/fixtures/state.json` 已被 Git 跟踪，契约校验零错误。
- Windows 验证入口可重复运行；全量测试只保留有明确理由的平台跳过和预期失败。
- P0 15 项均有对应行为证据；统一模态、键盘、错误态、真实回执、窄窗和文案均通过自动化与截图走查。
- 安全契约、品牌几何、token 持久化和契约 v1 语义没有发生未授权变化。
- 工作树只剩明确记录的本地镜像等忽略项，提交历史按验收门可独立审查和回退。
