# 统一「裁剪-重问」子系统（视口 viewport）设计

日期：2026-07-19　状态：甲方已评审开工　架构：**视口注册表 + zoom/pick 工具**（甲方 2026-07-19 拍板）
修订：2026-07-22 **Mac 路径纳入**（甲方拍板）——原「Mac 独立排期」作废，Mac 适配见 §Mac 适配。

## 一句话

给小蛇一双会「凑近看」的眼睛：每张给模型看的图都是一个带 id 的**视口**，随身带「回屏幕」的坐标变换；
看不清就 `zoom` 钻进去放大重看，看准了就 `pick` 按编号点——模型永远不做坐标算术。

## 为什么要做（一手实证，2026-07-19 当天）

1. **整屏 OCR 漏孤立数字（今天 E2E 第一轮实锤）**：3120×2080 整屏截图上，计算器数字键「5」
   OCR 返回 400 词却不含它（稀疏按钮网格的孤立单字符是 WinRT OCR 已知弱项）；两字母词「CE」则稳定识别。
   → 裁剪放大后重 OCR 是治此病的标准疗法（RegionFocus，ScreenSpot-Pro +28%）。
2. **密集 UI ~40px 误差**：Kimi 直接报坐标在密集界面点偏（spec 已录）。
3. **坐标系是心脏**：此前 OCR-SoM 尝试失败的根因就是「裁剪后坐标没换算回屏幕」。本设计把变换收进注册表，一次做对。
4. spec 定论：RegionFocus / zoom / Chain-of-Ground / FOVEA(A9) / SoM 是**同一机制的不同侧面**，做成一个子系统。

## 核心不变式（整个设计压在这三条上）

- **不变式①（回屏变换）**：每个视口携带 `origin=(ox,oy)` 与 `scale`，满足
  `屏幕坐标 = origin + 图内坐标 / scale`。根视口（整屏物理分辨率截图）origin=(0,0)、scale=1。
- **不变式②（模型零算术）**：一切给模型的坐标输出都已换算成**屏幕物理坐标**；模型只说「zoom 3 号」「pick 5 号」，
  绝不自己加减乘除。（第一轮 OCR-SoM 失败教训的制度化。）
- **不变式③（base64 不进 history）**：标注图走既有 `vision.put_image` 管道给模型看，**不落工作区文件**
  （避免截图文件堆积 + 屏幕隐私外泄面；与 screenshot 工具「显式落盘」互补分工）。

## 组件

### 1. `harness/viewport.py`（新，纯 Python 无子进程）

- `Viewport`：`{id, origin, scale, size, marks, parent_id}`。`marks` = 编号→
  `{no, label, screen_cx, screen_cy, source}`（source ∈ uia/ocr，屏幕坐标**建视口时就换算好**）。
- 注册表：会话内存 dict（ctx 挂载），上限 N=8 LRU 淘汰；**不落盘**（截图内容隐私，会话结束即弃）。
- 纯函数：`to_screen(vp, x, y)`、`crop_viewport(vp, region) -> 子vp参数`——坐标变换全部 TDD 覆盖，这是心脏。

### 2. `harness/imaging.py` 扩展（纯标准库，跨平台）

- `crop(w,h,rgba,region)`：裁剪。
- `upscale(w,h,rgba,k)`：整数倍最近邻放大（k∈{2,3}，把 ~40px 目标抬到 ≥80px 供 OCR/Kimi 看清）。
- 复用已有 `draw_marks`（编号红框）。放大后总像素闸对齐 50M（与 PDF 路径 `_PDF_MAX_PIXELS` 同值同理由）。

### 3. 工具面（模型可见 3 个新工具）

| 工具 | 做什么 | 返回 |
|---|---|---|
| `look()` | 建**根视口**：整屏截屏（内存中、不落盘）→ UIA 元素框 + OCR 词框两路框源合并去重 → `draw_marks` 画编号 → 标注图进 vision 管道 | 视口 id + 编号表（label + 屏幕坐标 + 来源），图附下条消息 |
| `zoom(viewport_id, mark_no 或 region)` | 建**子视口**：按编号周边（或显式区域）裁剪 → 放大 → 对小图**重新** UIA/OCR 打框重编号 | 新视口 id + 新编号表 + 放大标注图 |
| `pick(viewport_id, mark_no)` | 点编号：查表取屏幕坐标 → 走 **click_at 同一执行路径**（同权限面：默认 ask、指纹绑坐标、动作后 observe diff 汇报） | click_at 的界面变化汇报 |

- 三工具授权面对齐 observe/click_at：`look`/`zoom` 读屏（ask，文案说明整屏隐私面）；`pick` 状态改变（ask + 绑坐标指纹，不跨会话持久）。
- 迭代收窄即「Chain-of-Ground」：look → zoom → (再 zoom) → pick，每步模型在环、可核可停。

### 4. 框源（grounding，SoM 轴起步）

- UIA：`observe.capture_ax` 已有元素 pos/size（物理坐标）。
- OCR：`ocr boxes` 词框（图内坐标 → 建视口时经不变式①换算）。
- 合并去重：中心距小于阈值（起步定 16 物理 px，P2 真机校准）的 UIA/OCR 框并为一个编号（UIA 名优先做 label）。
- 编号是**我们画上去的可信标记**；框内文字仍是不可信外部数据（沿用既有污点框架，OCR 文本照旧入污点）。

## 数据流（坐标变换示例）

整屏 3120×2080 截图 = 根视口 v1（origin=(0,0), scale=1）。
`zoom(v1, region=(620,1100,800,600))` + 2× 放大 → 子视口 v2：origin=(620,1100)、scale=2、图 1600×1200。
v2 里 OCR 认出「5」词框中心图内 (416,516) → 表里直接给屏幕坐标 (620+416/2, 1100+516/2)=(828,1358)。
模型 `pick(v2, 编号)` → click_at(828,1358)。——今天 UIA 独立测得「五」键中心恰为 (828,1358)，两路对得上。

## 错误处理

- OCR 引擎缺失/空结果 → 只用 UIA 框源，返回里如实说明；两路全空 → 引导换 observe / 直接 click_at。
- zoom region 越界 → clamp 到视口内；目标视口 id 不存在（LRU 淘汰）→ 明确报「视口已过期，重新 look」。
- 放大超像素闸 → 拒绝并建议缩小 region。截屏失败 → 错误态（不产幽灵视口）。

## 测试与验收

- **纯函数 TDD**（心脏）：to_screen/crop/upscale/合并去重/往返（screen→crop→zoom→to_screen 恒等）逐条测。
- 工具面注入 runner 离线测；红队照惯例（新增读屏面 + pick 执行面）。
- **真机金标准（今天失败案例做验收）**：整屏 look 找不到数字「5」→ `zoom` 数字键盘区后 OCR **必须**认出 5，
  `pick` 后计算器显示 5。第二金标准：CE 闭环在新子系统下同样跑通（回归）。
- 真 Kimi 无头 E2E：Kimi 全自驱 look→zoom→pick 完成上述金标准。

## 分期施工（每期 TDD + 真机 + 过红队再进下期）

1. **P1**：imaging crop/upscale + viewport 纯函数（零工具面，纯 TDD）。
2. **P2**：`look`（根视口 + 双框源 + SoM 编号图）。前置：Mac OCR 引擎补齐（见 §Mac 适配）。
3. **P3**：`zoom`（子视口 + 迭代收窄）。
4. **P4**：`pick`（前置：`click_xy` 补 mac 分支）+ 两个真机金标准 + 真 Kimi E2E。

## Mac 适配（2026-07-22 甲方拍板纳入）

原「Mac 路径独立排期」作废。Mac 上本机已验的能力件直接复用，缺口逐个补：

- **框源一 AX**：`observe.capture_ax` Mac 已有真机验证（元素 pos/size，**逻辑点**坐标）。
- **框源二 OCR**：新增 `_mac_ocr`——`/usr/bin/swift` + Vision 框架（`VNRecognizeTextRequest`，本机 CLT 已装、
  swift 6.3.1 实测在），输出对齐 Windows 的 `WORD|text|x|y|w|h` 行协议，词框坐标=图片像素坐标。
  编译时延若不可接受，可按脚本哈希把编译产物缓存进 `.state/`（`.gitignore` 已覆盖）。
- **点击**：`click_xy` 补 mac 分支——CGEvent 左键单击（osascript JXA `ObjC.import('CoreGraphics')`
  或等价 Swift），坐标系=**逻辑点**；走辅助功能 TCC（`platform_caps` 已有检测+引导）。
- **坐标系（Retina 关键）**：Mac 截图=物理像素（Retina 2×），AX/点击=逻辑点。
  不变式①的「屏幕坐标」定义为**执行层坐标系**（Mac=逻辑点，Win=物理像素——Win 侧 DPI 感知后两者本相等）。
  根视口 scale = 截图像素 ÷ 屏幕逻辑尺寸：Mac Retina=2、Win=1。scale 不必假设，
  可照 `_mark_screenshot` 已验的做法实测（截图 IHDR 像素 ÷ AX/region 逻辑尺寸）。
- **金标准 Mac 版**：Mac 计算器——整屏 look 漏「5」→ zoom 数字键盘区后 OCR 必须认出 → pick 后计算器显示 5；
  CE 闭环回归。Windows 金标准保留（回 Windows 机时验）。

## 明确不做（YAGNI）

- OmniParser/外部模型；工具内部自调 Kimi（甲方已否 C 案）；
- 视口持久化/跨会话（隐私 + 无需求）；任意角度旋转/自由倍率缩放（整数倍够用）。
