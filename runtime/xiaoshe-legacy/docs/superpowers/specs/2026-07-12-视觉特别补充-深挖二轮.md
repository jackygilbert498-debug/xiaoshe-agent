## 甲、先纠正 A8/A9 里的几处认知（研究修正/锁定的事实）

1. **Kimi k2.6/k2.7 原生支持视频输入**（[官方视觉指南](https://platform.kimi.com/docs/guide/use-kimi-vision-model)：k2.7-code/k2.6"can also understand video content"）。→ 短演示可直接传视频（≤FHD 1920×1080、请求 body ≤100M、mp4/mov/avi/webm 等），不必自己拼帧。之前搜索里的"experimental"说法在官方页**未获证实**，以官方"can understand"为准。
2. **Kimi 读图无图片数量限制**，唯一硬限 = 请求 body ≤100MB；分辨率建议 ≤4K（4096×2160），**4K 以上纯浪费**（只增处理时间不增理解）；token 动态计价、**官方无公开公式**但提供 [token 估算 API](https://platform.moonshot.cn/docs/api/estimate)（把 base64 图发过去先算后调）；只收 base64 或 `ms://` file id，**不支持外链 URL**。→ 可把 A8 软预算注记里的"图片 token"从猜变成先验数字。
3. **Kimi file-extract 服务限时免费**、格式极广（pdf/doc/docx/xls/xlsx/ppt/pptx/md/html/json/csv+代码；纯图 PDF 会 OCR），但**返回纯文本、无页码/版面锚点**（[files-upload](https://platform.kimi.com/docs/api/files-upload.md) / [files-content](https://platform.kimi.com/docs/api/files-content.md)）。→ **决定性影响 A8 的"PDF 双通道"**：渲染图 vs 文本无法按页硬对齐，只能①整本抽取后文本模糊匹配对齐、或②按 page_range 逐段拆小 PDF 上传天然获页对齐；且"限时免费"要预留"文本通道降级为纯本地 OCR"开关。
4. **Kimi 官方无图像生成端点、也无预告**（[定价](https://platform.kimi.com/docs/pricing/chat) + 视觉文档核实）→ 图像生成必须外接第二家 API；Kimi 读图恰好当"生成→看图评审→改提示重生成"闭环里的**评审官**。
5. **gpt-image-1 将于 2026-10-23 退役**（[OpenAI 定价](https://developers.openai.com/api/docs/pricing)）；**百度 iRAG 已从千帆下架**（现行价格页无此项、被 ERNIE-Image-Turbo 取代）→ A8 若排期里写了这两个须改/删。
6. **ScreenSpot-Pro 坐标系给"Kimi ~40px 误差"定位**（[arXiv:2504.07981](https://arxiv.org/html/2504.07981v1)，目标平均仅占屏 0.07%）：两年内闭源通用模型从 GPT-4o **0.8%** 跃到 Claude Opus 4.8 87.9%/GPT-5.2 86.3%（[llm-stats 聚合榜](https://llm-stats.com/benchmarks/screenspot-pro)，第三方未官方二核）→ "通用 VLM 定位密集 UI 必挂"已过时，但 Kimi 处于中间代际，**脚手架（SoM/裁剪）仍是必要补偿**、不是可有可无。
7. **手写识别本地零依赖路径不存在**：Windows.Media.Ocr 不认手写（[WindowsAppSDK #3514](https://github.com/microsoft/WindowsAppSDK/issues/3514) 官方承认）；InkAnalyzer 只吃笔迹 stroke 矢量、位图照片进不去；新 App SDK Text Recognition 要 NPU（Copilot+ PC）→ **手写笔记/白板照片干脆路由到 read_image（Kimi 视觉）**，别本地做。

## 乙、grounding 深挖（定位命脉，A8"感知/操作"的加深）

1. **UIA/OCR 框做 Set-of-Mark（SoM）**——**本轮 grounding 头号**（[SoM 原论文 arXiv:2310.11441](https://arxiv.org/abs/2310.11441)）：在截图上用**跨平台纯标准库 `imaging.py`** 画**编号框**（框来自 UIA bbox / OCR 词框，不需要分割模型；画框走 imaging.py 而非 Win-only System.Drawing 当唯一路径，否则 Mac 又一处分叉），让 Kimi 回"点几号"而非报坐标——**把 40px 连续坐标误差变成离散选择题**。双先例坐实在 Windows 桌面成立：[WebVoyager](https://arxiv.org/html/2401.13919v3)（DOM 框+数字标签，成功率 59.1% vs 纯 a11y 40.1%，**+19pt**）、[Windows Agent Arena](https://arxiv.org/html/2409.08264v2)（pywinauto 抽 UIA 树生成 SoM，微软自己就这么干）。这是 A8"OCR 词框 grounder"的上位版（OCR 词框只标有文本的，SoM 连图标/无文本控件也能标）。**grounding 收口一条轴（与 A8 一致）**：SoM 是"OCR 词框中心点击"的上位版——**别先建 OCR 词框 grounder 再返工**，直接 SoM 起步、OCR 词框只当 SoM 的框来源之一；SoM 与下面乙 2 的 Chain-of-Ground、丙 6 的 zoom/RegionFocus"裁剪-重问"应统一成**一个子系统**（共用同一份裁剪/画框代码），别拆成各做各的并行工具。
   - **反例硬约束**（[SeeAct arXiv:2401.01614](https://arxiv.org/html/2401.01614v1)，ICML'24）：密集网页上 image annotation 步骤成功率仅 13% vs textual choices 40.6%；错误剖析 53% 因标注**遮挡内容**、21% 视觉幻觉（目标没标就**编造标签号**）、18% 框标对不上。→ 三条纪律必须带：①**只标裁剪后 ≤10–20 个相关候选**（先 Kimi 语义粗选/RegionFocus 裁剪再标）②标签画在框外/角落别盖文本 ③明确告诉模型"目标无标记就回 NONE"（治 21% 幻觉）。**"最佳框数"无公开消融**（诚实），但密度+遮挡是元凶已证。
   - 机理背书（[GUI-Actor arXiv:2506.03143](https://arxiv.org/abs/2506.03143)，NeurIPS'25，coordinate-free 注意力头 ScreenSpot-Pro 44.6 超 UI-TARS-72B 38.1）：坐标数字生成与视觉 patch 粒度错配是 VLM 定位误差的**结构性根源**——正是"让模型选离散标记而非报坐标"的理论依据。GUI-Actor 自身要 GPU、无 API，不采纳，只借机理。
2. **Chain-of-Ground 迭代自纠**（[arXiv:2512.01979](https://arxiv.org/abs/2512.01979)，training-free）：Kimi 报一个点→小蛇把点画回截图（十字/圈）→回喂"你点的是这里，是目标吗？不是就修正"→逐步收敛。ScreenSpot-Pro **+4.8pt**、工业 UI +6.9pt。是 A8"RegionFocus 裁剪-重问"的**姊妹轴**——RegionFocus 是空间聚焦，CoG 是时间上的迭代自纠，可叠加。**收口提醒**：CoG（时间自纠）、RegionFocus/zoom（空间聚焦）应与乙 1 的 SoM 合成**同一个"裁剪-重问"子系统**，别拆成三套并行工具重复造裁剪/画框。画十字/圈走**跨平台 `imaging.py`**（非 Win-only System.Drawing）+ 多轮对话，零依赖。（同族 GUI-Cursor 用 RL 训练不采纳，只证"渲染当前位置作视觉反馈"有效。）
3. **测试时扩展 + judge 挑选**（[GTA1 arXiv:2507.05791](https://arxiv.org/abs/2507.05791)，GTA1-7B ScreenSpot-Pro 50.1）：模型本身要 GPU 不可用，但**零成本可抄其"测试时扩展"思想**——对同一定位问题让 Kimi 采样 2–3 个候选点，再用一次"哪个点真落在目标上？"自评（或 a11y 闸门）挑选。与 TVAE（先声明期望后核验）同族，补"多候选+judge"可并行变体。
4. **doubao-1.5-ui-tars 兜底 grounding**（[火山方舟文档](https://www.volcengine.com/docs/82379/1536429)；UI-TARS-1.5 ScreenSpot-Pro 61.6 vs OpenAI CUA 23.4，[repo](https://github.com/bytedance/ui-tars)）：**唯一验证到的中国友好托管专用 grounding API**——输入 3.5 元/百万 token、输出 12 元/百万、送 50 万 token、实名直连**免翻墙**。做"Kimi 定位失败→调 doubao-1.5-ui-tars 只做 grounding（截图+指令→坐标）"的兜底，比 A8 里的 Gemini Computer Use 兜底更便宜可达。**传输**：复用现有 kimi_client/web.py 的 **curl 子进程**传输（小蛇没走 urllib，OpenAI 兼容 body 照发即可）、火山 host 落地前先**真机验一次 curl 连通**。**第三方出网隐私门（重要）**：doubao 是**第二厂商出网**、要把截图（可能含后台窗口/隐私）发出去——这条兜底出网路径必须先过 **CAPED 遮蔽（裁到活动窗口 + 密码框涂黑）+ 厂商告知门**，不能只对 Kimi 讲隐私、对第二家裸发（详见庚 23、辛）。
5. **坐标脚手架的对照结论**（[SCAFFOLD arXiv:2402.12058](https://arxiv.org/abs/2402.12058) 点阵优于网格线，因网格切碎连续视觉；反证 [Building Browser Agents arXiv:2511.19477](https://arxiv.org/html/2511.19477v1) 实测**放弃 grid-cell 映射**、转 a11y 为主）：→ 给 A9 的 VISER（叠水平线）**降温**——"帮 VLM 读坐标"的修饰里点阵>网格线，但两者都**不如离散标记 SoM**（让模型选编号 > 让模型读刻度）。VISER 若真验也应与点阵对比、预期上限有限。

## 丙、官方感知设计纪律（A8/A9 完全没有，纯工程零成本，最该先抄）

6. **抄全 Claude computer use 的 zoom 工具包 + 感知纪律**（[官方文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)，全部原文核实）——**本轮性价比之王之一**，全是零依赖工程纪律：
   - **zoom 动作**：按 `region:[x1,y1,x2,y2]` **全分辨率回看**某区域（治 sidebar 文件名/tab 标题/状态栏小字看不清）——是 A8 RegionFocus 的官方背书。**收口**：zoom = 乙 1 SoM + 乙 2 CoG 那个统一"裁剪-重问"子系统的空间聚焦入口，共用同一套裁剪/画框代码（`imaging.py`），别另起炉灶。
   - **缩放公式自己掌握 scale**：发送前自己缩到 `scale=min(1, 1568/长边, sqrt(1150000/总像素))`（Opus 4.8 放宽到 2576px 长边），**别依赖服务端降采样**否则拿不到 scale、坐标映射就断；点击时除以 scale 映射回真屏。"**点击恒定单向偏移 = display 尺寸与图不符**"（诊断表原文）——macOS Retina DPR=2 与小蛇已修的 DPI bug 同源，印证方向对。
   - **截图历史保最近 3 张、每 ~25 轮批量修剪**（而非每轮删一张——每轮删会打碎 prompt cache 前缀）；每张截图约 1000–1800 token。
   - **指令文本放在图片之前**（"improves click accuracy"）——小蛇可直接检查消息组装顺序。
   - 其它：下拉/滚动条难点用键盘替代；分辨率基线 1280×720 别超 1920×1080；每步后截图自评。
7. **OpenAI CUA 甜点分辨率 1440×900**（[OpenAI computer use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use)：截图建议原始分辨率、必须降采样时 1440×900/1600×900 实测好、降采样后自己重映射坐标）→ 与条 6 重合，**1440×900 可作小蛇截图压缩目标参考值**（既省钱又贴 CUA 甜点、又落在 Kimi ≤4K 建议内）。

## 丁、录屏 / 演示学习 / 世界模型（把 A9 的三个"想象跳跃"从想象变论文路线）

8. **想象跳跃②"视觉世界模型" → WebDreamer 是 training-free 正解**（[arXiv:2411.06559](https://arxiv.org/abs/2411.06559) TMLR'25 + [代码](https://github.com/OSU-NLP-Group/WebDreamer)）：动手前让 LLM **用自然语言而非像素**预测"点这个按钮会出现什么屏幕"，再选最优动作。GPT-4o 版无需训练：VisualWebArena **+34.1%**、Online-Mind2Web +42.3%、Mind2Web-live +23.8%，比沙盒树搜索快 4–5 倍。**核心落地洞察**：预测"语义状态/变化差异"而非完整像素——和小蛇 observe 元素树天然对齐；**预测≠实际就是"没看懂，该停/重规划"**（正是甲方设想的用法）。印证工作 [WMA arXiv:2410.13232](https://arxiv.org/abs/2410.13232)（ICLR'25）先证实"当前 LLM 本身没有世界模型"、再提出**只预测"这次动作改变了什么"的自由文本 diff**（不预测完整下一屏，因网页重复元素多）——两篇同指"预测差异而非整屏"才可行。桌面侧 [WorldGUI arXiv:2502.08047](https://arxiv.org/abs/2502.08047)（三 critique 阶段"预演-核验-修正"比 Claude CU +12.4%，且必测"非默认初始态"）**与 A8 的 TVAE 动作核验几乎同构**，给它论文级背书。纯提示词+observe diff，复用小蛇 click 后已有的"自动汇报界面变化"正好接。
9. **想象跳跃①"看一遍就学会" → PC Tracker 式"事件触发抓拍"是最短路径**（[PC Agent arXiv:2412.17589](https://arxiv.org/abs/2412.17589) + [GitHub](https://github.com/GAIR-NLP/PC-Agent) MIT，**Windows 原生**）：**放弃"从视频逆向猜动作"，改为录制时就记下动作**——`GetAsyncKeyState(VK_LBUTTON)`+`GetCursorPos` 每 30–50ms 轮询检测按下沿→点击瞬间加拍一张+记 UIA 元素（纯 Win32、Add-Type 内联 C#、无 DLL 注入），得到天然对齐的"事件+截图对"，再让 Kimi 跑**认知补全**把裸事件变带意图的步骤（"点(x,y)"→"点'保存'按钮以…"）。信息量远高于盲拍视频，且与 A9 的 wait_until_settled 帧差、click 自动汇报**共享截图/差分代码**。
   - 管线可拆抄的先例：[TongUI arXiv:2504.12679](https://arxiv.org/abs/2504.12679)（教程视频→GUI 轨迹三步：MOG2 关键帧→音频时间戳对齐→零样本模型标动作，每步都能降级成小蛇零依赖版：帧差分/用户口述/Kimi+observe）；[Watch&Learn arXiv:2510.04673](https://arxiv.org/abs/2510.04673)（**逆动力学**：给连续两帧问"中间做了什么动作"，training-free in-context 有效，是"视频→步骤"最简配方）；[OpenAdapt](https://github.com/OpenAdaptAI/OpenAdapt)（活跃 MIT 项目，抄其"演示作为提示词上下文而非硬编码脚本回放"哲学、容忍界面漂移）；[推理时视频学习 arXiv:2511.04137](https://arxiv.org/pdf/2511.04137)（证明结构化视频轨迹 > 纯文字教程；可执行时动态贴演示片段进上下文，比"抽象成固定步骤"更抗漂移）。
10. **多图当视频必须叠时间戳**（[NVIDIA VLM 提示指南](https://developer.nvidia.com/blog/vision-language-model-prompt-engineering-guide-for-image-and-video-understanding/) + [CogVLM2-Video](https://cogvlm2-video.github.io/) + [ViKey](https://arxiv.org/html/2603.23186v1)）：长演示抽关键帧当多图传时，**每帧角上叠印"帧3 / t=4.2s / 此刻点了保存"**（时间戳叠印走**跨平台 `imaging.py`**、非 Win-only System.Drawing）、提示词里复述帧号——多份工作实证单帧丢时序、多帧+显式时间戳才提升时序推理。是"抽帧当多图"落地的关键技巧。**多帧硬约束**：视觉活动帧有 `VISION_LIVE_MAX=2` 上限，抽多帧当多图/传视频会被**静默截断**只剩 2 帧——需要时临时上调该上限，并同时校 Kimi 的总像素/请求体上限（甲 2：body ≤100MB、建议 ≤4K），别悄悄丢帧还以为都发出去了。
11. **零依赖录屏三条路的诚实判定**（[PowerShell 全局钩子](https://hinchley.net/articles/creating-a-key-logger-via-a-global-system-hook-using-powershell) / [ffmpeg gdigrab](https://ffmpeg.org/ffmpeg-devices.html)）：①**笨路（GetAsyncKeyState 轮询 + 事件触发抓拍）= 推荐**，纯 Win32 零依赖、等于自建 PC Tracker；低级钩子 WH_MOUSE_LL 要跑消息循环阻塞主线程、不首选。②**WinRT Graphics.Capture 从 PS 5.1 调 = 不推荐**（异步投影坑 + Direct3D 拉帧繁琐、无干净先例，搜到的"PS 方案"底层其实是 ffmpeg）。③**ffmpeg gdigrab = 可选依赖**（真要连续视频才用，抓不到硬件加速窗口/高 DPI 有坑，不进核心）。
12. **想象跳跃③"自己吃狗粮" → 两个成熟范式 + 一份实证配方**：录制即测试有 [Meticulous.ai](https://www.meticulous.ai/)（web：录会话+网络流量，重放时 **mock 所有后端**求确定化，base/head 各跑截图对比拦回归）和 [WinAppDriver UI Recorder](https://github.com/microsoft/WinAppDriver/wiki/WinAppDriver-UI-Recorder)（桌面：录操作→实时生成 **UIA 定位** XPath+重放代码，微软开源，正是小蛇 observe/click 已有能力）。落地配方看 [WebGen-Agent arXiv:2509.22644](https://arxiv.org/html/2509.22644v1)：生成网站后**先外观自评（判分准 93–96%）过关才触发 GUI 功能走查（89–93%）**、修复循环带**连错 5 次回溯 + 收尾选历史最优步**；效果 Claude-3.5 26.4%→51.9%；**裸生成不自测最好也只 27.8%（一半以上功能是坏的）**、评审 VLM 有 4–11% 噪声不能无上限迭代。验收用例要**原子化**（一操作一预期状态可判 pass/fail，见 WebGen-Bench 647 条）。

## 戊、视觉回归 / 交付验收工程（A8 自纠环的工程底座）

13. **纯标准库 PNG 解码器 ~120 行**（[逐行教程](https://pyokagan.name/blog/2019-10-14-png/)）：小蛇没 PIL，但 `zlib`（解压 IDAT）+`struct`（拆 chunk）+5 种 filter unfilter 手写解码器约 80–90 行（补 RGB type 2 共 ~120 行），编码 PNG（写 diff 图）更简单（filter 全 0+zlib）。性能诚实账**（须按真实分辨率重估）**：1280×800（≈1.0Mpx）纯 Python 一遍 1–3 秒——但小蛇真实截图约 **3.4Mpx**（比 1280×800 大 3 倍多），全图纯 Python 解码会**成倍慢**，"~120 行/1–3 秒"这句是按 1280×800 算的、不能照搬到真实截图；对策要么按真实分辨率重估这笔时间账、要么**先降采样再解码**（dHash/diff 本就缩到小图，不需要全分辨率逐像素解码）。→ 作**跨平台纯标准库 `imaging.py`** 内核：解码→降采样→哈希/diff→编码回 PNG，且 dHash/diff/SoM 画框/时间戳叠印全复用它这一份跨平台代码（不再 Win-only System.Drawing 分叉）。**全新（小蛇现无任何像素级能力）**。
14. **dHash 基线回归**（[HackerFactor dHash](https://hackerfactor.com/blog/?%2Farchives%2F529-Kind-of-Like-That.html)）：缩到 9×8 灰度→相邻像素差分→64bit 指纹，汉明距离≤10 判相似；比 aHash 误报少、接近 pHash 而无需 DCT（在条 13 之上 +~20 行）。→ render_check 存基线 dHash（64bit=16 字符 hex，**基线"图"退化成一行文本、git 友好**），重渲染后汉明距离>阈值才触发像素 diff+Kimi 复审，省 API 钱。**SSIM 跳过**（无纯标准库先例、[Hitchhiker's Guide](https://arxiv.org/pdf/2101.06354) 证不同实现给的值差异大到影响结论，手搓无意义）；PowerShell System.Drawing 路（[PerceptHash](https://github.com/joshooaj/PerceptHash)）仅 Windows 且每次起子进程慢，只当"全尺寸像素 diff 太慢"的 Windows 备胎，**主走纯 Python 一份代码跨平台**。
15. **一段注入 JS 布局审计 = 性价比之王**（零依赖零幻觉、当天可落地，[零溢出实战](https://dev.to/ohugonnot/zero-overflow-in-10-minutes-responsive-testing-with-claude-code-and-playwright-59an)）：render_check 里一次 `evaluate` 跑完确定性布局检查——**溢出** `el.scrollWidth>el.clientWidth`（附实战 5 种 CSS 修法，inline 元素测不准要 inline-block）、**裂图** `img.complete&&naturalWidth===0`、**点击目标过小**（[Lighthouse](https://developer.chrome.com/docs/lighthouse/seo/tap-targets) 48×48 永不挂 / WCAG 2.2 AA 底线 24×24 / AAA 44×44）、**文字截断**（诚实：`text-overflow:ellipsis` 有分数像素取整假阴性、[Firefox bug 确认](https://bugzilla.mozilla.org/show_bug.cgi?id=1716572)，只查到大多数别承诺全查）。输出结构化 JSON 进 Kimi = 比截图自评便宜且零幻觉的**第一道门**。与 A8 的 DesignChecker（对齐/对比度）不重叠、互补。
16. **VLM diff 必须"先算术定位、再裁剪问询"——硬架构规定**（[DiffSpot arXiv:2605.29615](https://arxiv.org/html/2605.29615v1)，4400 图对实证）：裸喂两图问 Kimi"哪变了"**最好模型也只找出 40.7% 真实变化**、行高中位 Recall 仅 4%、圆角 13%、无差异对照上幻觉率高达 24.2%（没变硬说变）。→ **裸 VLM diff 不能当回归门禁**；正确姿势 = 确定性像素 diff 先判"变没变+包围盒定位"→把两图对应裁剪区放大喂 Kimi 问"这是什么变化、可接受吗"——**定位交给算术、语义交给 VLM**，与 A8 RegionFocus 天然互补。
17. **视觉回归成熟套路该抄的清单**（[Playwright toHaveScreenshot](https://playwright.dev/docs/test-snapshots) + [BackstopJS](https://github.com/garris/BackstopJS) + [Chromatic](https://www.chromatic.com/docs/threshold/)）：①**截图前先等稳定**（无网络/无动画，`animations:disabled`）——治 render_check 截到动画中间帧；②**双层阈值**（单像素 YIQ 感知距离 threshold≈0.2 + 总量 maxDiffPixelRatio≈1%）——**天然吸收抗锯齿噪声**，不必实现 AA 检测算法；③动态区 **mask/hide**（两档：visibility:hidden 保布局 vs display:none 整拿掉）；④基线**按平台分文件** + **显式 approve 动作**晋升新基线（防基线腐烂，小蛇问用户"这次变化是故意的吗"）；⑤失败落 **expected/actual/diff 三联横图**喂 Kimi/存证据。
18. **多视口矩阵 + 深浅色**（[BrowserStack 断点](https://www.browserstack.com/guide/responsive-design-breakpoints)）：最小集 375/768/1024/1440 四档、讲究版 8 档；每档核心断言只一条"内容不越屏+关键内容可见"；深色态对比度 4.5:1 在深底重新失效是最常见虫。→ render_check 单视口升 3 视口×2 色；**性价比诚实账**：resize+截图边际成本秒级，但全喂 Kimi 烧配额 → **确定性 JS 审计（条 15）6 档全跑、Kimi 只看 375/1440 极端档+深色 1 张**。与 A8 DesignChecker 衔接（深色态也跑一遍对比度）。

## 己、文档 / 图表 / 结构第三通道（A8"文档理解"的加深）

19. **长文档四件套 + mtime 缓存 = 把"几百页 PDF"从不可用变可用**（生产蓝图 [5 PDF Patterns](https://blog.jztan.com/ai-agent-pdf-reading-patterns/) + 两篇顶会 [PDFTriage EMNLP'24](https://arxiv.org/abs/2309.08872) / [DocAgent EMNLP'25](https://aclanthology.org/2025.emnlp-main.893/)）：`pdf_info`（页数/元数据）→`pdf_get_toc`（目录树）→`pdf_search`（keyword，FTS5）→`pdf_read_pages`（只读命中范围），+`pdf_read_all` 兜底，按"文件路径+mtime"缓存慢速抽取。三条黄金经验：①agent **自发按文档大小分支**（小全读、大搜索先行）——所以把"侦察"做成最便宜的工具；②阅读顺序修复（多栏）保真度 0.564→0.816；③**98.6% 内容不进上下文**。PDFTriage 的分诊思想：返回带类型的 frame（section/table/figure）而非"第 N 页文本"，因"把 PDF 摊成纯文本不符用户心智"。渲染靠 A8 已有 WinRT Windows.Data.Pdf、索引靠标准库 sqlite3（**FTS5 须运行时探测** `pragma compile_options`、官方 Windows 包带、没有就退逐页子串扫）、semantic 模式砍掉（要嵌入）。与 A11 里的 ReadAgent gist 不重复（那是记忆压缩、这是结构+检索）。
20. **Office COM / AppleScript 结构化直读 = "读文档不走视觉"第三通道**（[SS64 Word COM](https://ss64.com/ps/syntax-word.html) + [微软 Scripting Blog](https://devblogs.microsoft.com/scripting/how-can-i-extract-word-paragraphs-that-use-a-specific-style/) + [PPT HasTextFrame](https://learn.microsoft.com/en-us/office/vba/api/PowerPoint.Shape.HasTextFrame)）：`New-Object -ComObject Word/Excel/PowerPoint.Application` 直接拿文档对象树——Word 段落+样式（Heading 天然目录树）、Excel `.Value2`+**`.Formula`（公式本身，OCR 只看得到结果）**、PPT `HasTextFrame→HasText→TextRange.Text`+**演讲者备注**（视觉根本不可见）。**比 OCR/截图强在三点：无损、带结构、零 token**。安全护栏必加：`ReadOnly`+`Visible=$false`+**`AutomationSecurity=msoAutomationSecurityForceDisable` 防宏文档执行宏**+try/finally Quit 防僵尸进程；前提探测本机装了 Office（失败即降级）。**施工期安全硬化（COM/PowerShell 脚本必带）**：拼进 PS 的文档路径/变量走 **base64/参数化**（复用 press_keys/ocr 已验的防注入模式，杜绝文件名带引号/同形字逃逸成任意 PS 执行）+ 显式禁 **DDE / 远程模板 / 外链自动更新**（关自动链接更新，别让打开文档触发对外请求）+ **打开不可信文档走人在环**（先告知用户来源、确认后再放行）。**无 Office 兜底**：docx/xlsx/pptx 本体是 OOXML zip（ECMA-376），纯标准库 `zipfile`+`xml.etree` 解 `word/document.xml` 拿全文和样式、**跨平台**。Mac 侧对称 [iWork AppleScript](https://iworkautomation.com/)（Keynote/Numbers/Pages 三应用通用词典、能读备注、还能当 docx/xlsx/pptx 阅读器；iWork 原生格式 IWA/protobuf 纯 stdlib 解析不现实、AppleScript 是唯一零依赖路，**未真机验、归 Mac 待验清单**）。**全新——A8/A9 都没有的第三通道**。
21. **表格抽取：轻预处理 + 两遍式提示词**（[NGTR arXiv:2412.20662](https://arxiv.org/html/2412.20662v2) + [ACL'25 xLLM 对比](https://aclanthology.org/2025.xllm-1.2/)）：图像质量是第一瓶颈（GPT-4o TEDS 高质 91 vs 野生 44.68）；NGTR 预处理 PubTabNet **+10.57 TEDS**（主要来自**裁剪+上采样**）。两处实证短板：**VLM 认列强、认行弱**（列有表头语义锚）、**结构定位弱、认字强**。→ 落地简化版：①裁表格区（A8"逐块高清裁剪"已有）②低清/小字先上采样 2×③**先报"几行几列+表头"骨架、再逐行填内容**（把行定位变成顺序问题）、输出 HTML `<table>` 且要求自查列数一致。全 System.Drawing+提示词，零依赖，与 A8 MinerU 粗到细共用裁剪逻辑。
22. **扫描件预处理只做三件低风险的**（[PowerToys Text Extractor 官方](https://learn.microsoft.com/en-us/windows/powertoys/text-extractor)：同 WinRT 引擎、官方建议"放大后再识"；[arXiv:2008.02777](https://arxiv.org/pdf/2008.02777) 发现现代 LSTM 引擎在灰度上反而好于二值化）：①小图/小字 **2× 上采样**（HighQualityBicubic，微软自己背书）②低对比 **灰度+对比度拉伸**（ColorMatrix，无像素循环）③**二值化做成可选参数默认关**（证据分歧）。去倾斜工作量大收益不确定，**先在真扫描件量 WinRT OCR 裸跑词置信度、证明有洞再补**（符合"改真执行路径必真机复验"纪律）。`MaxImageDimension` 是运行时属性、上采样别越界。共用条 21 的 System.Drawing 工具函数（一次实现两处受益）。

## 视觉特别补充·推进排序（拍板建议，全部零/近零依赖优先）

**🟢 第一梯队（零依赖、纯工程/提示词、直击已知痛点，最该先做）**
1. **抄全 Claude zoom 感知纪律**（丙 6+7）——zoom 回看 + scale 自掌握 + 截图历史保 3 张批量修剪 + 指令在图前 + 1440×900 甜点分辨率。纯工程零成本、官方背书、同时利好定位准确率与省钱缓存。
2. **UIA/OCR 框做 Set-of-Mark**（乙 1）——直击 Kimi 40px 痛点，+19pt 双先例；带 SeeAct 三纪律（裁剪后≤20 框/不遮内容/允许 NONE）。
