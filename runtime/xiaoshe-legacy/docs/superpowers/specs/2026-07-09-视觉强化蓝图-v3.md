## 0. 心智模型（承 v1/v2）

**给小蛇装上「看 → 想 → 指 → 做 → 验」的完整视觉回路，且每一环都能重复成功、失败自知、危险自停。** 延续「循环属于模型，机制属于我们」。商用级的分水岭不是"一次点得准"，是**可复现的失败可控性**。

v3 的新认知：这条回路在**两台机上不对称**——Windows 侧 a11y/截屏零授权即用、快（几十 ms）；macOS 侧同样的能力**默认被系统权限门锁死**、且慢一个数量级。**"a11y-first"在两台机上是同一个方向、却是两套落地工程**——这是 v1（假设平台中立）和 v2（只验了 Windows）都没说清、而小蛇作为双机项目必须先认清的第一件事。

## 1. 双机 + 端点 一手总账（v3 的硬核心，也是它压过 v1/v2 的地方）

**三块一手数据，前两版没有任何一版三块齐全**：v1 只有 4 发浏览器/合成探针；v2 只有 Windows 一台机。v3 = Windows（承 v2，已核）+ macOS（本轮真机）+ Kimi 端点（本轮真机）。

### 1A. Kimi 端点真相（本轮实测，`api.kimi.com/coding/v1` / `kimi-for-coding` / 当前 key）
| 探针 | 真实结果 | 含义 |
|---|---|---|
| 图像 token 公式 | 448²=275、1280×800=1353、1920×1080=2710；**减去文字项后图像部分 `⌈W/28⌉×⌈H/28⌉` 严丝合缝** | **v2 的 patch 公式在真实端点成立**（代际疑虑就此消除：不管底座哪代，用 28px patch） |
| **超大图上限** | **4096×2160 → prompt_tokens=4202**（v2 公式会预测 11470） | **端点服务端强制降采样**：超大图被砍到 ~4200 token 封顶 |
| 反推有效天花板 | 4202 token ≈ **3.2M 像素（≈1792×1792）** | **恰好是 v2 嘲笑 v1"错扣"的那个 3.2M 数——真机证明它是端点真实上限，见 §2** |
| 单次约束 | 强制 `temperature=1`；1280×800 图单次推理 60–180s，超大图易超时 | 单次不确定→pass^k 补偿；**大图既慢又白费（降采样），必须发送前压到 ~1600–1800px 长边** |
| grounding | 单目标偏差 10px；**密集 18 目标误差 ~40px、脱靶** | 别赌坐标（与 v1/v2 同向，此处 v1 首测、v3 再确认） |

### 1B. Windows 零依赖回路（承 v2 探针，已核为真代码真数据）
UIA 树 521 元素 66–70ms + **InvokePattern 可编程点击（零坐标）**；`System.Drawing` 截屏 72ms；WinRT `Windows.Media.Ocr` 79ms 中文准、词级坐标；Edge `--headless=new` 渲染热跑 1.1s；`Windows.Data.Pdf` PDF→PNG。**DPI 深水雷**：不先 `SetProcessDPIAware()`，截屏(逻辑像素)与 UIA(物理像素)差 2 倍、全脱靶。→ Windows 侧 a11y/截屏**零授权即用、毫秒级**。

### 1C. macOS 零依赖回路（本轮真机，macOS 26.3 arm64 —— 填 v2 唯一结构性空洞）
| 能力 | 真机结果 | v2 §8 的假设 vs 真相 |
|---|---|---|
| a11y 树 | 进程数可读但 **3796ms**；元素树 **被拦 `-1719 不允许辅助访问`** | v2 假设"与 UIA 对称"；**真相：被辅助功能 TCC 权限门锁死、且慢 ~50×** |
| 截屏 | **`could not create image from display`（被屏幕录制权限门挡）** | v2 假设"screencapture 就行"；**真相：默认无权限即失败** |
| OCR | swift + shortcuts 均在 | Vision 可用，但**无预装 CLI，须编译小助手/走 shortcuts**，不如 Win 一行可调 |
| 渲染自验 | Chrome `--headless=new` 跑通，冷启 8.6s | ✅ 可行（此腿跨平台成立），但冷启慢 |
| PDF→PNG | **✅ 真机验：`sips` 69ms（612×792）、`qlmanage -t` 128ms（791×1024）；`cupsfilter` 还能零依赖造 PDF** | 补实——**且 v2 说的"sips 别用于 PDF、Ventura 起坏"在本机(26.3)不成立**（第三处数据反杀） |

> **纪律背书**：这一整节是"只信工具真实返回"的产物。三块里最贵的两块（Kimi 3.2M 上限、macOS 双权限门）都是**前两版凭文档/单平台推不出、只有真机能戳穿**的。

## 2. 三方终审：用新数据判 v1↔v2 的分歧（这一节直接定 v3 的价值）

| 争议点 | v1 说 | v2 说 | **v3 真机终审** |
|---|---|---|---|
| **图像成本单位** | 按 token 压小图省钱 | 端点按**请求次数**计费、token 无所谓，该"一图多问" | **v2 对**：coding 端点是请求配额制，v1 的 token 框架用错了驱动。但→ |
| **图像分辨率上限** | ~1792²/3.2M 像素（我标了"2506 版"但用作压图目标，且 §4 又写≤4K，自相矛盾） | v1 错扣开源小模型限制；API 支持 4096×2160/8.8M | **v1 的数字反而对**：真机 4096×2160 被砍到 4202 token≈**3.2M 像素封顶**。v2 的"8.8M 可用/成本 11470"**两头都错**——拿不到 4K 细节、也不花 11470。**净：该压到 ~1600–1800px，不是因为省 token，是因为超了也白费（服务端扔掉）** |
| **token 公式** | 无 | `⌈W/28⌉×⌈H/28⌉+4`，疑核错代际 | **v2 公式成立**（真机三尺寸吻合），代际疑虑消除——patch 项精确，常数项随文字浮动 |
| **桌面 a11y 定性** | 引 macOS"36% 应用半残"，称"地基裂缝" | Windows 是"金矿"、macOS 才需兜底 | **都只对一半**：Windows 确是金矿（零授权毫秒级）；macOS 真相比 v1 的"半残"更硬——**默认被 TCC 权限门整个锁死**，是"授权门"问题不是"覆盖率"问题 |
| **macOS 可行性** | 一句带过 | §8 列对称路、诚实标未验 | **v3 补实**：工具存在但 a11y+截屏**双双默认无权限**、osascript 慢 50×、Chrome 渲染可用——macOS 落地**必须先做一步权限引导**，否则静默失败 |

**一句话终审**：**v2 整体比 v1 更可施工**（Windows 深、成本模型有骨架、纠了 v1 的成本框架错），但 **v2 在它最得意的两处各踩一脚**——分辨率上限把 v1 冤枉了、macOS 把难度想简单了。**v3 = v2 的施工强度 + v1 被平反的分辨率真相 + 两版都缺的 macOS 权限门真相。**

## 3. 方向确认：a11y-first（承 v2 的产品级背书 + v3 的双机限定）

a11y-first 已是全行业投票结果（v2 已举证，v3 承接）：**微软 Playwright MCP**（"not pixel-based input, no vision models needed"，坐标锁在 `--caps vision`）、**谷歌 Chrome DevTools MCP**（返回带 uid 的 a11y 快照，坐标锁在 `--experimentalVision`）、**微软 UFO2**（UIA 优先 + 视觉补自绘 + IoU>10% 去重）。**grounding 榜 2026-07**：ScreenSpot-Pro 天花板 ~81%（专用小模型），通用旗舰裸打坐标仍差（GPT-4o 0.8% / Claude CU 17.1%）；**zoom 放大重试已成榜首标配**（高基线上仍 +6~9）。本地 grounder 若需：Holo3.1（Apache 2.0，支持 Apple Silicon）。

**v3 的限定**：a11y-first 在两台机上**方向同、工程异**——
- **Windows**：零授权、毫秒级，直接是最强路线（承 v2）。
- **macOS**：同样方向，但**先过辅助功能权限门**、且慢，需配"授权引导 + 慢就缓存/少调"的工程（v3 §8）。

## 4. Kimi 一手成本与能力模型（v2 骨架 + v3 真机修正）

- **图像 token**：`⌈W/28⌉×⌈H/28⌉`（patch 项，真机精确）+ 文字/结构常数。小蛇纯标准库一行算。
- **服务端降采样硬顶（v3 新增，最关键）**：单图 token 封顶 ≈ **4200（≈3.2M 像素 / ~1792² 等效）**。**发送前长边压到 ~1600–1800px**——再大既慢又被端点扔掉，纯亏。
- **计费单位 = 请求次数**（承 v2）：Kimi Code 端点按 5h 窗口的请求数配额，非 token。→ 设计取向 **"一图多问 > 多拍小图"**（v2 的正确翻转，v3 保留）。
- **prompt caching**：带 `prompt_cache_key`（=session id），稳定前缀命中省钱降延迟；前缀别放时间戳/随机串。
- **截图走 tool 结果回传**（承 v2，与 a11y-first 完美咬合）：默认给 a11y 文本，模型主动调 `take_screenshot` 才回传图，截图只在该来时来。
- **硬约束**：只收 base64 data URI（不收 URL 图）；多步工具循环须保留 assistant 的 `reasoning_content`；`temperature/top_p/n` 定值别传；诚实 UA 不伪装。
- **远期**：k2.6/k2.7 吃视频 base64——"录 5 秒操作让模型复盘"已就绪。

## 6. 六大能力线（合双方最优 + v3 补丁）

### ① 观察管道
`observe` 工具产「a11y 树 + 可选截图 + 可选 OCR」结构体，元素带稳定 uid。图像走 curl `--data @文件`（撞 ARG_MAX，小蛇临时文件传输天然规避）。**Win 第一行 `SetProcessDPIAware()`；Mac 第一步查 TCC 授权、未授权则明确引导而非静默失败。** 发送前长边压 ~1600–1800px（§4 硬顶）。

### ② 定位（承 v2 的最强升级面）
默认 UIA/AX uid + InvokePattern，零坐标。视觉兜底走 zoom（粗定位→裁原分辨率局部重发，对症 40px 脱靶）。已知坑（v2 实测）：过滤 `IsOffscreen`/∞ 矩形；无响应窗口子进程+超时杀；提权窗口 UIPI 隔离拿不到；PS 显式 `powershell.exe`（PS7 无托管 UIA/WinRT）。

### ③ 照稿写码 / 截图调试（用户最高频，承 v2 的具体化）
渲染自验腿零 MCP 也能走：Win Edge / **Mac Chrome `--headless=new`（本轮真机验，冷启 8.6s，建议常驻 profile 转热）**。硬参数：迭代 5–15 轮、连续失败 8 次熔断、每轮落盘。**判"像不像"用相对不用绝对**（UI2Code^N/RVPO：问"A/B 哪个更近目标图"而非打分）。廉价硬信号先粗筛（渲染报错/全白/目标文本在不在 DOM）再截图喂 Kimi（省请求次数）。数字背书 VF-Coder +6.6pp。可搬 Anthropic `frontend-design` 技能整篇。

### ④ 读文档/PDF/图表
主路：系统渲染器 PDF→PNG（Win `Windows.Data.Pdf` 已验；**Mac `sips` 69ms / `qlmanage` 128ms 已真机验**）→ 长边压 ~1600–1800px → base64。学 Claude"PDF 在前问题在后"+ 双通道（图 + `file-extract` 文本层互校）。图表护栏（ChartMuseum：视觉推理再降 35–55%）：prompt 强制"先枚举轴/图例/数据点再答"。

### ⑤ 安全（承 v1 污点原则 + v2 一手数字 + v3 双机权限现实）
- **a11y-first 顺带免疫图像对抗补丁**（MIP 桌面 100% ASR 是打"VLM 读像素决策"链路——小蛇不靠它定位，从根削掉这条攻击面）。
- 三件零依赖架构事：不可信内容（a11y dump/OCR/HTML）只进带 `source=untrusted` 标签的 tool_result 绝不拼 system；高后果动作（金融/删除/发送/执行）人工确认（CLI 人在环天然优势）；MCP/shell/curl 套沙箱+出网白名单。
- **双机沙箱现实**：Win Home **无 Windows Sandbox**（走 AppContainer/srt-win）；**Mac 的 TCC 权限门本身就是一层天然隔离**（未授权 app 连屏都截不了）——v3 把它从"障碍"重估为"默认最小权限"，授权引导里顺带做知情同意。
- 截图脱敏走窗口级排除（前台是密码管理器/凭据/终端敲密钥→拒截或只截目标窗口）。数字锚：Claude for Chrome 加缓解注入 ASR 23.6%→11.2%、浏览器专项 35.7%→0%。

### ⑥ 评测基建（采用 v2 的零 Docker 四层金字塔）
L1 终态断言（文件/哈希/剪贴板/窗口标题/URL，纯 stdlib，类型感知比较非子串）→ L2 a11y 快照 golden（UIA/AX 序列化成缩进文本存 git、跑完 diff，**小蛇 a11y-first 的天然回归形态**，双机通用）→ L3 关键屏截图 golden（宽容差+遮罩动态区，Win/Mac 各一套基线）→ L4 Kimi-judge 兜底（WebJudge 三步，85–87% 人类一致）。度量 **pass^3**。**judge 永不看 agent 自称"已完成"**（与"只信工具真实返回"同源），pairwise 交换位置跑两次防偏置。全程零 Docker。

## 7. 成本与延迟预算（v3 真机修正）

- **计费真相**：限请求次数（5h/300–1200 次），不是 token → 省钱靠减往返（一图多问、廉价硬信号先筛、批量多动作）。
- **图像 token 自算** `⌈W/28⌉×⌈H/28⌉` 进软预算记账；**且认死 3.2M 像素服务端硬顶**——长边一律压 ~1600–1800px。
- **caching**：带 `prompt_cache_key`，稳定前缀命中降本降延迟。
- **双机延迟锚（真机）**：Win UIA 70ms / 截屏 72ms / OCR 79ms / Edge 热 1.1s；**Mac osascript AX 3796ms（慢 50×）/ Chrome 冷启 8.6s**；Kimi 图单次 60–180s。→ **能用 a11y 文本就别等几十秒看图；Mac 上更要少调 osascript、多缓存树。**
- zoom 重试上限 3 次，超限降级人工。

## 8. 双平台落地（v3 把 macOS 从"未验空洞"补成"一手带权限门"）

| 能力 | Windows（v2 真机） | macOS（v3 本轮真机） |
|---|---|---|
| a11y 树 | PowerShell + `System.Windows.Automation`，**零授权 70ms** | `osascript` System Events → AXUIElement，**须辅助功能授权、3796ms** |
| 截屏 | `System.Drawing` CopyFromScreen 72ms | `screencapture`，**须屏幕录制授权**（未授权 `could not create image`） |
| OCR | WinRT `Windows.Media.Ocr` 一行 79ms | Vision（swift 编译小助手 / shortcuts），非一行 |
| PDF→PNG | `Windows.Data.Pdf` 已验 | **`sips` 69ms / `qlmanage` 128ms 真机验**（v2 说的"sips 坏"不成立） |
| 渲染自验 | Edge `--headless` 1.1s 热 | Chrome `--headless=new` 8.6s 冷（已验） |
| 题库 | Windows Agent Arena | macOSWorld（202 任务含中文+攻击子集，arXiv 2506.04135） |

**macOS 落地第一步（v3 硬性）**：首启做**权限引导**——检测辅助功能 + 屏幕录制 TCC 状态，未授权则弹步骤（系统设置 → 隐私与安全性 → 分别授予控制小蛇的终端），**授权前 a11y/截图能力明确置灰而非静默报错**。这一步 v1/v2 都没有。

## 9. 分阶段施工（承 v2，v3 加双机权限地基）

**地基（必先，串行）**：① eval 骨架（§6⑥ 四层 + pass^3，零 Docker）② 安全硬化（修 `permission.py` 路径护栏审计 #10、`source=untrusted` 污点、危险动作人工确认）③ Kimi 成本对接（`prompt_cache_key`、`⌈W/28⌉×⌈H/28⌉` 记账 + 3.2M 压图、截图 tool 回传）。**④（v3 新增）双机权限与降采样地基**：Win DPI 感知 + Mac TCC 授权引导做进 `observe` 工具的前置。
- 验收锚：最小 eval 自动打分跑通；注入回归入 CI；**Mac 上未授权时 observe 给出引导而非崩溃**。

**增量 A 装眼睛（Win 优先）** → **B 照稿写码闭环**（最高频，可提前）→ **C 浏览器操作**（接 Chrome DevTools MCP 首选 / Playwright MCP 备选）→ **D macOS 对称补全**（PDF 腿 sips/qlmanage 已验；先做 TCC 授权引导，再做 AX 定位）+ 视觉产出（源码生成图→渲染→截图自验；终端**不做 sixel 真图**，用 `[图像 #N]` 占位 + 落盘）。

## 10. 陷阱清单（v1 十条 + v2 七条 + v3 三条新真坑）

承 v1：1 赌坐标 2 pass@1 验收 3 黑名单当安全边界 4 截图不留引用直接压 5 无动作后验证 6 靠模型自评停机 7 全量 caching 反增延迟 8 MCP 描述直进 prompt 9 记忆"请遵循"=持久注入 10 缓存前缀放动态串。
承 v2：11 不声明 DPI（Win 坐标差 2 倍）12 按 token 抠截图预算（错对象）13 judge 信 agent 自述完成 14 Win Home 指望 Windows Sandbox（没有）15 PS7 调 WinRT/UIA（不可用）16 渲染信请求尺寸（DPI 翻倍）17 VLM 判 UI 用绝对打分。
**v3 新增（本轮真机踩到）**：
18. **超大图直发** → 端点砍到 3.2M 像素/4200 token，多花的分辨率被静默扔掉（既慢又白费）。**长边压 ~1600–1800px 是硬规矩。**
19. **在 macOS 假设 a11y/截屏零授权即用** → 双双被 TCC 权限门锁死、静默失败。**首启必须授权引导。**
20. **在 macOS 高频调 osascript AX** → 单次 ~3.8s、慢 Win 50 倍，长任务会拖垮。**多缓存树、少往返、能用 OCR/截图替代就替代。**

## 11. 三版裁决表（"哪个更好"总账）

| 维度 | v1（07-08） | v2（07-09） | **v3（07-09 合流）** |
|---|---|---|---|
| 架构骨架 | **原创** | 继承 | 继承 + 双机标注 |
| Windows 真机 | 无 | **6 探针全通** | 采信 v2 |
| macOS 真机 | 无 | 无（自认未验） | **本轮真机：TCC 双权限门 + 延迟 + Chrome 渲染** |
| Kimi 成本模型 | 碎片+自相矛盾 | 有骨架、疑核错代际 | **端点实测：公式确认 + 3.2M 硬顶新发现** |
| 分辨率上限 | ~3.2M（被 v2 说成错） | 8.8M/11470（错） | **真机判 v1 对：3.2M 服务端顶** |
| 成本单位 | token（错向） | **请求次数（对）** | 采信 v2 |
| eval | Terminal-Bench+Docker（重） | **零 Docker 四层（好）** | 采信 v2 |
| 平台平衡 | 中立但未验 | Win 深 Mac 空 | **双机都一手** |
| 陷阱 | 10 | 17 | **20（+3.2M顶/Mac双权限门/osascript慢）** |
| 诚实收口 | ship 前闭环自查错 | 批判找洞但没堵就发 | **把双方的洞都用数据堵了** |

> **结论**：**v3 ≥ v2 > v1**。v2 是把 v1 方向落到可施工，v3 是**用两发前两版都拿不到的一手数据（当前 Kimi 端点 + 真 Mac），把 v2 最得意的两处盲区（分辨率上限、macOS）也戳穿补实**——它是唯一一份两台机 + 端点三块真相齐全、且对每处 v1↔v2 分歧都有真机裁决的版本。动工以 v3 为准，v1/v2 作方向与 Windows 深度的溯源保留。
