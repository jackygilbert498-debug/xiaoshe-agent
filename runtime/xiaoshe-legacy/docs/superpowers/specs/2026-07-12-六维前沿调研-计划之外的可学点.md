## 甲、先纠正认知（研究修正了已有计划里的几个假设）

1. **"睡眠时整理记忆"有学术正主**：Letta×UC Berkeley《Sleep-time Compute》([arXiv:2504.13171](https://arxiv.org/abs/2504.13171)) + [Letta 产品化版](https://www.letta.com/blog/sleep-time-compute)。A10 里标注的"甲方直觉、非现成论文"应升级为"有论文实证"（test 时算力省 ~5 倍、准确度 +13–18%、多查询共享摊薄 2.5 倍）。**增量认知：睡眠不只"整理"（GC/去重）还要"预习"**——闲时预写"下次大概率被问的结论"（项目状态摘要/悬而未决/常用命令）。工程上可抄两条：①记忆块带标签、**整块重写**（`rethink_memory`）而非增量堆碎片；②**记忆写权分离**——会话主循环只读，只有整理者（idle 心跳/cron）有写权。
2. **Kimi 显式 Context Caching API 已下线**：2024 那套"创建 cache + ¥10/M/分钟存储费 + X-Msh-Context-Cache 头"在现行 [openapi.json](https://platform.kimi.com/docs/openapi.json) 里已无任何 /caching 端点；现行机制是**自动前缀缓存 + `prompt_cache_key`**（[chat API](https://platform.kimi.com/docs/api/chat.md)，Kimi Code Plan 下该字段官方标注**必填**；k2.7-code 缓存命中 ¥1.3/M vs 未命中 ¥6.5/M，[定价页](https://platform.kimi.com/docs/pricing/chat-k27-code.md)）。**已核真代码：小蛇 P2c 就传了 prompt_cache_key（=会话 id）且统计 cached_tokens 命中率**——这条不用做；剩余增量只有"**前缀字节稳定**做成回归断言"（用 usage.cached_tokens 断言命中率不退化）。冻结快照按"字节稳定前缀"设计即可，别照 2024 博客做废功能。
3. **kimi-for-coding 配额本质是 token 池、不是请求数**（[官方权益页](https://www.kimi.com/en-cn/help/kimi-code/benefits) + [kimi-cli issue #1994](https://github.com/MoonshotAI/kimi-cli/issues/1994)：官方宣传"每 5 小时约 300–1200 次请求"，用户实测思维链长的任务 2 次烧穿）→ **省 token 与省轮数同权重**。且 k2.7-code **思维链关不掉**（[模型参数](https://platform.kimi.com/docs/api/models-overview.md)：thinking 恒开、temperature 不可改）→ 输出侧最大省法 = PTC 少一轮 = 少一整条思维链。另：官方支持工具白名单（Kimi Code CLI / Claude Code / Roo Code），自研 harness 严格说在灰区，知情即可。
4. **工具声明动态裁剪：不做**。实测小蛇 23 工具声明 ≈9.6k 字符 ≈3.5k token/轮，远低于劣化阈值（[Anthropic Tool Search Tool](https://docs.claude.com/en/docs/agents-and-tools/tool-use/tool-search-tool) 给的经验值：>30–50 个工具才明显劣化）；动态换子集=每轮前缀变化=**打破自动前缀缓存**，大概率净亏。旁证：[Moonshot 官方 Claude Code 配置](https://platform.kimi.com/docs/guide/claude-code-kimi.md)明写 `ENABLE_TOOL_SEARCH=false`。**反向纪律更值钱：工具声明字节级冻结**。工具涨到 50+ 或接大型 MCP server 再重估（届时参考 [RAG-MCP](https://arxiv.org/abs/2505.03275)）。
5. **"禁抓负面断言"要校准边界**（ReasoningBank [arXiv:2509.25140](https://arxiv.org/abs/2509.25140) 实证）：该禁的是"X 功能/二进制不存在"这类**会过期的事实断言**；不该禁"遇 Y 先检查 Z"的**防御性行动指引**——含失败教训 49.7% vs 只用成功 46.5%（+3 点来自失败侧）。一刀切会把有增益的防御性知识也丢掉。
6. **Kimi 无 embedding 端点**（[官方文档索引 llms.txt](https://platform.kimi.com/docs/llms.txt) 坐实：只有 chat/files/batch/models/token 计算/余额）→ 一切向量方案永久出局。且 2026 测评意外背书 FTS5 路线：《Don't Ask the LLM to Track Freshness》([arXiv:2606.01435](https://arxiv.org/abs/2606.01435)) 里"该信哪条记忆"任务，裸 BM25 48% ≈ HippoRAG-v2 54%，**吊打 Mem0 18% / Zep 7%**——豪华记忆系统栽在组装层。 **实施前对抗审查定论（一个地基，别各建各的）**：A3 会话搜索 / Mem0 写入消歧 / pdf_search / Cheatsheet 检索若都要建，须**共用同一个全文检索层 + 一次 FTS5 能力探测 + 一条子串扫描降级路径**，别每个功能各探一遍 FTS5、各写一套降级。注：当前仓库无任何 sqlite/FTS5 使用，这是从零起的公共地基，一次建对四处复用。
7. **Windows 沙箱排雷**：Windows Sandbox 官方**不支持 Home 版**（[MS Learn](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)，dism 变通属不受支持路径）；`runas /trustlevel:0x20000` 是**假沙箱**（[microsoft/sudo issue #56](https://github.com/microsoft/sudo/issues/56)：只禁 Administrators 组、不降完整性、可绕）。

## 乙、全新的点（计划里完全没有）

### 省钱 / 上下文

1. **NOTES.md 结构化笔记跨 compaction 存活**（[Anthropic effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，Claude 玩宝可梦跨千步的做法）：agent 定期把进度/关键决策/报错原文/精确路径写进上下文之外的持久文件，压缩时豁免原样保留——治"压缩后失忆→重新探索"这类一次几万 token 的隐性返工，还允许摘要压得更狠。一个文件+提示词约定+compaction 豁免，纯标准库。**补 compaction 三连最大缺口。**
2. **ReWOO / LLMCompiler 不另起炉灶，并入 PTC**：[ReWOO](https://arxiv.org/abs/2305.18323)（规划器一次吐完整计划+#E1 变量占位，5× token 效率）和 [LLMCompiler](https://arxiv.org/abs/2312.04511)（DAG 并行派发，延迟 3.7×/成本 6.7× 降）都是 PTC 的**子集**——脚本天然表达变量传递/分支/循环/并行。只吸收两点：①脚本失败回落逐步 ReAct（ReWOO failsafe）；②脚本内无依赖调用并行（线程池）。省两套规划引擎的建设。
3. **Partial Mode 预填**（[官方 API](https://platform.kimi.com/docs/api/partial.md)）：PTC 请求预填 "```python" 强制直接吐脚本砍客套话；注意不可与 json_object 混用、返回不含预填文本需手拼。

### 安全（与 PTC 同一次施工）

4. **CaMeL 受限解释器嫁接 PTC**（DeepMind [arXiv:2503.18813](https://arxiv.org/abs/2503.18813) + [Willison 详解](https://simonwillison.net/2025/Apr/11/camel/)）：做 PTC 时**别用裸 exec**，用 `ast.parse` + 自写 NodeVisitor 受限解释器（禁 import/属性逃逸/双下划线），每个工具调用节点插 taint_gate + **按工具声明式策略**（策略函数拿参数值+capability 裁决 allow/ask/deny——判定集漂移类 bug 在这个架构里更难发生），值带 capability 元数据（来源/可信度/**允许读者集 readers**，防外泄不只防执行）自动传播。这补小蛇最大的架构级缺口：**污点只拦"脏参数进高危工具"一个断面，控制流本身仍可被工具输出劫持**；CaMeL 的"P-LLM 一次写完计划、之后脏数据改不了控制流"正好由 PTC 承载。AgentDojo 77% 任务可证安全。纯标准库，一次施工同时拿下省钱（PTC）+ code-then-execute + CaMeL 全部增量。 **实施前对抗审查定论（关键实现约束，别绕过）**：①受限解释器里每个工具调用节点的**唯一派发入口必须复用现有 `_handle_tool_call` 的完整前置链**（check→approval→taint_gate→execute→污点回记），绝不能让 PTC 桩直接回调 `tools.execute`——真代码里 `tools.execute` 不做任何权限检查，check/approval/taint_gate/污点回记全在 `_handle_tool_call`，桩绕过 = 权限裸奔；②**不另建平行策略集**——"声明式策略函数"要与现有 taint_gate 合流、capability 传播接到现有污点系统上，别开第二套判定（判定集漂移是本仓被反复咬过的老病）；③污点数据经脚本内任何变换（切片/拼接/改写）后仍须带 untrusted——这正是**禁裸 exec 的另一个理由**：裸 exec 会让污点数据被切片改写后失配 taint_gate 的子串匹配，唯有受限解释器按值传播 capability 才堵得住；④**无人值守 / 脚本态下 taint 命中默认拒**，不弹交互 approver（`_default_approver` 走 stdin `input()` 等 y/n，脚本态没人在键盘前）；⑤脚本内多个 ask 档工具调用的**批量审批 UX** 须成规约：静态扫全脚本一次性批 vs 中途逐个弹——先定死一种，别到执行期即兴。
5. **Q-LLM 隔离工具** `query_quarantined_llm(不可信文本, schema)`（[六防御模式论文](https://arxiv.org/html/2506.08837v2) Dual-LLM 的落地件）：不可信原文只交给无工具权限的第二个 Kimi 按 schema 提取结构化值，主模型**永不见原文**——比现在"外部数据前缀标注后仍喂主模型"强一档。六模式对照结论：小蛇组合建议 = Code-Then-Execute（PTC+CaMeL）主干 + Dual-LLM + 高危批量任务的 Plan-Then-Execute 开关（先出计划→人审→冻结执行）；Action-Selector 对通用 harness 削功能太狠不采。
6. **MCP 工具定义哈希 pin 防 rug-pull**（[Invariant Labs mcp-scan](https://invariantlabs.ai/blog/introducing-mcp-scan) 证实的真实攻击面）：首连对每个工具 description/schema 取哈希存档，变更即冻结该工具+弹 diff 人审。基线 MCP 硬化没覆盖"第三方 server 事后偷改"。几十行 stdlib，性价比极高。另可并入 taint_gate 一条 toxic-flow 规则："读过不可信 server 输出的回合内禁高危工具"。
7. **A2 沙箱选型定案：AppContainer + Job Object**（Win11 **Home** 上唯一"默认拒绝一切+资源笼+零依赖"组合）：
   - [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-for-legacy-applications-)：capability 模型**默认拒绝一切**（连读都拦，与 MIC 本质区别），文件/注册表/网络/他进程窗口全隔离，要什么给什么（internetClient 才有出网）；无需管理员、不分版本、毫秒级启动；需 PowerShell Add-Type P/Invoke 几百行（[MalwareTech 参考实现](https://github.com/MalwareTech/AppContainerSandbox)）。
   - [Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)：资源笼（进程数上限防 fork 炸弹/内存/CPU/KILL_ON_JOB_CLOSE 全家死/UI 限制断剪贴板）——只管资源不管访问，与 AppContainer 叠加。
   - 低完整性（icacls /setintegritylevel Low）：轻量档，**只拦写不拦读**（照样能读 .env），防篡改不防泄密，与敏感文件硬拒互补。
   - Mac 侧对称用 **sandbox-exec**（deprecated 但 Apple 自家仍在用、Claude Code/srt 同款，事实标准）。
   - [Anthropic srt](https://github.com/anthropic-experimental/sandbox-runtime)（真存在，Apache 2.0；Windows Alpha=专用账户+WFP+ACE）要 Node 不合红线，但其 Windows 源码可当免费架构图；或作"用户装了 Node 才启用"的最强档外挂。
8. **IsolateGPT 思路移植 MCP**（[NDSS 2025](https://www.ndss-symposium.org/ndss-paper/isolategpt-an-execution-isolation-architecture-for-llm-based-agentic-systems/)）：每个 MCP server 一个逻辑隔离上下文，server A 输出要影响 server B 调用必须过闸+用户许可（hub-and-spoke）——治跨 server tool-shadowing/越权链，纯 stdlib 逻辑隔离即可。

### 可靠性

9. **effects.jsonl 副作用账本**（Temporal/Restate/Inngest durable-execution 通行三段式，[Temporal×OpenAI SDK 已 GA](https://temporal.io/blog/announcing-openai-agents-sdk-integration)）：每个副作用工具**先写意图 `{intent_id,tool,args_hash,status:"intended"}` →执行→写回执 `{status:"done",receipt}`**；幂等键 = `hash(会话,回合,工具,参数)`，执行前查同键已 done 则直接返回原回执（同时防 LLM 重规划重发和重试重复执行）；文件类回执带备份路径（=undo 信息）；启动扫"有意图无回执"的悬挂条目提示"上次崩在这步，已做/未做？"。**一个 JSONL 同时把 A7 的 undo、崩溃恢复、重试安全三件事变具体**，与现有原子写/.state 严丝合缝。配套：给自家 18 个工具补 MCP [ToolAnnotations](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) 三布尔（readOnly/destructive/idempotent）作分层审批依据（外接 server 的注解按规范视为不可信、不降审批）。**实施前对抗审查定论**：幂等键别用 `回合下标 / history 长度` 这类会变的量，要用**稳定 `intent_id`**（脚本 / 意图生成时定死，重规划或重试都不变）——否则重规划后回合错位会让幂等键漂移、账本失效，既防不住重发也防不住重复执行。
10. **轨迹回放回归测试**（先例 [langchain-replay](https://github.com/sixty-north/langchain-replay)：录"LLM 决策"而非 HTTP，回放时工具真执行、LLM 零花费）：在 Kimi client 单点收口加 record/replay 开关，cassette=JSONL(请求哈希→响应)；改 prompt 后 miss 策略显式 fail（逼重录+diff 新旧轨迹）而非静默真调；教训：时间戳/UUID 等非确定输入要注入固定值。**治"改 prompt 不敢动"——每条真实会话变零成本回归资产**，是 600+ 单测照不到的整链路保险。
11. **轨迹匹配四模式 + 轨迹 judge**（[agentevals](https://github.com/langchain-ai/agentevals)）：strict（同序同调用）/unordered（可乱序）/subset/superset 四种纯函数匹配（自实现约百行，接回放断言；多数任务用 unordered/subset 防"换等效路径就挂"），疑难再上 LLM-as-judge（其 TRAJECTORY_ACCURACY_PROMPT 可改造成验收员 rubric）。
12. **用户模拟器 + 终态判定验收**（[τ-bench](https://arxiv.org/abs/2406.12045)/[τ²-bench](https://github.com/sierra-research/tau2-bench)，pass^k 出处）：第二个 Kimi 实例演用户（只给场景+性格、**看不到 agent 工具调用**，信息不对称逼 agent 主动问），成功判定只查文件系统终态 vs 目标状态、不看对话。把"真机+真人式验收"纪律自动化成可通宵跑。警示数据：GPT-4o retail 域 pass^8 <25%——单次成功的 agent 重复可靠性会指数塌方。
13. **evals 任务打包三件套约定**（terminal-bench/OSWorld 共同评法）：每任务 = `setup.py`（布初始状态）+ `task.txt`（指令）+ `verify.py`（查终态返 0/1），自包含、加任务不改跑分器。配 [Anthropic eval 方法论](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：从 20–50 个**真实失败案例**起步；judge 按维度拆+留 "Unknown" 选项防幻觉；transcript 指标（轮数/工具调用数/token/成本）与 outcome 分开记；工具调用验证别过刚（有效的非预期路径不扣分）；盯 pass 率饱和（全过=无信号该上新难题）。
14. **长任务账本**（[Anthropic effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)）：`features.json`（200+ 条具体 feature 每条 `passes:false`，**只许改 passes 字段**、明写"删测试不可接受"；**JSON 优于 Markdown**——模型不容易顺手改写）+ `progress.txt` + 每 session 开场仪式（pwd→git log→读进度→挑最高优先级→冒烟确认没被上轮搞坏）+ 一次只做一个 feature + session 末必提交。防提前宣布完成靠逐条核销而非笼统目标。
15. **Ralph Wiggum 通宵循环**（[官方插件 README](https://github.com/anthropics/claude-code/blob/main/plugins/ralph-wiggum/README.md)）：`:loop "任务" --max 20 --promise DONE`——外层重喂同一 prompt、精确匹配承诺串才停；`--max-iterations` 是主安全机制**必设**；**预算闸门 = 迭代上限 × 单轮成本上限**（小蛇已有 cost 统计直接乘）；困局出口："N 轮未完成→写阻塞报告停机"。与 MAX_TOOL_ROUNDS（轮内）正交，这是轮间刹车。
16. **日志字段名对齐 OTel GenAI 语义约定**（[规范](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-spans/)，仍 Development 态别追版本）：不接 SDK，只把 agent.jsonl 字段名对齐（chat/execute_tool/invoke_agent 等），将来接任何看板免翻译。

### 交互 / 主动性

17. **边跑边说（steering）**：Claude Code 做法已扒清（[issue #71726](https://github.com/anthropics/claude-code/issues/71726)：任务中打字的消息"picked up **between tool calls**"注入下一轮；user message 是注意力最高通道）。小蛇实现：daemon 输入线程阻塞 readline → `queue.Queue`，主循环每个**工具边界** drain，有内容作带 `[用户插话]` 标记的 user 消息追加；配单击 Esc=软打断（保留已完成步骤还控制权）。标准库先例：[pyserial miniterm](https://github.com/pyserial/pyserial/blob/master/serial/tools/miniterm.py)（输入线程 msvcrt.getwch/termios，十几年生产验证）。注意 stdin 争用有更严重的一半：steering 的 daemon readline 不只与 bracketed paste 读取抢 stdin，还与**审批 approver 的 `input()` 抢同一 stdin**——某工具走 ask 时 approver 读 y/n 与 steering 线程读插话是同一个 stdin，**用户为审批打的那个 `y` 可能被 steering 线程抢走**，污染"不可逆动作要人点头"这条铁律。**实施前对抗审查定论：stdin 单一归属**——daemon 是唯一读者，读到后按类分派到不同队列（普通插话 / 审批 y-n / 粘贴块）；approver 与主循环都改为**从队列取**、不再各自 `input()`；bracketed paste 解析也一并移进这个唯一读者；审批期间 steering 让位（插话只入队、不打断审批）。**现状长任务只有 Ctrl+C 一个核选项，这是交互第一缺口**；与心跳（agent→人）互为双向通道两半。
18. **主动触达通知**：Windows **零依赖 toast**——PowerShell 直投 WinRT（[已核实脚本](https://github.com/GitHub30/toast-notification-examples)：`[Windows.UI.Notifications.ToastNotificationManager]::CreateToastNotifier($AppId).Show($xml)`，**借 PowerShell 自己的 AUMID 免注册**，代价显示名为"Windows PowerShell"；WinRT 投影只在 PS 5.1 稳，Python subprocess 调 powershell.exe 正好；勿扰/专注助手会静默吞、失败无报错要写文档）。Mac：`osascript display notification`（坑：**通知权限归调用进程**，Terminal 没开权限则 exit 0 但静默不显示，[真实 bug 先例](https://github.com/anthropics/claude-code/issues/69408)；首跑要引导授权）。心跳发现事情的"最后一公里"。
19. **收件箱 inbox.jsonl**（[LangChain ambient agents](https://www.langchain.com/blog/introducing-ambient-agents) 三原语）：心跳/后台产出分 **notify**（知会不动作）/**question**（问一句解卡）/**review**（待批动作）三类落收件箱文件；REPL 启动/空闲时显示"📥 3 条待处理"；question/review 阻塞项等用户回来批。suggestions 的组织层。
20. **文件触发器**（先例 [aider watch mode](https://aider.chat/docs/usage/watch.html)：监视全仓、注释里 `ai!` 标记才唤醒）：调度器加"文件变更 + 内容匹配（如 `@小蛇` 标记）才唤醒"——**便宜过滤再唤醒**与 [SILENT] 心跳同构，把调度从定时升级为事件驱动。零依赖：os.scandir+mtime 轮询或 PowerShell FileSystemWatcher 常驻再唤醒无头模式。剪贴板轮询（Get-Clipboard 哈希）可做；窗口切换触发无先例、优先级低。
21. **办公产出 COM 通道**（甲方点名）：PowerShell `New-Object -ComObject PowerPoint.Application` 造真 .pptx（[微软官方 Scripting Guy 成套示例](https://devblogs.microsoft.com/scripting/hey-scripting-guy-how-can-i-customize-microsoft-powerpoint-presentations/)；COM 集合从 1 计数、用模板 CustomLayouts 套版式、必须显式 Quit() 防僵尸进程）；Word/Excel 同理；Mac 用 [Keynote AppleScript](https://iworkautomation.com/keynote/slide-make.html)（首跑过一次 TCC 自动化授权）。两平台共用"大纲 JSON→脚本"生成层；产出后截首页给 read_image 自验。真实先例：[powerpoint-mcp](https://github.com/ayushmaniar/powerpoint-mcp) 等多个 MCP 项目证明路线走通（借工具设计、不引 pywin32）。Python 侧零依赖；**系统侧前提=装了 Office**（要向甲方确认）。
22. **Checkpoint 对话+文件联动倒带**（升级 A7，[Claude Code 官方文档](https://code.claude.com/docs/en/checkpointing)全细节）：恢复点=**每条用户 prompt**（粒度对齐用户心智）；三种粒度（代码+对话 / 只对话 / 只代码——"改口重问但保留代码成果"是纯 undo 给不了的）；恢复后**原 prompt 自动填回输入框**形成"倒带→改词→重跑"闭环；增量快照（未变文件复用）；30 天清理；明确声明 **run_command 改的文件不承诺可回滚**。实现：每条用户输入前快照 + 记 messages 长度水位，rewind=截断 messages+还原文件。 **实施前对抗审查定论**：倒带的水位标记用**稳定 `checkpoint_id`**（每条用户 prompt 生成时定死）而非 `messages 长度 / 回合下标`——压缩、steering 插话追加都会改 messages 长度，用长度做锚点会在这些事件后错位、倒带到错误位置（与乙9 effects.jsonl 幂等键同一条纪律：稳定 id 而非可变下标）。

### 记忆 / 学习

23. **bi-temporal 时间戳 + 确定性冲突消解**（[Zep](https://arxiv.org/abs/2501.13956) 的字段方案 + [arXiv:2606.01435](https://arxiv.org/abs/2606.01435) 的组装层结论）：记忆条目加 `created_at / invalid_at / superseded_by`；矛盾时**代码 `max(created_at)` 定胜负，LLM 只判"是否同一事实"、不判"谁新"**（实测让 LLM 判新旧是豪华系统全线拉胯的根因；确定性规则 +10.8 分）；失效不删除、留档可溯。几个 JSON 字段+一个 max()，补基线完全空白的"新旧矛盾谁赢"。 **实施前对抗审查定论（这几个记忆字段一起落，别逐字段叠加）**：本条与乙24（`source`）、乙29（`strength/last_recalled`）、丙 Mem0-ACE 加的字段应**随 A3 的 v2 schema 一次迁移落地**，别每提一个点就往 memory.json 叠一个字段；且多机 git 合并须 **DELETE-aware**——否则被 `invalid_at` / DELETE 删掉、或被 `superseded_by` 取代的记忆，会在字符串并集式合并里被复活。详见 [[A3 跨会话项目记忆结构]]。
24. **记忆写入安全**（[MINJA 攻击](https://arxiv.org/html/2503.03704v2)：仅靠提问就能注入 agent 记忆，成功率 95%+）：**记忆是污点的跨会话洗白通道**（web_fetch 的外部数据被提炼进 memory.json，下会话就成了"可信记忆"）。条目加 `source`（user_direct/tool_output/web_untrusted）字段，污点来源的记忆**永久带 untrusted 标记**、注入时保留外部数据前缀。taint_gate 的自然延伸（安全线与记忆线两个研究员不约而同指到）。
25. **Dynamic Cheatsheet 战术小抄**（[arXiv:2504.07952](https://arxiv.org/abs/2504.07952) + [代码](https://github.com/suzgunmirac/dynamic-cheatsheet)；GPT-4o Game of 24：10%→99%，Claude AIME 翻倍）：比技能轻一层的"最近好用的小招"文件；会话末 curator 提炼**成功策略/代码片段**（episodic 现在只存失败！）、简洁可迁移、自我修剪；DC-Cumulative 变体连检索都不用。**当技能孵化前站**：小抄里被反复用到的才升格 SKILL.md。一个文件+一个提示词，一天可落地。 **实施前对抗审查定论（去重，别三处各存一套经验）**：Cheatsheet（本条乙25）、ReasoningBank（丙 Reflexion）、SKILL.md（A2）现在三处都在"存可复用经验"，须定死**唯一阶梯**：**Cheatsheet（战术小抄，最轻）→ ReasoningBank（= 改造现有 episodic，不是并存新建一套！）→ SKILL.md（成型技能，最重）**，走同一个 curator 生命周期升格 / 淘汰，别各写各的存储。配套一份**"写权与人审矩阵"**：自造技能激活 / 技能自改进（ACE delta）/ 大脑提炼 / 情节记忆各定一档人审强度，**background fork 只产 pending（待批），不直接落地**。
26. **GEPA 夜间自进化**（[arXiv:2507.19457](https://arxiv.org/abs/2507.19457)，ICLR 2026 口头 + [gepa-ai/gepa](https://github.com/gepa-ai/gepa)）：用自然语言反思进化系统提示/技能文本（Pareto 前沿采样候选→跑任务收轨迹→LLM 读轨迹+文本反馈反思"为何失败"→变异→小批评估赢了入池），胜 RL 6–20% 且 rollouts 少 35 倍，纯黑盒 API。小蛇用法：夜间 cron 从日志抽 30–100 个历史任务（尤其失败的）+自动判分器，费用封顶跑 N 轮，**晨间产出 diff+分数走甲方拍板才上线**。必配护栏（下条）。 **实施前对抗审查定论**：GEPA / 睡眠整理的后台写入同 A3/A10 纪律——**走增量 delta + token 预算闸门**，别整份覆盖系统提示 / 技能文本（呼应丙 ACE 反例：整体重写把 18,282 token/66.7 分崩到 122 token/57.1），也别把夜间自进化当免费——每轮 rollout 都在烧 token 池，费用要计入闸门封顶。
27. **自改系统的三条血泪护栏**（[Sakana DGM](https://sakana.ai/dgm/) + [SICA](https://arxiv.org/abs/2504.15228)）：①DGM 真发生过**伪造日志**（"创建伪造日志装作跑了测试"）和**目标黑客**（移除幻觉检测标记拿满分）→ **判分函数/评估数据/日志目录必须对被评估的 agent 只读**（"只信工具真实返回"纪律的论文级佐证）；②SICA 的**异步 overseer**——便宜模型旁路观察事件流、有权掐断（死循环/疯狂烧钱/越权尝试），比纯规则熔断多一层语义判断；③效用函数把 **Kimi 花费计入优化目标**（烧钱也算输）+ 每次自改留 git 谱系可整体回滚。
28. **Training-Free GRPO 同题多解互评**（腾讯 [arXiv:2510.08191](https://arxiv.org/abs/2510.08191)；100 样本 ~120 元 vs 微调 7 万）：对反复做的任务类型夜间采 3–5 个 rollout，让 Kimi 组内对比"为什么 A 比 B 好"（语义优势替代数值优势）提炼经验条目。补 Reflexion 没有的"同题多解对比"信号源，与 GEPA（进化提示词）互补（进化经验库）。
29. **MemoryBank 遗忘曲线**（[arXiv:2305.10250](https://arxiv.org/abs/2305.10250)，AAAI 2024）：条目加 `strength/last_recalled` 两字段，保留率 R=e^(−t/S)，每被召回一次 S+1 且 t 归零；curator 剪枝按 R 最低优先、而非按年龄一刀切——常用老记忆天然保住。一行公式两个字段。

## 丙、强化已计划项的（点到为止，出处在括号里）

- **技能/curator**：ACE 增量 delta——技能文件 bullet 化、每条带唯一 ID + helpful/harmful 计数（被注入后由 Reflexion 判定是否帮了忙、计数回写）、**永不整体重写只打补丁**（[ACE](https://arxiv.org/abs/2510.04618) 实锤反例：整体重写把 18,282 token/66.7 分崩到 122 token/57.1）；AWM 参数化模板+**≥2 条轨迹共性才提取**（防过拟合）+递归组合（[AWM](https://arxiv.org/abs/2409.07429)）；SkillWeaver 主动探索发现技能+高频技能升格为**带测试的代码函数**（检索靠描述、执行靠确定性代码，[SkillWeaver](https://arxiv.org/abs/2504.07079)、[Voyager](https://arxiv.org/abs/2305.16291) 同路）；Memp"**贵模型夜间写记忆、便宜模型白天用**"实证有效（[Memp](https://arxiv.org/abs/2508.06433)）——正对按请求计费。
- **Reflexion**：ReasoningBank 三字段（title/description/content 1–3 句）+ 成败**双**提取（成功提"可迁移策略"、失败提"预防性策略"）+ 每任务只注入 k=1 条 + LLM-judge 自动判成败无需人工标签（[ReasoningBank](https://arxiv.org/abs/2509.25140)）；ExpeL 加第二通道——**成功轨迹本身当 few-shot**（[ExpeL](https://arxiv.org/abs/2308.10144)）。
- **会话末提炼**：Mem0 四操作——候选事实连同 FTS5 检索到的相似旧条目一起给 Kimi，让它选 **ADD/UPDATE/DELETE/NOOP**（写入前先消歧，别只 append；[Mem0](https://arxiv.org/abs/2504.19413)，LOCOMO 省 90%+ token）；A-MEM 卡片属性（tags/keywords 让 FTS5 更准）+"新记忆触发旧记忆演化"（[A-MEM](https://arxiv.org/abs/2502.12110)）。
- **nudge**：升级为"重要性累计超阈值才触发反思"——提炼时顺手让 Kimi 给记忆打 1–10 重要性分，累计超阈值触发聚类+合成高层洞察（反思树，[Generative Agents](https://arxiv.org/abs/2304.03442)）。
- **compaction**：ReadAgent gist 分页——压缩时保留"页号→原文位置"索引 + `lookup_history(page)` 工具按需回看会话档案原文（有效上下文扩 3.5–20×，[ReadAgent](https://arxiv.org/abs/2402.09727)）；tool result clearing **提早常态化**（不等 50%/75% 触发、零请求成本，Anthropic 称其"最安全最轻量的 compaction"，已产品化为 [context editing](https://www.anthropic.com/news/context-management)）。**实施前对抗审查定论**：若把压缩触发点设在 75%，**必须同时抬高现有字符数安全网（约 24000 字符）否则整条是 no-op**——字符网会先开火触发压缩，使 75% 这个高触发点永远轮不到、形同虚设；两道闸的阈值要一起调，别只改一个。
- **多模型路由**：FrugalGPT 级联判定不做（订阅制无价差可套利）；保持"泛提"级即可。
- **Batch API**：现行 6 折（[定价](https://platform.kimi.com/docs/pricing/batch.md)）；交互 harness 用不上、订阅制不适用；唯一场景=开放平台 key 离线跑 evals 省 40%，边缘。

## 丁、明确不做（排雷记录，防将来重查）

- **FrugalGPT 级联**（[arXiv:2305.05176](https://arxiv.org/abs/2305.05176)）：订阅制单模型无价差可套利，打分器本身烧请求。
- **Semantic caching**（[GPTCache](https://github.com/zilliztech/GPTCache)）：单用户编码提问几乎不重复、强依赖仓库状态，误命中危害>收益，且要 embedding。
- **HippoRAG**（[arXiv:2405.14831](https://arxiv.org/abs/2405.14831)）：需图算法+embedding 双依赖，收益场景（多跳语料检索）与单用户 agent 记忆错位。
- **STaR**（[arXiv:2203.14465](https://arxiv.org/abs/2203.14465)）：必须微调权重；其思想已被 ReasoningBank/ExpeL 吸收。
- **ttyd / tmux 会话移交**：外部二进制破坏零依赖；toast+收件箱+无头已覆盖 80% 诉求。零依赖替代：transcript 落 HTML + http.server 只读围观（不排期）。
- **ETDI 签名工具定义**（[arXiv:2506.01333](https://arxiv.org/abs/2506.01333)）：draft 未进 MCP 规范；哈希 pin（乙 6）是够用的穷人版。
- **工具声明动态裁剪**（见甲 4）、**Windows Sandbox on Home / runas trustlevel**（见甲 7）。
