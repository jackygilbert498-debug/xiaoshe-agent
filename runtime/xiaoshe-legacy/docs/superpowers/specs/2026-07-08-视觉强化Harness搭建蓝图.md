## 0. 一句话与心智模型

**给小蛇装上「看 → 想 → 指 → 做 → 验」的完整视觉回路，且每一环都能重复成功、失败自知、危险自停。**

延续项目心法「循环属于模型，机制属于我们」：视觉能力的 agency（看懂、规划）交给模型，我们造的是让它**安全、可复现、可度量**运转的机制。本蓝图不追求「一次点得到」，追求商用级的分水岭——**可复现的失败可控性**。

### 诚实前置（选型的物理事实，不是小蛇的短板）
GUI 视觉 grounding 是**全行业未解难题**：在密集专业界面基准 ScreenSpot-Pro 上，最强端到端模型端到端命中率仅 **18.9%**（[arXiv 2504.07981](https://arxiv.org/html/2504.07981v1)）。任何声称「截图丢给模型就能可靠操作桌面」的方案都在骗人。商用级的做法不是硬刚这个难题，而是**架构上绕开它**（能用结构化定位就绝不赌坐标）。这条贯穿全蓝图。

### 我方实测探针结论（本机真数据，非推测）
| 探针 | 方法 | 结果 | 蓝图含义 |
|---|---|---|---|
| 能否看图 | 纯标准库合成 64×64 左红右蓝 PNG → base64 喂 `kimi-for-coding` | ✅ 答「左红右蓝」，`kimi-latest`/`vision-preview` 同通 | **装眼睛这条腿，当前端点当前 key 直接可走，零额外采购** |
| 定位·单目标 | 640×400 白底单蓝矩形问中心 | ✅ 偏差仅 (0,10)px | 干净大目标可用 |
| 定位·密集场景 | 1280×800 撒 18 个 44px 异色方块，问指定色中心 | ⚠️ 误差跳到 **~40px、落在 44px 目标框外**（橙 41px、青 40px；一次调用 180s 超时） | **干净图 ≠ 密集场景**：一有干扰项裸坐标就点不准——**实测背书「别赌坐标、走 a11y」** |
| a11y vs 截图（活体） | 本会话连 Playwright MCP，对真实网页 news.ycombinator.com 取树/截图 | ✅ a11y 快照**秒回、稳定**（1043 元素，每个带稳定 `ref=e17`）；❌ 截图路径**每次 5s 超时** | a11y 路线比截图路线**更快更稳**，连工具链都在替这个结论背书 |
| 端点约束 | — | 强制 `temperature=1`；1280×800 图单次推理 60–180s | 单次不确定 → pass^k + 投票补偿；大图必须先降采样（延迟/成本双压） |

## 1. 商用级 vs 够用级的分水岭

目标从「够用」抬到「商用」，四类东西从**「不必做」翻转成「必修」**（这几项正是第一轮我判为「个人自用属过度工程」的，目标抬高后定性反转）：

| 维度 | 够用级 | 商用级（必修） |
|---|---|---|
| 度量 | pass@1「这次成了」 | **pass^k**：重复 k 次全过率（τ-bench SOTA pass^8 常 <25%，[2406.12045](https://arxiv.org/abs/2406.12045)） |
| 动作 | 发出即完 | **动作后验证**：每个动作有客观 postcondition，错了自知 |
| 安全 | 提示词请模型别乱来 | **人在环闸门 + 污点隔离**：不可信内容进不了触发动作的路径 |
| 质量门 | 人工看一眼 | **回归 eval + CI**：改动有客观标尺，注入话术做成测试契约 |

## 2. 五段参考架构（跨商用产品的公约数）

拆解 Claude Computer Use、OpenAI CUA、UI-TARS、Gemini Computer Use，四家收敛到同一条流水线；商用级的差别在于**每段都挂了「验证 / 降级」分支**：

```
 观察 Observe ─▶ 规划 Plan ─▶ 定位 Ground ─▶ 执行 Act ─▶ 验证 Verify
   │              │              │             │            │
 截图+a11y      ReAct显式      能用uid          前置校验     查postcondition
 双通道         thought/plan   绝不赌坐标        幂等/可回滚   失败进恢复分支
 元素带uid      长任务外置todo  像素兜底才       ↑             ↓
                              放大重试         └───── 恢复/重试/换策略/安全停 ──┘
```

| 段 | 够用级 | 商用级形态 |
|---|---|---|
| **观察** | 截图丢模型 | 截图 + a11y 树/DOM 双通道；图像下采样到模型有效像素；结构化元素带稳定 uid |
| **规划** | 一步反应 | ReAct 显式 thought→plan；长任务外置 todo 笔记做近端 recitation（对抗上下文漂移） |
| **定位** | 让主脑猜坐标 | grounding 与推理**解耦**：能用 uid/a11y 就不用坐标；必须像素时挂专用 grounder + 局部放大重试 |
| **执行** | 发坐标点击 | 动作前置校验 + 幂等/可回滚封装 |
| **验证** | 无 | 每动作查 postcondition（DOM/截图 diff/文件态）；失败进恢复分支 |

> **关键数字**：ScreenSeekeR 把 ScreenSpot-Pro 的 18.9% → **48.1%**，靠的正是「定位」段的**局部放大重试**（[2504.07981](https://arxiv.org/html/2504.07981v1)）——这是本蓝图定位段的核心手法来源。

## 3. 六大子系统选型（商用级做法 / 小蛇落地 / 自研 vs 外借）

### ① 多模态输入管道
- **商用级做法**：截图与 a11y/DOM 双通道；图像按模型有效分辨率下采样（**Kimi-VL-A3B-Thinking-2506** 版单图上限约 1792×1792 / 3.2M 像素，[Kimi-VL](https://github.com/MoonshotAI/Kimi-VL)）；结构化元素编号（Set-of-Marks）。
- **高分辨率别只会「下采样」——要用 AnyRes 切片**：整图缩小会把小字/小图标糊掉。商用做法是 **AnyRes**（把大图切成子块分别喂、每行末尾插位置 token、坐标像素级重映射回原图），比单一下采样在密集 UI 上保真得多（[AnyRes/LLaVA-OneVision](https://arxiv.org/html/2410.05243v1)）。小蛇的密集场景探针（40px 脱靶）正是不切片的后果。
- **小蛇落地**：`tools.py` 新增 `observe` 工具，产出「截图 + a11y 快照」结构体，元素带稳定 uid；消息层扩成 OpenAI 多模态 `content` 数组（`{type:text}` + `{type:image_url, base64}`）。**图像走 curl `--data @文件`**（几 MB base64 撞 ARG_MAX，小蛇现有临时文件传输天然规避）。
- **自研 vs 外借**：缩放/切片**外借系统工具**（macOS `sips` / Windows PowerShell `System.Drawing`）→ Pillow → 不缩放告警，三级降级，核心链路仍近零依赖；AnyRes 分块与坐标重映射自研。

### ② grounding 与定位
- **商用级做法**：能用可访问性/DOM 定位就**绝不赌坐标**；像素兜底用视觉搜索 + 放大。
- **小蛇落地**：默认走 a11y uid（模型说「点 e15」）；无 a11y 时调外挂 grounding 模型返坐标，命中失败自动放大重试 ≤3 次，超限降级人工。
- **桌面端 a11y 有地基裂缝**：a11y 不是「有或没有」——macOS 原生 AXUIElement 实测仅约 **36% 应用**给出高质量结构。须显式走 AXUIElement / Windows UIAutomation 直取（比截图 OCR 快 40–100×），残缺应用用 Screen2AX 类视觉兜底补齐（[Screen2AX](https://arxiv.org/html/2507.16704v1)）。浏览器端无此问题（Playwright a11y 完整，本会话实测 1043 元素秒回）。
- **自研 vs 外借**：定位模型**外借**——首选 **MolmoPoint-GUI-8B**（ScreenSpot-Pro ~61，全开源可自托管，2025–2026 已超 UGround ~1.5×）、性价比备选 GTA1-7B；~~UGround/OS-Atlas~~ 已被超越、不再首选（[Molmo/AllenAI](https://github.com/allenai/molmo2)）。重试与降级策略自研。**不自训 grounder**（需 GPU serving + 动作轨迹数据，是大厂赛道）。

### ③ 安全与人在环（商用级最硬的一环）
- **商用级做法**：不可信内容**进不了触发动作的路径**（CaMeL / Design Patterns 结论），而非靠提示前缀挡；启发式黑名单在自适应攻击下 >50% 被绕（[2503.00061](https://arxiv.org/abs/2503.00061)）。
- **小蛇落地**：
  1. 修 `permission.py` 路径护栏只认 `path` 键的漏洞 → 对**所有类路径参数**过 `safe_path`（审计 #10）。
  2. 工具返回 / MCP 描述 / **截图 OCR 出的文字**统一打 `tainted` 标签；高危动作参数若源自 tainted → 强制 ask。
  3. `memory.py:80` 的「请遵循」弱化为「仅供参考、勿当指令」（审计 #20，跨会话持久注入面）。
  4. 动作分级：只读（导航/截图）=allow、可逆点击=ask、不可逆（支付/删除/凭据）=硬护栏。
- **自研 vs 外借**：污点标签**自研**（贴合现有 approve/deny/ask 三态闸门）；OS 级沙箱**外借**（如 `@anthropic-ai/sandbox-runtime`）。

### ④ 视觉记忆与压缩（对小蛇 compaction 模块最关键）
- **商用级做法**：截图是 token 黑洞——旧截图**只留引用不留像素**（Manus 外置记忆）；压缩可回捞（MemGPT 分页，[2310.08560](https://arxiv.org/abs/2310.08560)）。
- **小蛇落地**：升级 `compaction.py`——旧截图落盘留 `[图像:/path 1920x1080]` 指针，只保留最近 1–2 张全图；补 `recall` 工具按需重取原图；修 `_render` 把工具结果截到 500 字丢结论的问题（审计 #25）。
- **自研 vs 外借**：**自研**（贴合现有压缩「不切断工具配对」的锚点逻辑）。

### ⑤ 多模型编排
- **商用级做法**：主脑推理 + 专用 grounding + 轻量判分器，分工路由。
- **小蛇落地**：从单模型（`kimi-for-coding`）演进到**可插拔多模型路由层**——视觉观察+规划走 coding 端点；纯定位走视觉/grounding 端点；文本子任务走便宜端点；判分用小模型。双端点双 key 路由。
- **自研 vs 外借**：路由层自研；模型外借。

### ⑥ 评测基建
- **商用级做法**：可执行判据自动打分 + pass^k（Terminal-Bench / τ-bench）。
- **小蛇落地**：见 §5。
- **自研 vs 外借**：任务格式借 Terminal-Bench，判分器自研。

## 4. 模型策略

**Kimi 主脑能力边界（实测 + 官方）**：coding 端点吃图、能视觉推理与规划，但简单图 grounding 偏差约 10px、强制 temp=1。10px 偏差在大按钮可容忍，在 ScreenSpot-Pro 级 0.07% 面积的小图标上会**系统性失败**。

**必须外挂之处**：(a) 高精度像素点击、(b) 高分辨率/密集 UI、(c) 需要坐标级 bbox。

**能吃图的 Kimi 模型（官方现行清单，已二次核实）**：`moonshot-v1-8k/32k/128k-vision-preview`、`kimi-k2.5/k2.6`、`kimi-k2.7-code`（原生多模态 MoonViT）——型号名经官方文档 [use-kimi-vision-model](https://platform.moonshot.ai/docs/guide/use-kimi-vision-model) 核实**真实存在**（第一轮「疑为合成来源」的怀疑已被官方文档推翻）。只收 base64 data URI 和 file-id，**不收 URL 外链**；建议 ≤4K，超出只涨费不涨效果。

> **信源矛盾（须判断）**：UI-TARS 主张**纯视觉**（只吃截图、坐标交互，[2501.12326](https://arxiv.org/abs/2501.12326)）；Gemini Computer Use 走 **DOM+a11y**。根源是**训练资源**——UI-TARS 专门训了 grounding，小蛇没有这条训练管线。**判断：小蛇站 a11y-first 一侧，纯视觉仅当兜底**，与第一轮结论一致。
>
> **来源可信度纪律**：computer-use 各家对比多为营销博客、数字互相打架，只取「Gemini 用 a11y、Claude 用便携截图」这类**架构事实**，不采信其绝对数值。**聚合站（llm-stats/codesota 等）出现的「Claude Opus 4.8 ScreenSpot-Pro 87.9%」「Qwen3 WebArena 95.6%」等已确认为幻觉数字，官方榜无此条目——全文禁引。** 所有百分比只认 arXiv 一手论文与官方榜（见 §4.5、§10）。

## 4.5 清醒基线（业界现在实际能到什么程度 · 期望管理）

> 榜单一手数据（OSWorld-Verified / ScreenSpot-Pro / WebArena，2025–2026），专治「商用级 = 无所不能」的幻觉。**若不写这一层，会把业务方带向过度乐观。**

- **通用旗舰 ≠ 视觉 agent 能力，差一个数量级**：ScreenSpot-Pro 上 GPT-4o 裸测 **0.8%**、Claude Computer Use **17.1%**、GPT-5(resized) 6–18.5%；而开源**专用** GUI 模型 60–80%。→ **底层 grounding 是专用模型的天下，主脑再强也代替不了**（这就是 §3② 必须外挂 grounder 的硬理由）。
- **分数是「步数预算」的函数**：OSWorld 同一 claude-sonnet-4-5，100 步 62.9% / 15 步仅 42.9%。榜首 Holo3-35B 80.4%（已超人类 72.4%）也建立在充足步数上。→ 报成功率必须连步数预算一起报。
- **只信 verified、别信自报**：WebArena 最可信锚点是 **IBM CUGA 61.7%**（团队核实 + 开源轨迹），不是那些 64–70% 的闭源自报值。
- **清醒结论**：受控基准上「最强开源 + 专用组合」能到人类水平；但**通用模型开箱即用、或砍步数预算/脚手架薄，实际落在 30–60%**。小蛇用 Kimi 主脑 + a11y-first + 外挂 grounder，目标现实区间就在这条带子里——**追求可控，不追求刷榜**。

## 5. 可靠性工程清单（映射小蛇现有机制）

| 能力 | 商用级要求 | 小蛇现状 | 缺口 |
|---|---|---|---|
| **动作验证** | 每动作查 postcondition | 无 | **新增**：DOM/截图 diff/文件态三选一 |
| **失败恢复** | Reflexion：失败→复盘→写 episodic 记忆→下轮改进（[2303.11366](https://arxiv.org/abs/2303.11366)） | 无 | **新增** |
| **停机判定** | 锚**客观信号**判是否推进（纯自评会变差，[2310.01798](https://arxiv.org/abs/2310.01798)） | `MAX_TOOL_ROUNDS=20` + `STALL_LIMIT=3` | 太粗，补外部推进信号 |
| **死循环** | in-context locking 检测原地打转 | 部分（STALL） | 补「反复点同一无反应元素」检测 |
| **坐标共识** | 多次采样投票选坐标（补 temp=1 单次抖动） | 无 | **新增 GUI-RC** 空间投票网格，零训练零标注 +2~3%（[2508.05615](https://arxiv.org/abs/2508.05615)）——直接对症探针实测的 40px 抖动 |
| **高危预演** | 不可逆动作前用轻量 world model「演一屏」 | 无 | 可选 gWorld 代码渲染路线，与小蛇「源码生成图」同源（[2504.13936](https://arxiv.org/abs/2504.13936)） |
| **预算** | 真 token 计量 + 步数/超时 | 字符估算 + 两阶段杀 | 接真 token（审计 #23）、修流式重试重复计费（审计 #6） |

## 6. 评测与质量门

- **回归集**：每任务 = 初始环境 + 目标 + **程序化验收**，借 Terminal-Bench 格式，Docker 沙箱跑。
- **判分**：可执行判据优先；非黑白输出用 LLM-as-judge（防裁判偏置，[2306.05685](https://arxiv.org/abs/2306.05685)）；视觉终判可选「像素占比 + 模型看图」双门。
- **指标**：pass@1 + **pass^k** + grounding 命中率 / 平均像素误差。
- **CI**：注入攻击话术（InjecAgent / AgentDojo）做成**中文测试名契约**入 CI——延续项目「一个功能配一条中文测试名」的验收纪律。

## 7. 成本与延迟预算（带数字）

- **prompt caching**：稳定前缀（system + 工具定义）官方口径**降本 up to 90%（分场景 53–90%）、延迟/TTFT 改善 up to 85%（分场景 31–79%）**（[Claude 官方](https://claude.com/blog/prompt-caching)、[docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[2601.06007](https://arxiv.org/abs/2601.06007)）。**只缓存 system、排除动态工具结果**，前缀里**别放时间戳/随机串**（毁 KV 缓存）。KV 命中/未命中价差是**数量级级别（≈10×，个别厂商现价已扩到约 50×）**——勿绑某家现价。**前提**：先确认 Kimi 端点是否支持缓存，否则收益为零。
- **截图预算**：1792×1792 单图约占上下文数千 token；每留一张历史全图 ≈ 一次小请求成本。**只留最近 1–2 张全图，旧图留缩略/指针**。
- **grounding 重试**：放大重试上限 3 次，超限降级人工。
- **多 agent**：orchestrator-worker 并行约 **15×** token（Anthropic），仅高价值任务开。

## 8. 商用级最容易翻车的 10 个陷阱

1. 赌坐标而非 a11y（小图标 <20% 命中）。
2. 用 pass@1 验收（temp=1 下假绿）。
3. 黑名单当安全边界（自适应攻击 >50% 绕过）。
4. 截图不留引用直接压掉（丢证据不可回捞）。
5. 无动作后验证（错了不自知）。
6. 靠模型自评停机（会越纠越差）。
7. 全量 prompt caching（反增延迟）。
8. MCP 工具描述直接进 prompt（tool poisoning 拦截 <30%）。
9. 记忆「请遵循」= 跨会话持久注入。
10. 缓存前缀放动态串（毁 KV 缓存）。

## 9. 分阶段施工建议（地基优先，锚点可验收）

> 目前不动手；此为动工时的施工顺序参考。**地基三件必须先做**——没有标尺，一切视觉改动都是盲改。

**地基（必先，串行）**
1. **eval 骨架 + Docker 沙箱**——最小视觉任务集端到端自动打分跑通。
2. **安全硬化**——修 #10 路径护栏、加污点标签、接沙箱。
3. **prompt caching + 真 token 计量**（先确认 Kimi 支持缓存）。
- 验收锚：最小 eval 套件自动打分跑通；注入回归入 CI 全绿；缓存命中率可观测。

**增量 A · 装眼睛**：多模态观察管道（a11y + 截图双通道）+ a11y-first 定位 + compaction 剥图。
- 验收锚：无坐标路径完成 3 个真实 UI 任务 **pass^4 = 4/4**；「看截图调试」「读图像文档」跑通。

**增量 B · 照稿写码 + 像素兜底**：双图对比迭代闭环（3–5 轮硬上限，对比靠模型看不靠算法 diff，与人类偏好一致率 94%）+ 像素 grounding 外挂 + 放大重试 + 动作后验证。
- 验收锚：设计稿→页面 3 轮内收敛；ScreenSpot 子集命中率有基线。

**增量 C · 浏览器/桌面操作**：借 MCP 插座接 Playwright MCP（现成 stdio server，零自研 CDP），无障碍树点击，敏感动作进 approve/deny/ask；ReAct/Reflexion/进度感知停止/死循环检测。
- 验收锚：长任务死循环检测触发、失败自动复盘写 episodic 记忆；「操作电脑/浏览器」跑通。

**增量 D · 视觉产出**：源码生成图（SVG/HTML/mermaid/matplotlib）→ 渲染 → 截图自验；终端展图降级链（SIXEL/iTerm2 → Unicode 块 → 写盘唤起系统查看器，兜底纯标准库）。文生图非核心（Kimi 无，可选智谱 CogView 插件）。

## 附录 A：源码级可抄参数（读顶级项目源码所得，非泛泛概念）

> 直接抄 Anthropic computer-use-demo、Playwright MCP、browser-use 的**真实常量**——把「概念对」落成「参数对」。

**Anthropic computer-use-demo（`loop.py` / `computer.py`）**
- `max_tokens=4096`；坐标缩放**三档** `1024×768 / 1280×800 / 1366×768`（宽高比容差 0.02，**只在真屏更大时才缩**）。
- 截图前 `_screenshot_delay=2.0s`（等 UI 稳）；打字 `TYPING_DELAY_MS=12`、`TYPING_GROUP_SIZE=50`。
- **缓存断点只打最近 3 个 user turn 且成块对齐**；裁历史图按 `min_removal_threshold` **成块删**（保护 prompt cache 不被打穿）。

**Playwright MCP（ref 契约）**
- ref 形如 `e12` / 跨 iframe `f1e12`，正则 `^(f\d+)?e\d+$`；模块级单调计数器**跨快照对同元素稳定**；**只有「可见且 receivesPointerEvents」的节点才编 ref**。
- 等待已内建（导航 domcontentloaded+5s、动作后网络静默 ≤5–10s、`browser_wait_for` ≤30s）——**接入方别自加固定 sleep**。

**browser-use（三件套）**
- `[i]<tag attr>text</tag>` 索引化 DOM 序列化：只给可交互+可见元素分配 index，`*` 前缀标新元素，属性 `cap_text_length(100)` 截断。
- 两级超时 `llm_timeout≈90s` + `step_timeout≈180s`；`consecutive_failures / max_failures=5`；空动作自动补重试；只留最近一张截图 + history 折叠。
