# 小蛇多服务商模型管理设计

> 日期：2026-08-02
>
> 状态：待用户审核
>
> 实施分支：`codex/handoff-ux-p0`
> 当前基线：`b285c96`

## 1. 背景与根因

当前 `.env` 同时保留了 Kimi 与 DeepSeek 的密钥和默认模型，Kimi 密钥并未被删除。界面只显示 DeepSeek 的根因是：现有配置在进程启动时只解析一个 `MODEL_PROVIDER`，随后 `model_candidates()` 又主动过滤另一服务商的模型；会话切换只替换模型名称，底层请求仍固定使用启动时选中的密钥、接口和协议。因此，直接把 `kimi-for-coding` 塞进现有下拉框会把 Kimi 模型名发往 DeepSeek 接口，是错误且不安全的“假切换”。

本设计把“模型”从一个字符串升级为一个完整的本地连接配置。选择模型时必须原子切换服务商、协议、接口、鉴权和上游模型名。

## 2. 目标

1. 已保存且具有可用配置的 Kimi、DeepSeek 自动出现在模型菜单中；两者都存在时可以即时切换。
2. 切换仅作用于当前会话，下一次请求使用新模型对应的密钥、接口和协议；正在生成的请求继续使用它开始时捕获的旧配置。
3. 模型菜单底部增加“＋ 添加模型”，打开本地模型管理窗口。
4. 管理窗口允许选择协议/服务商模板，填写显示名称、上游模型名、接口地址、鉴权方式和密钥。
5. 第一版内置 OpenAI Chat Completions 兼容、Anthropic Messages、Google Gemini、Ollama 四类协议；Kimi 与 DeepSeek 是 OpenAI 兼容协议的内置模板。
6. 通过适配器注册表继续扩展特殊厂商，不改会话层和管理界面主体。
7. 密钥只保存在本机；任何读取接口、页面、日志、异常、测试快照和进程命令行均不得回显密钥。
8. Kimi 额度不足、鉴权失败或临时故障时仍保留在模型列表中。每次真实调用都以服务商当次响应为准；额度恢复后无需重新配置即可正常使用。

## 3. 范围边界

“兼容任意模型”的含义是：

- 只要服务商采用四类内置协议之一，用户可通过界面添加其任意模型名和接口地址。
- 对请求格式不同的特殊服务商，通过新增一个后端协议适配器接入；不允许在页面粘贴或执行任意代码。
- 第一版不承诺自动猜中每个服务商的私有协议、私有签名算法或全部模型能力。
- 模型是否支持工具调用、视觉输入、流式响应和推理字段由适配器声明，并在界面中如实展示；不支持工具调用的模型可用于普通对话，但不能伪装成能执行小蛇工具。

本轮不建设云端账号同步、团队共享密钥、服务商计费中心、模型市场或自动购买额度。

## 4. 方案选择

采用“本地模型注册表 + 协议适配器 + 会话级模型引用”。未采用以下两种方案：

- 只修改 `XS_MODELS`：只能切同一接口下的模型名，无法正确切换密钥和协议。
- 每次切换都改 `.env` 并重启：破坏当前会话、体验差，而且容易覆盖用户原配置。

新方案保留 `.env` 作为兼容配置源，不迁移、不清空、不覆盖原 Kimi 密钥。界面新增的配置写入被 Git 忽略的本机状态目录；旧命令行入口仍可使用 `MODEL_PROVIDER` 默认值。

## 5. 核心数据模型

### 5.1 服务商配置 `ProviderProfile`

每个连接配置包含：

- `id`：本机稳定 ID，不使用密钥或接口地址派生。
- `display_name`：如“Kimi”“DeepSeek”“本地 Ollama”。
- `protocol`：`openai_compatible`、`anthropic`、`gemini`、`ollama` 或已注册扩展协议。
- `base_url`：服务商接口根地址，保存前规范化并校验为 `http`/`https`；Ollama 可使用本机地址。
- `auth_mode`：`bearer`、`x_api_key`、`query_key`、`none`，模板给出安全默认值。
- `api_key_ref`：只指向本机密钥存储中的条目，不含密钥本身。
- `source`：`environment`、`local` 或 `builtin`，用于说明配置来源。
- `enabled`：是否显示和参与候选列表。

### 5.2 模型配置 `ModelProfile`

- `id`：页面与会话使用的稳定 ID，避免仅凭模型名猜服务商。
- `provider_id`：关联 `ProviderProfile`。
- `display_name`：用户看到的名称。
- `upstream_model`：发送给服务商的真实模型名。
- `capabilities`：`stream`、`tools`、`vision`、`reasoning` 等适配器能力标记。
- `enabled`：是否出现在选择菜单中。

允许两个服务商拥有相同的 `upstream_model`，因为页面和后端均以稳定 `id` 区分。

## 6. 配置来源与兼容策略

启动时注册表按以下顺序合成配置：

1. 进程环境变量，优先级最高；界面标记“由环境管理”，不得从页面覆盖其密钥。
2. 本机模型注册表与本机密钥存储。
3. 原有 `.env` 中的 `KIMI_*`、`DEEPSEEK_*`、`MODEL_PROVIDER` 和 `XS_MODELS`。
4. 内置模板默认值。

只要 `KIMI_API_KEY` 非空，就生成 Kimi 服务商和 `KIMI_MODEL` 对应模型；只要 `DEEPSEEK_API_KEY` 非空，就生成 DeepSeek 服务商和 `DEEPSEEK_MODEL` 对应模型。两者同时存在时，两者同时显示。`XS_MODELS` 继续解释为当前默认服务商的附加模型，保证旧配置不失效。

新增配置元数据保存到 `.state/model_profiles.json`。密钥不写入该文件；Windows 使用 DPAPI 加密后保存到 `.state/model_secrets.bin`，并把解密范围限定为当前 Windows 用户。其他平台后续分别接系统凭据库；若系统凭据库不可用，必须明确提示并采用仅当前用户可读的本地降级存储，不能静默降低保护级别。

`.env`、`.state/` 和密钥文件继续由 `.gitignore` 排除。实施与测试必须验证 Git 无法枚举到真实密钥文件。

## 7. 后端结构

### 7.1 模型注册表

新增单一注册表模块，负责：

- 从多种配置源合成并校验服务商/模型。
- 返回不含密钥的页面视图。
- 根据模型 ID 解析一次请求所需的完整运行时配置。
- 原子保存新增或修改的本地配置。
- 保持原 Kimi、DeepSeek 环境配置只读兼容。

注册表不会根据一次请求失败自动删除、禁用或改写模型。

### 7.2 协议适配器

统一接口负责四件事：构造请求、执行非流式/流式传输、规范化响应和规范化错误。内置适配器为：

- `openai_compatible`：Kimi、DeepSeek、OpenAI 兼容中转和自建端点。
- `anthropic`：Anthropic Messages 请求、流式事件和工具调用。
- `gemini`：Gemini generateContent/streamGenerateContent 与函数调用。
- `ollama`：Ollama chat 与本机无密钥模式。

当前 `kimi_client` 中已经验证过的 curl stdin 密钥传递、超时、重试和脱敏规则下沉为共享安全传输层；适配器不得把密钥放入命令行参数。

Kimi 的 `prompt_cache_key`、DeepSeek 的 `thinking` 等厂商差异由模板/适配器处理，不再读取一个全局 `config.PROVIDER` 判断。

### 7.3 会话切换

会话上下文保存 `_model_profile_id`，不保存密钥。每次发送前，模型客户端通过注册表把该 ID 解析为一份不可变请求配置；切换模型只替换当前会话的 ID。

- 新会话使用 `MODEL_PROVIDER` 对应默认模型；若该模型不可用，使用第一个已启用且配置完整的模型。
- 切换发生在请求开始前；生成过程中修改选择只影响下一次发送。
- 已恢复的历史会话若没有模型 ID，按默认模型处理，保证旧存档兼容。

## 8. 本地接口契约

### 8.1 `GET /api/models`

为避免破坏现有契约与旧页面，现有 `models/current/default/switchable` 字段继续保持“当前默认服务商的上游模型名”语义。新增 `items/current_id/default_id` 承载跨服务商选择；新版页面优先读取 `items`，旧页面仍可按原逻辑工作：

```json
{
  "models": ["deepseek-v4-flash", "deepseek-v4-pro"],
  "current": "deepseek-v4-flash",
  "default": "deepseek-v4-flash",
  "switchable": true,
  "current_id": "builtin-deepseek-flash",
  "default_id": "builtin-deepseek-flash",
  "items": [
    {
      "id": "builtin-kimi-coding",
      "label": "Kimi · kimi-for-coding",
      "provider": "Kimi",
      "protocol": "openai_compatible",
      "configured": true,
      "capabilities": ["stream", "tools"]
    }
  ]
}
```

`configured` 只表示本机存在所需配置，不表示账号当前有额度，也不通过探测请求推测服务是否可用。

### 8.2 `POST /api/model`

新版页面发送 `{"model_id":"<model-profile-id>"}`。为兼容旧页面，接口继续接受 `{"model":"<upstream-model>"}`，但旧格式只在当前默认服务商的旧候选清单中解析，绝不跨服务商猜测。成功后返回模型 ID、上游模型名、显示名称、服务商以及 `persisted:false`；不返回接口密钥。未知、禁用或配置不完整的模型返回 400，并保持原选择不变。

`GET /api/state` 同样保留现有 `model` 字段，并增补 `model_id/provider`；现有客户端不需要同步升级即可继续读取。

### 8.3 模型管理接口

- `GET /api/model-profiles`：返回脱敏配置；密钥字段只返回 `configured/source`，不返回长度、前缀或尾号。
- `POST /api/model-profiles`：创建模型与服务商配置；`api_key` 是只写字段。
- `PATCH /api/model-profiles/{id}`：修改非秘密字段；密钥留空表示保留原值，显式“清除密钥”使用单独确认动作。
- `DELETE /api/model-profiles/{id}`：只删除本机新增配置；`.env`/环境变量生成的内置配置不可删除，只能在本机隐藏，且不改原文件。
- `POST /api/model-profiles/{id}/test`：用户主动触发连接测试。界面必须说明测试可能产生极少量调用或计费；未点击时不后台消耗额度。

所有写接口复用现有本地 token、来源校验、请求体大小限制和 schema 校验。

## 9. 界面设计

模型菜单中的每一项显示“服务商 · 模型名”，当前项带“当前”标记。列表底部固定一条分隔线和“＋ 添加模型”按钮；按钮不随模型列表滚动丢失。

点击后打开现有统一模态框体系中的“模型管理”窗口：

1. 选择模板：Kimi、DeepSeek、OpenAI 兼容、Anthropic、Gemini、Ollama。
2. 填写显示名称和上游模型名。
3. 根据模板预填接口地址与鉴权方式，允许在“高级设置”中修改。
4. 密钥输入框始终为空；编辑已有配置时只显示“密钥已保存”，绝不把旧值写回 DOM。
5. 保存前做本地格式校验；连接测试是独立、显式操作，不能以保存为由偷偷发起计费请求。
6. 保存成功后立即刷新模型菜单；若选择“保存并切换”，只切当前会话。

键盘与无障碍要求：按钮是真实 `button`；模态框有标题、描述、错误摘要、焦点圈、Esc 关闭、Tab 循环和关闭后焦点归还。“删除/清除密钥”必须二次确认，默认焦点落在取消按钮。

## 10. 错误与额度语义

适配器保留服务商返回的 HTTP 状态和结构化错误类型，经脱敏后映射为统一类别：鉴权失败、额度/限流、模型不存在、协议不兼容、网络/代理、超时和未知上游错误。

对 Kimi 的规则：

- 只有真实请求收到 Kimi 的额度或限流响应时，才显示“Kimi 当前额度不足/受限”及其脱敏详情。
- 不因为历史失败、本地缓存、时间推算或 DeepSeek 状态提前判断 Kimi 无额度。
- 额度错误不改变 `enabled/configured`，不删除密钥，不自动切换模型。
- 用户稍后再次发送时重新真实调用 Kimi；额度恢复即正常返回。
- 鉴权失败与额度不足必须分开显示，不能把密钥问题误报成额度问题。

任何错误都必须经过密钥、Authorization、查询参数和自定义鉴权头脱敏后才能进入日志、WebSocket 或页面。

## 11. 安全设计

- 页面和读取接口永不返回密钥；“已配置”是唯一可见状态。
- 保存接口接受密钥后立即写入本机秘密存储，不进入会话历史、任务日志或审计详情。
- 自定义接口仅允许 `http`/`https`；非本机明文 HTTP 默认拒绝。Ollama 的 `localhost/127.0.0.1` 可使用 HTTP。
- 不允许用户通过界面配置任意命令、脚本、证书路径或可执行适配器。
- 自定义鉴权头只允许受控的头名与单个秘密值；拒绝 CR/LF 等控制字符，防止头注入。
- 导出会话、诊断包、截图和错误报告不得包含密钥存储或秘密字段。
- 保存采用临时文件、落盘同步和原子替换；写失败时保留旧配置，不产生半份注册表。

## 12. 测试与红→绿顺序

实施拆为三批，每批都先写失败测试、确认按预期失败，再做最小实现、跑定向与全量回归、提交、独立验收。

### 批次 A：注册表与秘密边界

- 红：两把密钥同时存在时当前列表仍只有一个服务商；读取接口若能看到密钥则失败。
- 绿：合成 Kimi/DeepSeek 配置、稳定模型 ID、本机注册表、DPAPI 秘密存储和脱敏视图。
- 验收：原 `.env` 字节不变；Kimi 与 DeepSeek 同时出现；所有 JSON/日志/Git 状态无密钥。

### 批次 B：多协议请求与会话切换

- 红：从 DeepSeek 切 Kimi 后请求仍使用 DeepSeek URL/key；Anthropic、Gemini、Ollama 无法规范化请求/响应。
- 绿：共享传输层、四个内置适配器、会话级模型 ID、请求开始时配置快照、统一错误分类。
- 验收：使用假服务端逐项核对 URL、鉴权头、请求体、流式增量、工具调用和错误；再对用户已配置且允许测试的真实服务做最小冒烟。真实密钥绝不输出。

### 批次 C：模型管理界面

- 红：模型菜单无 Kimi、无添加入口、管理窗口可回显秘密或键盘路径不完整。
- 绿：分组模型菜单、固定添加按钮、管理模态框、保存/测试/切换反馈和错误态。
- 验收：浏览器自动化覆盖鼠标、纯键盘、窄屏、亮暗主题、保存刷新、跨服务商切换和零未捕获异常；人工截图确认信息层级。

每批提交后先审查再进入下一批。最终运行契约校验、服务冒烟、E2E、Windows 入口和全量单测。

## 13. 验收标准

以下条件必须同时成立：

- 当前本机 Kimi 与 DeepSeek 密钥均保持存在，`.env` 未被覆盖或清空。
- 模型菜单同时显示 `Kimi · kimi-for-coding` 与已配置的 DeepSeek 模型。
- 在同一会话切换后，下一次请求使用所选模型绑定的正确 URL、密钥、协议和模型名。
- 页面底部有“＋ 添加模型”，可添加四类内置协议覆盖的任意上游模型。
- 密钥创建后不能通过任何 GET、DOM、日志、错误、命令行、导出和 Git 读取出来。
- Kimi 额度不足只在真实 Kimi 请求返回对应错误时提示；模型仍可选，额度恢复后可直接正常调用。
- 不支持工具调用的模型被如实标记，不能伪装执行工具。
- 旧会话、旧 `.env`、旧命令行默认模型和现有 DeepSeek 调用保持兼容。
- 三批均有独立红→绿证据、提交和验收记录，全量测试无新增失败。
