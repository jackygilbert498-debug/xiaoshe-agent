# Beta 回退操作手册

## 立即触发条件

以下任一情况都不等待“更多样本”：用户工作丢失、严重未授权副作用、跨项目泄漏、破坏性 false success、不可恢复迁移、权限硬护栏被绕过、受支持 Git 恢复误删文件，或遥测/诊断泄漏敏感数据。

## 前 15 分钟

1. **冻结**：停止新放量、后台 Trigger、worker 和进一步迁移；不要删除队列、日志、worktree 或用户数据。
2. **保全**：记录候选 ID、应用版本、commit、时间、受影响范围和报错；复制只读诊断与 manifest，避免在原地改写证据。
3. **降级**：切换到最近验证的 last-known-good 应用的只读模式。若不能安全降级，明确阻止写入并提供只读导出。
4. **通知**：告知受影响用户当前限制、已知影响和下一次更新时间；不把尚未验证的恢复称为成功。

## 恢复与判定

5. 使用迁移前且实际可打开的备份恢复 DB、WAL、SHM 和元数据；对恢复后的读写、Task 状态、Session 引用和证据索引做确定性校验。
6. 对 Git/worktree 只使用登记过的工作区和显式恢复操作；禁止 `git reset --hard`、`git clean`、自动 stash 或覆盖用户未提交改动。
7. 为每项已知副作用记录 `restored`、`partially_restored` 或 `unrecoverable`。存在部分结果时，Task 必须进入 Failed 或 WaitingUser，不得显示完成。
8. 只有独立复核恢复证据、根因修复、相关失败注入回归通过，并重新满足发布门后，才可解除冻结。

## 复盘与防复发

9. 写入 ADR：触发信号、影响、决策、回退范围、数据处理、修复、验证和后续门。
10. 把缺失的检测或回退步骤补入 `release-governance.json`、本手册和自动测试；单靠人工提醒不视为修复。
