## 一、方向目标与价值

这一批清的是「单测照不到、真机偶发、无人值守时最伤」的一簇缺陷：模型循环里的原子性漏洞、流式传输的重试/失速/看门狗、会话与记忆的边界时序、MCP/定时/后台的资源回收与协议健壮。它们各自都不是崩溃级 bug，但叠在一起会让 harness 在长跑、断线、时钟回拨、坏档案、进程复用等真实工况下悄悄跑偏——尤其在**无人值守的定时/无头模式**下，一次静默毒化就可能砖死整条会话或误杀无辜进程。

价值定位一句话：**把「示例能跑」抬到「长期无人看管也不出事」**。修完后的三条硬不变式：

1. **原子性**：本轮追加进 `history` 的一切状态（含被有损压缩的旧史、越权计数、打转计数、todos）失败时整体回滚，绝不留半截。
2. **协议自洽**：写进 `history` 的每个 `tool_calls` 项都有唯一 id 且恰配一条 tool 结果——存档 resume 永不触发 OpenAI 协议 400。
3. **资源不泄漏、活性不外包**：流式读、MCP 读、后台/定时子进程都自带有界读与看门狗，不把「会不会挂死」押给下游 curl / 子进程。

三个实现单元按代码归属切分，互不阻塞：

| 单元 | 覆盖文件 | 缺陷数 | readiness | 工作量 |
|---|---|---|---|---|
| **4a 循环·传输·流式** | agent.py / kimi_client.py / tools.py | 9 点 | 4/5 | 中(2-4天) |
| **4b 会话·记忆·压缩·权限·IO** | session/memory/permission/_io/config/headless | 12 点 | 3/5 | 中(2-4天) |
| **4c MCP·定时·后台** | mcp_client/schedule/jobs/headless | 14 点 | 4/5（未评审，本文档补默认 4）| 中(2-4天) |

> **真机基线口径**：本沙箱跑全量有 4 条 `test_m2` 预存 ERROR（Windows 控制台把子进程 GBK 输出按 utf-8 解码的环境假故障，与本批六~九文件无关，`config.MODEL=None` 也是缺 `.env` 所致）。用户真机（有 `.env`、`config.MODEL` 非 None）口径是 **190 绿**。落地后回归须在用户真机复跑确认「190 绿」，本机复跑时**显式排除**那 4 条环境假故障、不得误判成本批引入的回归。

#### 4a-#1 + #23 压缩纳回滚 + 回滚含 `_denied_calls`/`_repeat`

- **病灶**：`compaction.maybe_compact(history, ...)`（agent.py:133）跑在原子边界之外。它会就地把旧史压成一条 system 摘要（`compaction.py:110` `history[:]=pinned+[summary_msg]+recent`，有损改写）。一旦本轮 `model_fn` 抛错走 `except`（agent.py:172），`del history[start_len:]`（175）只能删掉本轮追加的尾部，**还原不了被压缩丢掉的旧史**——旧史永久丢。同时 `_denied_calls`（agent.py:105）/`_repeat`（agent.py:85）不随 except 回滚，失败轮的越权/打转计数残留，污染无人值守的越权信号灯。
- **改法**（`agent.py` run_once）：以 commit 为回滚单元。
  1. 在调 `compaction.maybe_compact` **之前**先整表浅拷贝：`pre_history = list(history)`（浅拷贝够用——compaction 是整表替换而非改单条 dict）。
  2. 把压缩纳入同一 `try` 原子边界之内（compaction 移到 `pre_history` 快照之后、`append user` 之前调用）。
  3. 同处快照计数：`denied_snap = ctx.get('_denied_calls', 0)`；`repeat_snap = dict(ctx['_repeat']) if ctx.get('_repeat') else None`（`_repeat` 是 dict，必须 `dict()` 浅拷贝；原本无该键时快照为 `None`）。
  4. `except` 分支从 `del history[start_len:]` 改为 `history[:] = pre_history`（整表还原，连同被压缩的旧史）；并补 `ctx['_denied_calls'] = denied_snap`、`ctx['_repeat'] = repeat_snap`（还原为 `None` 即等价「本轮未打转」）、`ctx['todos'] = todos_snapshot`。
- **中文测试名**：
  - `test_压缩纳回滚_本轮model失败后被压旧史整表还原不永久丢`
  - `test_回滚同时还原denied_calls和repeat计数不残留`

#### 4a-#2 tool_call_id 去重 / 规范化

- **病灶**：`for tc in tool_calls`（agent.py:169）逐个 `_handle_tool_call`，对模型返回的**重复/空 id 不规范化**。重复 id 会各追加一条 `role:tool` 同 `tool_call_id`（agent.py:53），存档 resume 时违反 OpenAI「每个 `tool_call_id` 恰配一条 tool 结果」契约 → API 400 毒化会话。
- **新增函数**（`agent.py`）：`_dedupe_tool_calls(tool_calls: list) -> tuple[list, list]`
  ```
  # docstring 必须标注：本函数就地规范化 tc['id']（补合成 id），
  # 调用方须确认这些 dict 未被 kimi_client 层复用/缓存（parse_response 每次新建 list，安全）。
  seen = set(); kept = []; dups = []
  for i, tc in enumerate(tool_calls):
      tid = tc.get('id') or f'_auto_{i}'; tc['id'] = tid
      name = tc.get('function', {}).get('name', '')
      if tid in seen:
          dups.append((tid, name))
      else:
          seen.add(tid); kept.append(tc)
  return kept, dups
  ```
- **主循环接线**（评审强制次序，务必照做）：拿到 `result` 后、**在 `history.append(assistant_msg)`（agent.py:149）之前**调 `_dedupe_tool_calls`，用 `kept` 覆盖 `assistant_msg['tool_calls']` 再 append；紧接着为每个 `dup` 补一条配对结果 `_append_tool_result(history, dup_id, dup_name, '（重复的 tool_call_id，已忽略此次调用）', True, log_file, ctx)`；分发循环（agent.py:169）与 `MAX_TOOL_ROUNDS` 补空那段（agent.py:165）都改遍历 **kept 版本**。否则重复 id 仍进 history，反而制造它想防的 400。
- **中文测试名**：
  - `test_重复tool_call_id_只执行首次其余补配对结果_history每id恰配一条`
  - `test_空或缺失tool_call_id_被补合成id且能正常配对不400`
  - `test_去重后assistant消息里的tool_calls与tool结果一一对应_ends_clean为真`

#### 4a-#4 + #6(reasoning) 流式重试漏算 reasoning

- **病灶**：`has_output = c["message"].get("content") or c["message"].get("tool_calls")`（kimi_client.py:167）漏了 `reasoning_content`（reassemble_stream 已在 `message.reasoning_content` 透出，见 kimi_client.py:300 附近）。reasoning-only 且中途断线（`rc!=0`）时 `has_output` 为假 → 走 `attempt<retry` 重试 → 重复生成/重复计费（这是上轮「握手重试」修复自引入的 bug，路线文档点名先修）。
- **改法**（kimi_client.py:167）：`has_output = c['message'].get('content') or c['message'].get('tool_calls') or c['message'].get('reasoning_content')`。一旦吐过 reasoning 即视为已开始生成，绝不重试。
- **评审补充**：改后须确认 reasoning-only 但**已带 `finish_reason` 的正常结束**不被 `kimi_client.py:178` 的 `not finish_reason` 空响应守卫误判为空。补一条测试锁死。
- **中文测试名**：
  - `test_reasoning_only截断响应_不被误判空_不重试不重复计费`
  - `test_已吐reasoning后断线_保留不重试`
  - `test_纯reasoning正常收尾_不判空不重试`

#### 4a-#6(exit 分类) exit28 vs exit35

- **病灶**：`kimi_client.py:170-177` 对任意 `rc!=0` 统一按 `has_output` 决定是否重试。curl **exit 35**=TLS 握手失败（出字前断，重试安全）；**exit 28**=操作超时/speed-time 失速（服务端静默或慢速，重试易叠加成本且常再次失速）。
- **改法**（kimi_client.py:170-177 分支）：新增模块常量 `_RETRYABLE_EXIT = {35, 7, 56}`（握手/连接类，出字前断）、`_STALL_EXIT = {28}`（失速）。逻辑：
  - `rc in _STALL_EXIT` → 直接 `raise KimiError('到 Kimi 的响应失速（exit 28），非握手问题，未重试——检查网络/代理')`；
  - `rc in _RETRYABLE_EXIT` 且 `attempt < retry` → 保留现有重试；
  - 其余 rc → 保留现有 `raise KimiError(f'curl 流式调用失败（exit {rc}）')`。
- **中文测试名**：
  - `test_exit28失速_不重试_抛明确失速原因`
  - `test_exit35握手失败_出字前_仍按原策略重试到通`

#### 4a-#5 流式读循环 idle 看门狗（**本批最高风险，务必按评审防线写**）

- **病灶**：`reassemble_stream`（kimi_client.py:231）的 `for line in lines` 无自身超时，永久阻塞只靠 curl 的 speed-time（kimi_client.py:79）兜底；若 curl 因平台/信号未如期失速退出，Python 读循环挂死。
- **新增函数**（`kimi_client.py`）：`_idle_guarded_lines(stdout, idle_timeout)` 生成器 + 内部异常 `_StreamStall(KimiError)`。起一个 **daemon 读线程**把每行 `put` 进 `queue.Queue`，主体 `while True: item = q.get(timeout=idle_timeout)`（`queue.Empty` → `raise _StreamStall()`），哨兵 `None` 结束。
- **接线**：`_post_stream` 里把 `reassemble_stream(proc.stdout, ...)` 改成 `reassemble_stream(_idle_guarded_lines(proc.stdout, idle_timeout), ...)`；捕获 `_StreamStall` → terminate curl 并按失速定性（不重试，抛明确 KimiError）。`reassemble_stream` **保持纯函数不动**（离线可测）。常量 `STREAM_IDLE_TIMEOUT = min(timeout, 30)`。
- **评审硬约束（不照做会砸掉多条现有流式测试）**：
  1. 只用**行读取**、对任意可迭代对象都成立——**禁用 `fileno()` / `readline()` 等 fd 专属调用**（现有 `test_streaming` 用 `proc.stdout=iter([...])` 纯迭代器，无真 fd）。
  2. 读线程 `daemon=True`，terminate 后**不 join 阻塞**；接进 `_post_stream` 现有 `finally` 的 `poll/kill/wait(5)` 收割路径，别另起收割。
  3. 快迭代器**不得误触** idle 超时逻辑。
- **中文测试名**：
  - `test_流式读循环空闲超时_看门狗触发_按失速处理不永久阻塞`
  - `test_流式正常流_看门狗不误伤_内容完整拼回`

#### 4a-#3 + #26 子 agent 流冲主屏 + 摘要冲屏

- **中文测试名**：
  - `test_子agent走安静句柄_正文不冲主屏_只带回最终结论`
  - `test_子agent内部压缩摘要_不冲主屏`

### 单元 4b — 会话 / 记忆 / 压缩 / 权限 / IO 类修复

> 涉及 `session.py` / `memory.py` / `permission.py` / `_io.py` / `config.py` / `headless.py`。评审结论：**需修正后落地，readiness 3/5**。评审揪出**两处契约级行为变更被夹带进健壮性批**（#8 deny→ask、#37 读副作用移除），已在真代码+真测试核实，本方案已按评审改成「不碰契约、只修误伤」。以下逐点为已修正版。

#### 4b-#22 .env 剥引号 · #29 .env 去 BOM（切片A，quick-win）

- **#22**（config.py:34）：`vals[k.strip()] = v.strip()` 会把引号带进 value（`KIMI_API_KEY="sk-xxx"` → 401）。改：`v = v.strip()` 后 `if len(v) >= 2 and v[0] == v[-1] and v[0] in ('"', "'"): v = v[1:-1]`。
- **#29**（config.py:19）：`read_text(encoding="utf-8")` 遇 Windows 记事本带 BOM 的 `.env` 首行 key 挂 `\ufeff`。改 `encoding="utf-8-sig"`（读无 BOM 文件无副作用；真 GBK 仍抛 `UnicodeDecodeError`，坏编码 except 分支不变）。
- **中文测试名**：`配置_env值带双引号被剥成裸值不带进key`、`配置_env值带单引号同样剥一层引号内空格保留`、`配置_env带UTF8BOM首行key能正常读到不挂feff`、`配置_env真GBK坏编码仍走告警按未配置处理不崩`

#### 4b-#36 fsync 父目录（切片A）

- （_io.py:48）`os.replace(tmp, p)` 后只 fsync 了文件、没 fsync 父目录，掉电后目录项可能丢。改：`os.replace` 成功后加 POSIX-only 段——`if os.name != 'nt': try: dfd = os.open(str(p.parent), os.O_RDONLY); os.fsync(dfd); os.close(dfd); except OSError: pass`。用 `O_RDONLY`（对目录更通用），Windows 直接跳过。**判据只用 `os.name=='nt'`，不用 `hasattr(os,'O_DIRECTORY')`**（评审要求）。
- **中文测试名**：`IO_原子写POSIX下replace后fsync父目录Windows下跳过不报错`、`IO_atomic_write_json往返内容一致且不留tmp残留`

#### 4b-#10 + #11 session 清理排序（切片B）

- **#10**（session.py:70/95）：`sorted(..., key=_mtime, reverse=True)`，NTFS mtime 粗粒度同刻撞车会把当前会话排末尾被 unlink。**#11**（时钟回拨）：mtime 作唯一键，回拨后新档判最旧。
- **改法**：新增 `_sort_key(f) -> (_stem_ts(f), _mtime(f), f.stem)` 复合键；`_stem_ts` 用 `re.search(r'(\d{8}-\d{6})', f.stem)` **只认首个时间戳段**（容忍 `headless-`/`sched-`/`legacy-` 前缀与 `-pid`/`-2` 后缀），抠不到返回 `0.0`、回落 mtime。`save_session`（70）与 `list_sessions`（95）的 `sorted key` 换成 `_sort_key`。
- **双保险（务必保留）**：`save_session` 清理前把**当前 session_id 从清理候选剔除**：`fg = [f for f in fg if f.stem != session_id]`（bg 同理）——这是 NTFS 同刻撞车的真兜底。
- **中文测试名**：`会话_同刻mtime撞车时当前会话永不被清理排末尾`、`会话_清理候选显式排除当前session_id`、`会话_时钟回拨后新档靠文件名时序仍排最前不被误判最旧`、`会话_文件名时序解析失败时回落mtime不崩`

#### 4b-#34 todos 校验 · #35 new_session_id 同进程唯一（切片B）

- **#34**（session.py:40-44）：load 只校验 history 元素为 dict，坏档 `todos` 是 dict/字符串时下游 `ctx["todos"]` 崩。改：`if not isinstance(data.get("todos"), list): data["todos"] = []`。
- **#35**（session.py:54-61）：只防磁盘已存在文件，同进程同秒多线程取 id 会撞（纵深防御，当前无触发路径）。改：模块级 `_ISSUED_IDS: set[str]` + `threading.Lock`；生成循环除 `(SESSIONS_DIR/f'{sid}.json').exists()` 外再判 `sid in _ISSUED_IDS`，选定后在锁内 `add`。
- **中文测试名**：`会话_坏档todos是字典或字符串时load归空列表不崩`、`会话_new_session_id同进程连取多次id互不重复`

#### 4b-#37 memory 损坏备份职责解耦（切片C，**契约级变更，单独提交**）
