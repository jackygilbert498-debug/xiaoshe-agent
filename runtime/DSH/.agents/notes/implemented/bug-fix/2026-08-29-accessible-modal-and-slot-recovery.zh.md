# Agent Note：弹层焦点与插槽故障必须保持可恢复

Status: implemented

[English](2026-08-29-accessible-modal-and-slot-recovery.md) | 中文

## Problem

共享弹层原子虽然暴露了 `role="dialog"`，却没有约束键盘焦点、隔离背后的页面，也没有在关闭后把焦点还给触发控件。另一方面，界面插槽崩溃时只会渲染一个空的 `data-slot-error` 元素。因此，即使渲染器已经监管并记录故障，根插槽失败看起来仍像整套应用无故空白。

## Decision

`Modal` 现在持有完整的浏览器弹层交互合同。打开时，它记录先前获得焦点的元素，把 portal 根之外的每个同级元素标记为 `inert` 和 `aria-hidden`，选择有意义的初始控件，约束 `Tab` 与 `Shift+Tab`，响应 `Escape` 关闭，并在清理时恢复原有无障碍状态和焦点。

插槽渲染器仍通过 ledger 上报故障并让失败配置项退出竞争。其临时错误边界与永久 dry-cell 路径现在会渲染一个小型可访问恢复界面，不再输出空节点。根故障会占满视口并解释当前状态；所有故障界面都提供重新加载操作，仍挂载的错误边界还提供局部重试。启动顺序造成的装配错误继续明确失败，不会被转成运行时恢复界面。

## Alternatives considered

**让每个产品壳自行实现弹层键盘交互。** 已否决，因为焦点约束、背景隔离和焦点恢复属于 primitive 行为，分散实现会在不同产品壳之间漂移。

**插槽崩溃后自动重新加载。** 已否决，因为这可能形成重载循环，并在未经同意时丢弃用户尚未保存的状态。

**吞掉缺失的根注册。** 已否决，因为组合缺失属于装配错误，而不是可恢复的注册项崩溃。

## Consequences

- 共享弹层打开时，键盘和辅助技术用户无法误操作背景控件。
- 插槽监管仍是事实来源；恢复界面不会把崩溃的配置项伪装为健康状态。
- dry root 不再呈现无法解释的空白屏幕，但局部重试仍无法复活已被 ledger 淘汰的配置项；重新加载是显式恢复路径。

## Testing

`packages/client/ui-primitives/tests/atoms.client.spec.tsx` 覆盖初始焦点、正反向焦点循环、背景隔离和焦点恢复。`packages/client/ui-renderer/tests/scoped-slots.client.spec.tsx` 覆盖可操作的根/子插槽故障界面，同时保留兄弟项隔离以及启动装配错误明确失败的行为。
