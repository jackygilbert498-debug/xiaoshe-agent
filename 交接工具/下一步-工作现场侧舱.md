# 小蛇“工作现场侧舱”V1 交接边界

状态：**2026-08-28 本地工程主线已完成；真实浏览器与跨设备视觉复验为 `release-held`。**

实现和新鲜门禁见 `docs/evidence/work-surface-dock-v1/acceptance.md`。不要重做契约、Provider 或中央侧舱；接手时先完成文末保留的真实交互验收。

## 用户提出的目标

像 Codex 的“输出内容”侧栏一样，在小蛇任务过程中直接显示网页、文件、终端、后台进程或桌面画面，并允许用户或小蛇在同一工作现场继续操作。

## 推荐信息架构

不要增加永久占位的第四栏，也不要替换现有“状态 / 记忆 / 系统”工作台。推荐把中央任务区变成可选分屏：

```text
会话栏 | 任务/对话  <->  工作现场侧舱 | 状态/记忆/系统
```

- 关闭时保持当前老版三栏基线不变。
- 打开时只拆分中央任务区；支持拉宽、收起、固定、弹出和全屏。
- 窄屏降级为抽屉或全屏现场，不压缩成不可用的四列。

## 第一阶段建议范围

1. `SurfaceRegistry`：工具统一登记 `web / file / image / video / pdf / terminal / desktop` 类型现场，并携带标题、来源、状态、能力、信任级别和会话归属。
2. `SurfaceDock`：多标签页、刷新、关闭、固定、外部打开、复制路径、拉宽与会话级恢复。
3. 本地网页：优先承载 `127.0.0.1` 工具界面；遇到 CSP、`X-Frame-Options`、跨域认证或下载限制时必须明确降级到安全 WebView/外部浏览器，不能显示空白 iframe。
4. 文件与产物：图片、视频、PDF、文本和 diff 可查看；不把“文件存在”误报为业务验收。
5. 进程与终端：展示后台进程、端口、实时日志、停止/重启边界；禁止把任意终端输入默认视为安全动作。

## 操作模式

- `仅观看`：只显示现场和运行事实。
- `我来操作`：用户直接点击、输入、播放或检查。
- `交给小蛇`：由小蛇通过浏览器桥或 `python/xiaoshe_desktop_bridge.py` 执行；当前桥已经具备 observe、zoom、verify、list/focus window、click、type_text 和 press 基础。

关键动作仍需沿用现有审批、权限和完成凭证链；动作前后要有可见时间线、截图/状态差异和验证结果。用户接管后，小蛇必须停止输入，只有用户明确交还控制才恢复。

## 不应采用的方案

- 只写一个固定 iframe 并称为“可操作工作现场”。
- 把侧舱塞进右侧状态工作台，导致状态、记忆和系统失去稳定位置。
- 绕过现有审批/权限服务，直接允许页面或插件控制桌面。
- 在 URL、日志、截图名或会话状态中持久化 API Key、UI token 或个人凭据。
- 修改 `runtime/xiaoshe-legacy/ui` 或重新绘制品牌标识。

## 已完成的实施前提

1. 用户已确认继续实现，并要求尽量不抢电脑控制权。
2. 独立实施计划位于 `docs/superpowers/plans/2026-08-28-xiaoshe-work-surface-dock-v1.md`。
3. V1 已明确为“显示 + 用户手动操作”；不包含“小蛇接管操作”。
4. 原品牌母版未修改；正式改动只进入 XS Product 的契约、Provider 和 adapted 工作层。

## 接手后仍需完成的真实验收

- 在正式浏览器中让一个真实工具产生 URL 或文件，确认侧舱自动出现正确标签页。
- 由用户在侧舱内完成一次真实交互；遇到 CSP / XFO 时确认可理解的安全降级。
- 实测关闭后恢复原布局、宽度与标签按会话恢复，并补齐五档自适应截图。
- 在 Windows/Linux、125%/150% DPI 和目标显示器上复验；这些不能由当前 macOS 后台单测代替。
- “小蛇接管操作”不属于 V1；若未来实施，必须另立权限、接管互斥和动作凭证计划。
