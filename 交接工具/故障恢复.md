# XS 交接故障恢复

这份说明只处理“接收、校验、安装或启动没有通过”的情况。默认原则是保留现场、换新目录复验，不在失败的副本上执行 `reset`、`clean`、`stash`、强制覆盖或批量改权限。

## 先保留证据

1. 不删除原压缩包、`.sha256`、失败的解压目录和终端输出。
2. 记录当前设备、操作系统、Node/pnpm 版本、执行命令与完整错误。
3. 不粘贴 API Key、Token、个人会话内容或 `.state` 文件；需要分享日志时先脱敏。

## 按顺序定位

### 1. 压缩包 SHA-256 不一致

- 停止解压和安装；该副本不能继续使用。
- 从原设备重新复制 `.tar.gz` 与同名 `.sha256`，不要复用不完整下载。
- 校验通过后解压到一个全新的空目录，不要覆盖旧工程。

### 2. 完整性清单报告文件或 Git 对象不一致

- 保留校验输出，不要用当前设备的文件补丁式覆盖交接副本。
- 重新解压到新目录，再运行 `交接工具/验证交接-Windows.ps1` 或 `验证交接-macOS.command`。
- 如果仍是文件哈希、HEAD 或 Git 对象错误，回到原设备重新创建交接包。

### 3. 只有顶层 Git 工作树指纹不一致

macOS → Windows 可能把可执行位或符号链接呈现为工作树差异。只有在逐文件哈希、三个 HEAD 和 Git 对象均通过，并且差异与 `docs/evidence/cross-device-sync/` 中记录的平台差异一致时，才可标记为平台待复验；不要自动 `chmod`、提交或清理。

### 4. Node、pnpm 或依赖安装失败

- 当前验证基线是 Node.js 24 和 pnpm `11.7.0`。
- 不从另一台设备复制 `node_modules`、`lib`、缓存或运行状态；使用接收脚本在本机重建。
- 如果旧 DSH Profile 的 `node_modules` Junction 导致备份递归，确认当前副本包含 `scripts/backup-dsh-profile.ps1`，并重新运行最新版接收脚本。

### 5. 3080 端口、桌面桥或正式页面失败

- 先运行 `xiaoshe-doctor --json`，根据失败项处理端口占用、Profile、Node/pnpm 或系统权限。
- 页面能打开不等于产品通过；还需确认 `/xiaoshe/desktop/status`、正式 root/client、Product 服务和浏览器控制台。
- API Key、个人会话和系统权限不在交接包中，必须在新设备重新配置。

## 仍无法恢复时

保留以下材料再交回原设备或下一位接手者：压缩包文件名与 SHA-256、完整性校验输出、三个仓库的 branch/HEAD/status、`xiaoshe-doctor --json`、失败命令和脱敏日志。不要覆盖原项目；以 `从这里开始.md` 和 `当前状态.md` 记录的边界重新建立接力点。
